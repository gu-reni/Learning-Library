## `<cerrno>` 头文件详解

`<cerrno>` 是 C++ 标准库中从 C 标准库继承而来的头文件，提供了**错误码处理**的宏定义。它主要用于错误报告机制，允许系统调用和库函数通过一个全局可修改的整数 `errno` 来返回具体的错误原因。该头文件在 C++ 中同样有效，是跨平台错误处理的基础。

---

## 一、宏定义详解

### 1. `errno`

**宏原型：**
```cpp
#define errno /* 实现定义 */
```

**作用：** `errno` 是一个可修改的**左值**（通常是 `int` 类型的变量），用于报告最近发生的系统调用或库函数的错误。在程序启动时，`errno` 的值为 `0`。当某个函数发生错误时，它会将一个正数错误码存入 `errno`。若函数执行成功，`errno` 的值不会被清除，因此建议在调用可能失败的函数前将 `errno` 置为 `0`，并在其后检查。

**使用注意事项：**
- 没有函数会将 `errno` 设置为 `0`，因此调用前通常需手动清零。
- 在多线程环境中，`errno` 通常被实现为**线程局部存储**，每个线程有自己的 `errno`，以避免线程间干扰。
- 标准库函数成功时允许修改 `errno`，因此仅凭 `errno` 的非零值不能可靠地判断错误，必须结合函数返回值（如 `-1`、`NULL`）。

**示例用法：**
```cpp
#include <cerrno>
#include <cstdio>
#include <cstring>

int main() {
    errno = 0;                           // 清零
    FILE* fp = fopen("not_exist.txt", "r");
    if (fp == NULL) {
        std::printf("Error opening file: %s\n", std::strerror(errno));
    }
    return 0;
}
```

**实现原理：** `errno` 通常通过编译器的线程局部存储机制实现。在单线程环境中，它可能是全局 `int` 变量；在多线程环境中，编译器通过 `__thread` 或 `_Thread_local` 关键字为每个线程生成独立的错误码存储。

---

### 2. 错误码宏

`<cerrno>` 定义了一系列以 `E` 开头的宏常量，每个常量代表一种特定的错误类型。这些宏的值在不同平台上可能不同，但含义相同。以下列出 POSIX 标准定义的常见错误码（非穷举）：

| 宏名 | 含义 | 典型原因 |
|------|------|----------|
| `EACCES` | 权限被拒绝 | 文件权限不足 |
| `EAGAIN` | 资源暂时不可用 | 非阻塞操作无法立即完成 |
| `EBADF` | 无效的文件描述符 | 文件描述符未打开或已关闭 |
| `EEXIST` | 文件已存在 | `open` 或 `mkdir` 时指定 `O_EXCL` 但文件存在 |
| `EFAULT` | 地址无效 | 传递到内核的指针指向非法地址空间 |
| `EFBIG` | 文件太大 | 超出文件系统或进程允许的最大文件大小 |
| `EINTR` | 系统调用被信号中断 | 慢速系统调用（如 `read`、`write`）被信号打断 |
| `EINVAL` | 无效参数 | 传递给函数的参数不正确 |
| `EIO` | I/O 错误 | 硬件或底层 I/O 故障 |
| `EISDIR` | 是一个目录 | 期望一个普通文件，但路径是目录 |
| `EMFILE` | 进程打开的文件描述符过多 | 达到进程的文件描述符上限 |
| `ENFILE` | 系统打开的文件过多 | 达到系统全局的文件描述符限制 |
| `ENOENT` | 文件或目录不存在 | 路径名中的组件不存在 |
| `ENOMEM` | 内存不足 | 无法分配所需内存 |
| `ENOSPC` | 设备无剩余空间 | 磁盘已满 |
| `ENOTDIR` | 不是一个目录 | 期望目录，但路径是普通文件 |
| `EPERM` | 操作不允许 | 没有超级用户权限 |
| `EPIPE` | 管道破裂 | 向没有读取端的管道写入 |
| `ERANGE` | 结果超出范围 | 数值转换函数（如 `strtol`）的值超出可表示范围 |
| `ESPIPE` | 非法定位 | 对管道或套接字使用 `lseek` |
| `ESRCH` | 没有这样的进程 | 传给 `kill` 或 `waitpid` 的 PID 无效 |
| `ETIMEDOUT` | 连接超时 | 网络操作超过时限 |
| `EXDEV` | 跨设备链接 | 尝试在不同文件系统间创建硬链接 |

**使用示例：**
```cpp
#include <cerrno>
#include <cstring>
#include <iostream>

int main() {
    errno = ENOENT;
    std::cout << std::strerror(errno) << std::endl; // 输出 "No such file or directory"
    return 0;
}
```

## 二、函数详解

`<cerrno>` 本身不声明任何函数。但与 `errno` 配合使用的标准库函数包括：
- `std::strerror`（定义在 `<cstring>`）：给定错误码，返回描述错误的字符串。
- `std::perror`（定义在 `<cstdio>`）：向标准错误输出打印用户提供的消息后跟错误描述。

这些函数都需要包含相应的头文件。

---

## 三、结构体详解

`<cerrno>` 不定义任何结构体。

---

## 四、类型定义

`<cerrno>` 不定义任何类型。`errno` 的类型是实现定义的，但通常是 `int`。

---

## 五、宏总结

| 宏名 | 作用 |
|------|------|
| `errno` | 可修改的整型宏，用于保存错误码。 |
| `E*` 系列宏 | 整数常量，表示各种错误类型。 |

---

## 六、模板声明

`<cerrno>` 是纯 C 风格头文件，不包含 C++ 模板。
