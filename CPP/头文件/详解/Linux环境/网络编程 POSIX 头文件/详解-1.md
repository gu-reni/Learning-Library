# `<sys/socket.h>` 核心函数与结构体详解（Linux / POSIX）

## 函数详解

### 1. socket 函数

**函数原型：**
```c
int socket(int domain, int type, int protocol);
```

**作用：**  
创建一个通信端点，返回一个文件描述符，后续操作通过该描述符进行。

**参数：**  
- **domain**：指定通信协议族（地址族）。  
  - `AF_INET`：IPv4 网络通信，使用 32 位 IPv4 地址。  
  - `AF_INET6`：IPv6 网络通信，使用 128 位 IPv6 地址。  
  - `AF_UNIX`（或 `AF_LOCAL`）：Unix 域套接字，用于同一台机器上进程间通信，基于文件系统路径。  
  - `AF_PACKET`：链路层套接字，可直接访问网卡数据包（需 root 权限）。  
- **type**：指定套接字类型。  
  - `SOCK_STREAM`：流式套接字，提供可靠的、面向连接的字节流服务，对应 TCP 协议。数据按序、无边界、可靠传输。  
  - `SOCK_DGRAM`：数据报套接字，提供无连接的、不可靠的数据报服务，对应 UDP 协议。数据以报文形式发送，可能丢失、乱序，有边界。  
  - `SOCK_RAW`：原始套接字，允许直接访问底层协议（如 ICMP、IP），常用于构造特殊报文（需 root 权限）。  
  - `SOCK_SEQPACKET`：顺序数据包套接字，提供可靠、有边界、有序的数据包服务（如 SCTP）。  
- **protocol**：指定具体协议。通常设为 `0`，让系统根据 `domain` 和 `type` 自动选择默认协议（如 `SOCK_STREAM` + `AF_INET` 自动选择 TCP）。也可显式指定，如 `IPPROTO_TCP`、`IPPROTO_UDP`、`IPPROTO_ICMP` 等。

**返回值：**  
- 成功：返回一个非负整数（文件描述符）。  
- 失败：返回 `-1`，并设置 `errno` 指示错误（如 `EPROTONOSUPPORT` 表示协议不支持）。

**示例用法（小例子）：**
```c
int sockfd = socket(AF_INET, SOCK_STREAM, 0);
if (sockfd == -1) {
    perror("socket");
    exit(1);
}
printf("Socket created, fd = %d\n", sockfd);
```

**实现原理（内部机制）：**  
`socket()` 是一个系统调用，进入内核后：  
1. 根据 `domain`、`type`、`protocol` 查找已注册的协议族（如 IPv4、IPv6）。  
2. 分配一个 `struct socket` 内核对象（表示套接字），并根据协议类型初始化其操作函数表（如 `inet_stream_ops`）。  
3. 分配一个未使用的文件描述符，建立文件描述符与内核套接字对象的关联。  
4. 返回文件描述符给用户态。此时套接字尚未绑定地址或连接，仅处于“未初始化”状态。

**线程安全提示：**  
`socket()` 是线程安全的。它是一个系统调用，内核内部对资源分配进行了同步，多个线程同时调用不会相互干扰。

### 2. bind 函数

**函数原型：**
```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

**作用：**  
将套接字与一个本地协议地址（IP + 端口）绑定，用于服务器端指定监听地址。

**参数：**  
- `sockfd`：由 `socket()` 返回的文件描述符。  
- `addr`：指向协议地址结构的指针。对于 IPv4，应使用 `struct sockaddr_in`；对于 IPv6，使用 `struct sockaddr_in6`。  
  - `struct sockaddr_in` 包含：  
    - `sin_family`：必须设为 `AF_INET`。  
    - `sin_addr.s_addr`：IPv4 地址（如 `INADDR_ANY` 表示绑定所有接口）。  
    - `sin_port`：端口号（需用 `htons` 转换为网络字节序）。  
  - `INADDR_ANY`：常量，值为 `0`，表示监听所有本地网络接口。  
  - `htons()`：将主机字节序的端口号转换为网络字节序（大端）。  
- `addrlen`：地址结构的长度，使用 `sizeof(struct sockaddr_in)` 等。

**返回值：**  
- 成功：返回 `0`。  
- 失败：返回 `-1`，常见 `errno`：  
  - `EADDRINUSE`：指定的地址（IP+端口）已被占用。  
  - `EINVAL`：套接字已经绑定过。  

**示例用法（小例子）：**
```c
struct sockaddr_in serv_addr;
memset(&serv_addr, 0, sizeof(serv_addr));
serv_addr.sin_family = AF_INET;
serv_addr.sin_addr.s_addr = INADDR_ANY;   // 绑定所有本地 IP
serv_addr.sin_port = htons(8080);         // 端口 8080

if (bind(sockfd, (struct sockaddr*)&serv_addr, sizeof(serv_addr)) == -1) {
    perror("bind");
    close(sockfd);
    exit(1);
}
```

**实现原理（内部机制）：**  
`bind()` 系统调用：  
1. 通过 `sockfd` 找到对应的内核套接字对象。  
2. 检查套接字是否已绑定，若已绑定则返回 `EINVAL`。  
3. 将用户传入的地址结构拷贝到内核空间，并保存到套接字对象中。  
4. 对于 TCP/UDP 端口，内核会检查该端口是否已被其他套接字占用（除非设置了 `SO_REUSEADDR`）。若占用且不允许重用，返回 `EADDRINUSE`。  
5. 将套接字标记为已绑定，并分配相关的协议控制块（如 TCP 控制块）。  

**线程安全提示：**  
`bind()` 是线程安全的。它作为系统调用，内核会保护套接字相关数据结构的并发访问。但注意：若多个线程对同一个未绑定的套接字并发调用 `bind()`，可能会竞争导致其中一个失败（返回 `EINVAL` 或 `EADDRINUSE`），但函数本身不会导致内存损坏。

### 3. listen 函数

**函数原型：**
```c
int listen(int sockfd, int backlog);
```

**作用：**  
将一个未连接的主动套接字转为被动监听状态，使其能够接收客户端的连接请求。

**参数：**  
- `sockfd`：已绑定但尚未监听的套接字。  
- `backlog`：指定已完成连接队列的最大长度（即全连接队列大小）。系统可能限制一个上限（如 `SOMAXCONN`，通常为 128）。该值过小可能导致连接被拒绝。

**返回值：**  
- 成功：返回 `0`。  
- 失败：返回 `-1`，常见 `errno`：`EOPNOTSUPP`（套接字类型不支持监听）。

**示例用法（小例子）：**
```c
if (listen(sockfd, SOMAXCONN) == -1) {
    perror("listen");
    close(sockfd);
    exit(1);
}
printf("Server listening on port 8080...\n");
```

**实现原理（内部机制）：**  
`listen()` 执行时：  
1. 内核将套接字的状态从 `CLOSED` 转为 `LISTEN`。  
2. 为该套接字创建两个队列：  
   - **半连接队列（SYN 队列）**：存放收到 SYN 但未完成三次握手的连接（状态为 `SYN_RCVD`）。  
   - **全连接队列（Accept 队列）**：存放已完成三次握手的连接（状态为 `ESTABLISHED`），等待 `accept()` 取出。  
3. `backlog` 参数通常限制全连接队列的最大长度（Linux 中实际值可能由 `/proc/sys/net/core/somaxconn` 限制）。  
4. 内核开始在该端口上监听，当收到 SYN 报文时，将其加入半连接队列并回复 SYN+ACK；收到 ACK 后，将连接移入全连接队列。

**线程安全提示：**  
`listen()` 是线程安全的。系统调用内部会同步修改套接字状态，多个线程对同一套接字调用 `listen()` 可能只有第一个成功，后续调用会返回 `EINVAL`（因为状态已改变），但不会破坏内核数据结构。

### 4. accept 函数

**函数原型：**
```c
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```

**作用：**  
从全连接队列中取出第一个已完成连接的客户端，创建一个新的套接字用于与该客户端通信。

**参数：**  
- `sockfd`：处于监听状态的套接字。  
- `addr`：输出参数，用于返回客户端的协议地址（可为 `NULL`）。若不为空，内核将客户端的地址信息填入。  
- `addrlen`：输入输出参数。输入时表示 `addr` 结构的长度；输出时返回实际地址长度。

**返回值：**  
- 成功：返回一个新的文件描述符（已连接套接字），用于后续 `send`/`recv`。  
- 失败：返回 `-1`，常见 `errno`：`EAGAIN`（非阻塞模式下无连接）、`EINTR`（被信号中断）。

**示例用法（小例子）：**
```c
struct sockaddr_in client_addr;
socklen_t client_len = sizeof(client_addr);
int client_fd = accept(sockfd, (struct sockaddr*)&client_addr, &client_len);
if (client_fd == -1) {
    perror("accept");
    close(sockfd);
    exit(1);
}
printf("New connection from %s:%d\n",
       inet_ntoa(client_addr.sin_addr), ntohs(client_addr.sin_port));
```

**实现原理（内部机制）：**  
`accept()` 系统调用：  
1. 检查监听套接字的全连接队列是否为空。若为空，默认阻塞等待，直到有连接进入队列。  
2. 从队列头部取出一个连接，创建新的内核套接字对象（复制监听套接字的参数）。  
3. 为新套接字分配一个未使用的文件描述符，并将其与新的内核套接字关联。  
4. 若 `addr` 不为空，将客户端的地址信息从内核拷贝到用户空间。  
5. 返回新文件描述符。原监听套接字保持不变，继续监听。

**线程安全提示：**  
`accept()` 是线程安全的。多个线程可以并发在同一个监听套接字上调用 `accept()`，内核会通过互斥锁保护全连接队列，确保每次只取出一个连接。因此，可以使用多线程模型处理连接，每个线程阻塞在 `accept()` 上，共同接收客户端连接。

### 5. connect 函数

**函数原型：**
```c
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

**作用：**  
客户端主动与服务器建立连接（TCP）或设定对端地址（UDP）。

**参数：**  
- `sockfd`：未连接的套接字。  
- `addr`：服务器的协议地址（IP + 端口）。  
- `addrlen`：地址结构的长度。

**返回值：**  
- 成功：返回 `0`。  
- 失败：返回 `-1`，常见 `errno`：  
  - `ECONNREFUSED`：服务器无进程在监听端口。  
  - `ETIMEDOUT`：连接超时。  
  - `EINPROGRESS`：非阻塞模式下连接仍在进行中。

**示例用法（小例子）：**
```c
struct sockaddr_in serv_addr;
memset(&serv_addr, 0, sizeof(serv_addr));
serv_addr.sin_family = AF_INET;
serv_addr.sin_port = htons(8080);
inet_pton(AF_INET, "127.0.0.1", &serv_addr.sin_addr);

if (connect(sockfd, (struct sockaddr*)&serv_addr, sizeof(serv_addr)) == -1) {
    perror("connect");
    close(sockfd);
    exit(1);
}
```

**实现原理（TCP）：**  
`connect()` 对于 TCP：  
1. 若套接字未绑定，内核自动分配一个临时端口（范围由 `ip_local_port_range` 决定）。  
2. 构造 SYN 报文发送给服务器，套接字进入 `SYN_SENT` 状态。  
3. 等待服务器的 SYN+ACK 响应。收到后，发送 ACK，套接字进入 `ESTABLISHED` 状态。  
4. 若中途失败（如超时、收到 RST），返回错误。  
对于 UDP：  
- `connect` 仅仅记录对端地址，不发送任何报文。之后可使用 `send`/`recv` 而不需指定地址。

**线程安全提示：**  
`connect()` 是线程安全的。系统调用内部会同步修改套接字状态，多个线程对同一个套接字并发调用 `connect()` 可能导致状态混乱，因此应该确保每个套接字只在一个线程中执行连接操作。

### 6. send 函数

**函数原型：**
```c
ssize_t send(int sockfd, const void *buf, size_t len, int flags);
```

**作用：**  
在已连接的套接字上发送数据（通常用于 TCP）。

**参数：**  
- `sockfd`：已连接套接字。  
- `buf`：数据缓冲区。  
- `len`：要发送的字节数。  
- `flags`：控制选项，常用：  
  - `0`：默认阻塞模式。  
  - `MSG_DONTWAIT`：非阻塞操作，若无法立即完成则返回 `EAGAIN`。  
  - `MSG_NOSIGNAL`：避免向对端发送 `SIGPIPE` 信号（当写已关闭的连接时）。  

**返回值：**  
- 成功：返回实际发送的字节数（可能小于 `len`）。  
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
char *msg = "Hello, Server!";
ssize_t sent = send(client_fd, msg, strlen(msg), 0);
if (sent == -1) {
    perror("send");
}
```

**实现原理（内部机制）：**  
1. 将用户数据拷贝到内核套接字发送缓冲区。  
2. TCP 协议栈根据拥塞控制、发送窗口将数据分割成 TCP 段，依次发送。  
3. 若发送缓冲区剩余空间不足，`send` 会阻塞（默认）直到有空间可用，或返回已拷贝的部分数据（取决于标志）。

**线程安全提示：**  
`send()` 是线程安全的。多个线程可以同时向同一个套接字发送数据，内核会保证每个系统调用的原子性（即一次 `send` 操作的数据不会与另一个 `send` 的数据交错），但多个 `send` 之间的数据顺序可能交叉。如果需要有序发送，应用层应使用锁或确保单线程写入。

### 7. recv 函数

**函数原型：**
```c
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
```

**作用：**  
在已连接的套接字上接收数据（通常用于 TCP）。

**参数：**  
- `sockfd`：已连接套接字。  
- `buf`：数据缓冲区。  
- `len`：要接收的字节数。  
- `flags`：控制选项，常用：  
  - `0`：默认阻塞模式。  
  - `MSG_DONTWAIT`：非阻塞操作，若无数据则返回 `EAGAIN`。  
  - `MSG_WAITALL`：尝试接收满 `len` 字节再返回（但可能因信号或错误提前返回）。

**返回值：**  
- 成功：返回实际接收的字节数（可能小于 `len`）。  
- 返回 `0`：对端关闭连接。  
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
char buffer[1024];
ssize_t received = recv(client_fd, buffer, sizeof(buffer) - 1, 0);
if (received > 0) {
    buffer[received] = '\0';
    printf("Received: %s\n", buffer);
} else if (received == 0) {
    printf("Server closed connection.\n");
}
```

**实现原理（内部机制）：**  
1. 从内核套接字接收缓冲区中读取数据。  
2. 若缓冲区为空，阻塞等待数据到达。  
3. 数据到达后，从缓冲区拷贝到用户空间，返回实际字节数。  
4. 若对端发送了 FIN，在读取完剩余数据后返回 0。

**线程安全提示：**  
`recv()` 是线程安全的。多个线程可以并发从同一个套接字接收数据，内核会保证每个系统调用的原子性（一次 `recv` 读取的数据不会与其他 `recv` 交错），但应用层通常应使用单线程接收或加锁，以避免数据混乱。

### 8. sendto 函数

**函数原型：**
```c
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);
```

**作用：**  
用于无连接套接字（UDP）发送数据，可指定目标地址。

**参数：**  
- `dest_addr`：目标地址结构。  
- 其余参数同 `send`。

**返回值：**  
同 `send`。

**示例用法（小例子）：**
```c
struct sockaddr_in dest;
dest.sin_family = AF_INET;
dest.sin_port = htons(8080);
inet_pton(AF_INET, "192.168.1.100", &dest.sin_addr);
char *msg = "UDP message";
sendto(sockfd, msg, strlen(msg), 0, (struct sockaddr*)&dest, sizeof(dest));
```

**实现原理（内部机制）：**  
内核根据 `dest_addr` 查找路由，构建 UDP 数据报（添加 UDP 头和 IP 头），发送到目标 IP 和端口，不保证可靠到达。

**线程安全提示：**  
`sendto()` 是线程安全的，与 `send()` 类似。对于同一个 UDP 套接字，多个线程并发发送，内核会保证每个数据报的原子性，但顺序可能交错。无需额外同步。

---

### 9. recvfrom 函数

**函数原型：**
```c
ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);
```

**作用：**  
用于无连接套接字（UDP）接收数据，同时返回源地址。

**参数：**  
- `src_addr`：输出参数，返回发送方地址。  
- `addrlen`：输入输出参数，传入地址结构长度，返回实际长度。  
- 其余参数同 `recv`。

**返回值：**  
同 `recv`。

**示例用法（小例子）：**
```c
struct sockaddr_in src;
socklen_t src_len = sizeof(src);
char buffer[1024];
ssize_t n = recvfrom(sockfd, buffer, sizeof(buffer), 0,
                     (struct sockaddr*)&src, &src_len);
if (n > 0) {
    buffer[n] = '\0';
    printf("Received from %s:%d: %s\n",
           inet_ntoa(src.sin_addr), ntohs(src.sin_port), buffer);
}
```

**实现原理（内部机制）：**  
从内核接收队列中取出一个完整的 UDP 数据报（UDP 保留报文边界），将数据拷贝到用户缓冲区，同时返回源地址信息。

**线程安全提示：**  
`recvfrom()` 是线程安全的。多个线程可以并发从同一个 UDP 套接字接收数据，每个数据报只会被一个线程接收，不会重复。

### 10. setsockopt 函数

**函数原型：**
```c
int setsockopt(int sockfd, int level, int optname, const void *optval, socklen_t optlen);
```

**作用：**  
设置套接字选项，用于调整网络协议行为。

**参数：**  
- `level`：协议层，常用：  
  - `SOL_SOCKET`：通用套接字层。  
  - `IPPROTO_TCP`：TCP 协议层。  
  - `IPPROTO_IP`：IPv4 协议层。  
- `optname`：选项名称，常用：  
  - `SO_REUSEADDR`：允许重用本地地址（解决 `bind` 时 `EADDRINUSE`）。  
  - `SO_RCVTIMEO` / `SO_SNDTIMEO`：设置接收/发送超时时间。  
  - `TCP_NODELAY`：禁用 Nagle 算法，减少小包延迟。  
  - `SO_KEEPALIVE`：开启 TCP 保活机制。  
- `optval`：指向选项值的指针。  
- `optlen`：选项值的长度。

**返回值：**  
成功返回 `0`，失败返回 `-1`。

**示例用法（小例子）：**
```c
int reuse = 1;
if (setsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse)) == -1) {
    perror("setsockopt");
    close(sockfd);
    exit(1);
}
```

**实现原理（内部机制）：**  
1. 系统调用根据 `level` 和 `optname` 找到对应的协议层处理函数。  
2. 读取或修改内核中该套接字对象的对应选项字段。  
3. 选项修改后立即生效。

**线程安全提示：**  
`setsockopt()` 是线程安全的。多个线程可以同时设置同一套接字的不同选项，内核会保护内部数据结构。但若并发修改同一选项，最终值取决于最后一次修改，可能存在竞争，应用层应避免。

### 11. getsockopt 函数

**函数原型：**
```c
int getsockopt(int sockfd, int level, int optname, void *optval, socklen_t *optlen);
```

**作用：**  
获取套接字选项的当前值。

**参数：**  
同 `setsockopt`，但 `optval` 用于输出，`optlen` 为输入输出参数。

**返回值：**  
成功返回 `0`，失败返回 `-1`。

**示例用法（小例子）：**
```c
int reuse;
socklen_t len = sizeof(reuse);
if (getsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &reuse, &len) == -1) {
    perror("getsockopt");
} else {
    printf("SO_REUSEADDR = %d\n", reuse);
}
```

**实现原理（内部机制）：**  
与 `setsockopt` 类似，从内核读取指定选项的值并拷贝到用户空间。

**线程安全提示：**  
`getsockopt()` 是线程安全的。多个线程可以并发读取同一套接字的选项，读取操作不会相互干扰。

---

### 12. close 函数

**函数原型：**
```c
int close(int fd);
```

**作用：**  
关闭文件描述符，当引用计数为零时释放套接字资源并终止连接。

**参数：**  
- `fd`：要关闭的文件描述符（包括套接字描述符）。

**返回值：**  
成功返回 `0`，失败返回 `-1`。

**示例用法（小例子）：**
```c
close(client_fd);  // 关闭已连接套接字
```

**实现原理（内部机制）：**  
1. 减少文件描述符的引用计数（可能由 `fork` 导致多个引用）。  
2. 若计数降为 0，释放内核套接字对象。  
3. 对于 TCP，如果发送缓冲区仍有数据，会尝试发送剩余数据，然后发送 FIN，开始四次挥手。

**线程安全提示：**  
`close()` 是线程安全的。多个线程可以尝试关闭同一个文件描述符，但内核保证不会重复释放资源。然而，在并发场景下，一个线程关闭套接字而另一个线程仍在读写该套接字会导致错误（如 `EBADF`），应用层应确保使用同步机制避免此类情况。

---

### 13. shutdown 函数

**函数原型：**
```c
int shutdown(int sockfd, int how);
```

**作用：**  
独立关闭套接字的读或写方向，更精细地控制连接关闭过程。

**参数：**  
- `how`：关闭方式  
  - `SHUT_RD`：关闭读方向，丢弃接收缓冲区数据，后续 `recv` 返回 0。  
  - `SHUT_WR`：关闭写方向，发送 FIN 包，后续 `send` 返回 `EPIPE`（若未设 `MSG_NOSIGNAL`）。  
  - `SHUT_RDWR`：同时关闭读写。

**返回值：**  
成功返回 `0`，失败返回 `-1`。

**示例用法（小例子）：**
```c
shutdown(sockfd, SHUT_WR);  // 关闭写方向，通知对端不再发送数据
// 之后仍可接收数据，最后再 close
```

**实现原理（内部机制）：**  
1. 直接操作套接字的传输控制块。  
2. `SHUT_WR` 会立即发送 FIN，不再允许发送数据，但接收通道仍可用。  
3. `SHUT_RD` 会丢弃后续收到的数据，但发送通道仍可用。  
4. `shutdown` 不释放文件描述符，仍需 `close` 释放资源。

**线程安全提示：**  
`shutdown()` 是线程安全的。多个线程可以同时调用 `shutdown()`，内核会同步处理状态变更。但与 `close()` 类似，并发使用时应避免与读写操作冲突。

## 结构体详解

### 一、POSIX 标准结构体（定义在 `<sys/socket.h>`）

#### 1. struct sockaddr
**定义：**
```c
struct sockaddr {
    sa_family_t sa_family;    // 地址族
    char        sa_data[14];  // 地址数据
};
```
**作用：** 通用套接字地址结构，用于传递协议无关的地址信息。所有具体地址结构都可强制转换为 `struct sockaddr*` 传递给套接字函数。

**成员详解：**
- `sa_family`：地址族，如 `AF_INET`、`AF_INET6`、`AF_UNIX` 等。
- `sa_data`：14 字节缓冲区，存储实际地址数据（格式与地址族相关）。

**示例用法：**
```c
struct sockaddr_in addr_in;
addr_in.sin_family = AF_INET;
bind(sockfd, (struct sockaddr*)&addr_in, sizeof(addr_in));
```

---

#### 2. struct sockaddr_storage
**定义：**
```c
struct sockaddr_storage {
    sa_family_t ss_family;               // 地址族
    char        __ss_padding[_SS_PADSIZE]; // 填充，足够容纳任意地址
    // 可能还有对齐字段
};
```
**作用：** 足够大且对齐合适的通用地址结构，可存储任何协议族的地址，常用于编写地址族无关的代码。

**成员详解：**
- `ss_family`：地址族，用于判断实际地址类型。
- 内部填充确保结构体足够大，能容纳 `sockaddr_in`、`sockaddr_in6`、`sockaddr_un` 等所有类型。

**示例用法：**
```c
struct sockaddr_storage client_addr;
socklen_t addr_len = sizeof(client_addr);
int client_fd = accept(listen_fd, (struct sockaddr*)&client_addr, &addr_len);
if (client_addr.ss_family == AF_INET) {
    struct sockaddr_in *ipv4 = (struct sockaddr_in*)&client_addr;
    // 处理 IPv4
}
```

---

```c
struct msghdr {

    size_t        msg_iovlen;     // iov 数组长度

    size_t        msg_controllen; // 辅助数据长度

```
**作用：** 用于 `sendmsg()` 和 `recvmsg()` 系统调用，支持分散/聚集 I/O 和辅助数据传递。

**成员详解：** 见前文。

### 二、常用派生地址结构（位于其他头文件，但常与 `<sys/socket.h>` 一起使用）

#### 7. struct sockaddr_in（定义在 `<netinet/in.h>`）
**定义：**
```c
struct sockaddr_in {
    sa_family_t    sin_family;   // AF_INET
    in_port_t      sin_port;     // 端口号（网络字节序）
    struct in_addr sin_addr;     // IPv4 地址
    unsigned char  sin_zero[8];  // 填充，使结构体与 sockaddr 大小相同
};

struct in_addr {
    in_addr_t s_addr;   // IPv4 地址（网络字节序）
};
```
**作用：** IPv4 地址专用结构。

**成员详解：**
- `sin_family`：必须为 `AF_INET`。
- `sin_port`：16 位端口号，使用 `htons()` 转换为网络字节序。
- `sin_addr`：32 位 IPv4 地址，使用 `inet_addr()` 或 `inet_pton()` 赋值。
- `sin_zero`：填充字段，通常用 `memset` 清零。

**示例用法：**
```c
struct sockaddr_in serv_addr;
memset(&serv_addr, 0, sizeof(serv_addr));
serv_addr.sin_family = AF_INET;
serv_addr.sin_port = htons(8080);
serv_addr.sin_addr.s_addr = INADDR_ANY;   // 监听所有接口
bind(sockfd, (struct sockaddr*)&serv_addr, sizeof(serv_addr));
```

---

#### 8. struct sockaddr_in6（定义在 `<netinet/in.h>`）
**定义：**
```c
struct sockaddr_in6 {
    sa_family_t     sin6_family;   // AF_INET6
    in_port_t       sin6_port;     // 端口号（网络字节序）
    uint32_t        sin6_flowinfo; // 流信息（通常为 0）
    struct in6_addr sin6_addr;     // IPv6 地址
    uint32_t        sin6_scope_id; // 作用域 ID（如链路本地地址的接口索引）
};

struct in6_addr {
    unsigned char s6_addr[16];   // IPv6 地址（网络字节序）
};
```
**作用：** IPv6 地址专用结构。

**成员详解：**
- `sin6_family`：必须为 `AF_INET6`。
- `sin6_port`：端口号，网络字节序。
- `sin6_flowinfo`：流标签和优先级，通常为 0。
- `sin6_addr`：128 位 IPv6 地址。
- `sin6_scope_id`：链路本地地址的接口索引（如 `if_nametoindex("eth0")`）。

**示例用法：**
```c
struct sockaddr_in6 serv_addr;
memset(&serv_addr, 0, sizeof(serv_addr));
serv_addr.sin6_family = AF_INET6;
serv_addr.sin6_port = htons(8080);
serv_addr.sin6_addr = in6addr_any;   // 监听所有接口
bind(sockfd, (struct sockaddr*)&serv_addr, sizeof(serv_addr));
```

---

#### 9. struct sockaddr_un（定义在 `<sys/un.h>`）
**定义：**
```c
struct sockaddr_un {
    sa_family_t sun_family;   // AF_UNIX
    char        sun_path[108]; // 路径名（以空字符结尾）
};
```
**作用：** Unix 域套接字地址，用于本地进程间通信。

**成员详解：**
- `sun_family`：必须为 `AF_UNIX`。
- `sun_path`：套接字文件路径，长度不超过 108 字符（包括终止符）。

**示例用法：**
```c
struct sockaddr_un addr;
memset(&addr, 0, sizeof(addr));
addr.sun_family = AF_UNIX;
strncpy(addr.sun_path, "/tmp/mysocket", sizeof(addr.sun_path) - 1);
unlink("/tmp/mysocket");
bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
```

### 三、Linux 特有结构体（位于其他头文件，常用于底层协议）

#### 10. struct sockaddr_ll（定义在 `<linux/if_packet.h>` 或 `<netpacket/packet.h>`）
**定义：**
```c
struct sockaddr_ll {
    unsigned short sll_family;   // 总是 AF_PACKET
    unsigned short sll_protocol; // 协议类型（如 ETH_P_IP）
    int            sll_ifindex;  // 接口索引（如 if_nametoindex("eth0")）
    unsigned short sll_hatype;   // ARP 硬件类型
    unsigned char  sll_pkttype;  // 包类型（如 PACKET_HOST）
    unsigned char  sll_halen;    // 硬件地址长度
    unsigned char  sll_addr[8];  // 硬件地址（MAC）
};
```
**作用：** 链路层（数据链路层）地址结构，用于原始套接字（`AF_PACKET`）直接访问网络接口。

**成员详解：**
- `sll_family`：必须为 `AF_PACKET`。
- `sll_protocol`：以太网协议类型（如 `htons(ETH_P_IP)` 表示 IPv4 包）。
- `sll_ifindex`：接口索引（通过 `if_nametoindex` 获取）。
- `sll_hatype`：硬件地址类型（如 `ARPHRD_ETHER`）。
- `sll_pkttype`：包类型（`PACKET_HOST` 表示发往本机，`PACKET_BROADCAST` 广播等）。
- `sll_halen`：硬件地址长度（以太网为 6）。
- `sll_addr`：硬件地址（如 MAC 地址）。

**示例用法（接收链路层帧）：**
```c
int sockfd = socket(AF_PACKET, SOCK_RAW, htons(ETH_P_ALL));
struct sockaddr_ll addr;
socklen_t addrlen = sizeof(addr);
char buffer[1500];
recvfrom(sockfd, buffer, sizeof(buffer), 0, (struct sockaddr*)&addr, &addrlen);
printf("Received from interface index: %d\n", addr.sll_ifindex);
```

#### 11. struct sockaddr_nl（定义在 `<linux/netlink.h>`）
**定义：**
```c
struct sockaddr_nl {
    sa_family_t nl_family;  // AF_NETLINK
    unsigned short nl_pad;  // 填充（通常为 0）
    __u32        nl_pid;    // 端口 ID（通常是进程 ID 或 0）
    __u32        nl_groups; // 多播组掩码
};
```
**作用：** Netlink 套接字地址，用于内核与用户空间通信（如路由表、网络事件等）。

**成员详解：**
- `nl_family`：必须为 `AF_NETLINK`。
- `nl_pid`：单播地址，通常设置为进程 ID 或 0（由内核分配）。
- `nl_groups`：多播组掩码，用于接收特定类型的 Netlink 消息。

**示例用法（创建 Netlink 套接字监听路由事件）：**
```c
int sockfd = socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE);
struct sockaddr_nl addr;
memset(&addr, 0, sizeof(addr));
addr.nl_family = AF_NETLINK;
addr.nl_groups = RTMGRP_IPV4_IFADDR;  // 监听接口地址变化
bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
```

#### 12. struct sockaddr_alg（定义在 `<linux/if_alg.h>`）
**定义：**
```c
struct sockaddr_alg {
    sa_family_t salg_family; // AF_ALG
    unsigned char salg_type[14];   // 算法类型（如 "hash"、"skcipher"）
    unsigned char salg_name[64];   // 算法名称（如 "sha256"、"aes"）
    __u32 salg_feat;               // 特性标志
    __u32 salg_mask;               // 掩码
};
```
**作用：** 内核加密算法 API 的地址结构，用于通过套接字访问内核加密服务。

**成员详解：**
- `salg_family`：必须为 `AF_ALG`。
- `salg_type`：算法类型，如 `"hash"`、`"skcipher"`、`"aead"`。
- `salg_name`：具体算法名，如 `"sha256"`、`"aes-cbc"`。

**示例用法（创建 SHA256 哈希套接字）：**
```c
int sockfd = socket(AF_ALG, SOCK_SEQPACKET, 0);
struct sockaddr_alg sa;
memset(&sa, 0, sizeof(sa));
sa.salg_family = AF_ALG;
strcpy((char*)sa.salg_type, "hash");
strcpy((char*)sa.salg_name, "sha256");
bind(sockfd, (struct sockaddr*)&sa, sizeof(sa));
```

## 环境判定
**`<sys/socket.h>` 是 Linux / Unix 类系统下的标准头文件**，属于 POSIX 套接字 API。  
Windows 环境需使用 `<winsock2.h>`，函数名和行为有差异。因此，该头文件明确指示目标环境为 **Linux（或其他 POSIX 兼容系统）**。
