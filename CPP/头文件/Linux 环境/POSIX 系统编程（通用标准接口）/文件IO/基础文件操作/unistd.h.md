# `<unistd.h>` 核心函数详解（Linux / POSIX）

## 说明
`<unistd.h>` 是 POSIX 标准定义的头文件，提供了对操作系统 API 的访问，包括文件 I/O、进程控制、系统标识、用户信息、时间、环境等。本文件将详细介绍其中最常用且与网络编程、系统编程密切相关的函数，并说明其内部原理与线程安全性。

---

## 函数详解

### 1. read 函数
**函数原型：**
```c
ssize_t read(int fd, void *buf, size_t count);
```

**作用：**  
从文件描述符 `fd` 中读取最多 `count` 字节数据到 `buf` 指向的缓冲区。

**参数：**
- `fd`：文件描述符（可以是文件、管道、套接字、终端等）。
- `buf`：指向存储读取数据的缓冲区。
- `count`：要读取的最大字节数。

**返回值：**
- 成功：返回实际读取的字节数（0 表示到达文件末尾或对端关闭连接）。
- 失败：返回 `-1`，并设置 `errno`。

**示例用法（小例子）：**
```c
char buffer[1024];
ssize_t n = read(fd, buffer, sizeof(buffer) - 1);
if (n > 0) {
    buffer[n] = '\0';
    printf("Read: %s\n", buffer);
} else if (n == 0) {
    printf("End of file\n");
} else {
    perror("read");
}
```

**实现原理（内部机制）：**
1. 系统调用进入内核，根据文件描述符找到对应的 `struct file` 对象。
2. 根据文件类型（普通文件、管道、套接字等）调用相应的读方法。
3. 对于普通文件：从当前文件偏移量读取数据到内核缓冲区，再拷贝到用户空间，更新偏移量。
4. 对于套接字：从接收缓冲区读取数据，若数据不足且为阻塞模式则等待。
5. 对于管道：类似，但可能阻塞等待写入者。

**线程安全提示：**
`read()` 是线程安全的。内核会确保每个系统调用的原子性（即一次 `read` 不会与其他 `read` 交错），但多个线程同时读取同一文件描述符可能导致数据混合，通常需要应用层同步。

### 2. write 函数
**函数原型：**
```c
ssize_t write(int fd, const void *buf, size_t count);
```

**作用：**  
将 `buf` 指向的缓冲区中的最多 `count` 字节写入文件描述符 `fd`。

**参数：**
- `fd`：文件描述符。
- `buf`：指向要写入的数据。
- `count`：要写入的字节数。

**返回值：**
- 成功：返回实际写入的字节数（可能小于 `count`）。
- 失败：返回 `-1`，并设置 `errno`。

**示例用法（小例子）：**
```c
char *msg = "Hello, world!\n";
ssize_t n = write(fd, msg, strlen(msg));
if (n == -1) {
    perror("write");
}
```

**实现原理（内部机制）：**
1. 系统调用进入内核，根据文件描述符找到对应的文件对象。
2. 对于普通文件：数据从用户空间拷贝到内核页缓存，更新文件偏移量，实际磁盘写入由内核异步完成。
3. 对于套接字：数据拷贝到发送缓冲区，TCP 协议栈负责发送。
4. 对于管道：数据拷贝到管道缓冲区，唤醒等待的读取进程。
5. 若写入缓冲区空间不足，可能阻塞（默认）或返回部分数据。

**线程安全提示：**
`write()` 是线程安全的。多个线程同时写入同一文件描述符时，内核保证每个系统调用的原子性（即一次 `write` 的数据不会与另一个 `write` 的数据交错），但顺序可能任意。对于普通文件，若使用 `O_APPEND` 标志，内核会保证所有写入都在文件末尾，避免竞争。

### 3. close 函数
**函数原型：**
```c
int close(int fd);
```

**作用：**  
关闭文件描述符 `fd`，释放相关资源。当引用计数为零时，对于套接字和管道会触发连接终止。

**参数：**
- `fd`：要关闭的文件描述符。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
close(fd);
```

**实现原理（内部机制）：**
1. 减少文件描述符在内核中的引用计数。
2. 若计数降为 0，释放文件对象，关闭设备或连接。
3. 对于 TCP 套接字，若发送缓冲区仍有数据，会尽力发送后发送 FIN，或根据 `SO_LINGER` 选项行为处理。

**线程安全提示：**
`close()` 是线程安全的，但并发使用需谨慎：一个线程关闭文件描述符时，其他线程可能仍在使用该描述符，导致 `EBADF`。建议使用引用计数或确保同步。

### 4. lseek 函数
**函数原型：**
```c
off_t lseek(int fd, off_t offset, int whence);
```

**作用：**  
重新定位文件描述符 `fd` 的读写位置（文件偏移量）。

**参数：**
- `fd`：文件描述符（必须支持随机访问，如普通文件）。
- `offset`：偏移量，相对于 `whence` 指定的位置。
- `whence`：基准位置
  - `SEEK_SET`：文件开头。
  - `SEEK_CUR`：当前文件偏移量。
  - `SEEK_END`：文件末尾。

**返回值：**
- 成功：返回新的文件偏移量（从文件开头计算）。
- 失败：返回 `(off_t)-1`，并设置 `errno`。

**示例用法（小例子）：**
```c
off_t pos = lseek(fd, 0, SEEK_END);  // 获取文件大小
printf("File size: %ld\n", pos);
```

**实现原理（内部机制）：**
1. 系统调用进入内核，根据 `fd` 找到文件对象。
2. 检查 `whence` 和 `offset` 是否合法（如不能超出文件范围，对于 `SEEK_END` 允许负偏移）。
3. 修改文件对象中的当前偏移量字段。
4. 对于不支持 `lseek` 的套接字、管道等，返回 `-1` 并设置 `errno` 为 `ESPIPE`。

**线程安全提示：**
`lseek()` 是线程安全的，但多个线程同时调用可能相互影响偏移量。建议使用文件锁或确保单线程操作。

### 5. pipe 函数
**函数原型：**
```c
int pipe(int pipefd[2]);
```

**作用：**  
创建一个管道，用于进程间通信。`pipefd[0]` 用于读，`pipefd[1]` 用于写。

**参数：**
- `pipefd`：长度为 2 的整数数组，用于接收两个文件描述符。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
int fd[2];
if (pipe(fd) == -1) {
    perror("pipe");
    exit(1);
}
pid_t pid = fork();
if (pid == 0) {
    close(fd[1]);          // 子进程关闭写端
    char buf[256];
    read(fd[0], buf, sizeof(buf));
    close(fd[0]);
} else {
    close(fd[0]);          // 父进程关闭读端
    write(fd[1], "hello", 5);
    close(fd[1]);
}
```

**实现原理（内部机制）：**
1. 内核创建一个管道对象，包含一个环形缓冲区（通常 4KB 或更大）。
2. 分配两个文件描述符，一个用于读，一个用于写，指向同一个管道对象。
3. 写入的数据放入缓冲区，读取的数据从缓冲区取出。
4. 当缓冲区满时，写入阻塞；当缓冲区空时，读取阻塞。
5. 当所有写端关闭后，读端读取返回 0（EOF）。

**线程安全提示：**
`pipe()` 本身是线程安全的。创建后，对管道的读写操作与其他文件 I/O 类似，多线程读写需同步。

### 6. dup 函数
**函数原型：**
```c
int dup(int oldfd);
```

**作用：**  
复制文件描述符 `oldfd`，返回一个新的文件描述符，指向同一个文件表项。新描述符是当前可用的最小整数。

**参数：**
- `oldfd`：要复制的文件描述符。

**返回值：**
- 成功：返回新文件描述符。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
int newfd = dup(oldfd);
if (newfd == -1) perror("dup");
```

**实现原理（内部机制）：**
1. 内核在进程的文件描述符表中查找最小的未使用条目。
2. 将新条目指向与 `oldfd` 相同的文件对象，并增加文件对象的引用计数。
3. 返回新描述符。

**线程安全提示：**
`dup()` 是线程安全的。但复制后，两个描述符共享文件偏移量和打开文件状态标志。

---

### 7. dup2 函数
**函数原型：**
```c
int dup2(int oldfd, int newfd);
```

**作用：**  
复制文件描述符 `oldfd` 到 `newfd`。若 `newfd` 已打开，则先关闭它，再复制。

**参数：**
- `oldfd`：源文件描述符。
- `newfd`：目标文件描述符。

**返回值：**
- 成功：返回 `newfd`（或 `oldfd` 如果 `newfd == oldfd`）。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
dup2(oldfd, 1);  // 将标准输出重定向到 oldfd 指向的文件
```

**实现原理（内部机制）：**
1. 若 `oldfd` 无效，返回错误。
2. 若 `newfd == oldfd`，直接返回 `oldfd`。
3. 否则，若 `newfd` 已打开，先关闭它（忽略关闭错误）。
4. 将 `newfd` 的文件描述符表项指向 `oldfd` 的文件对象，增加引用计数。
5. 返回 `newfd`。

**线程安全提示：**
`dup2()` 是线程安全的，但若 `newfd` 已被其他线程使用，关闭它可能导致其他线程的 `read/write` 失败。应谨慎使用。

### 8. fork 函数
**函数原型：**
```c
pid_t fork(void);
```

**作用：**  
创建一个子进程。子进程是父进程的副本，拥有独立的内存空间，但共享文件描述符等资源。

**返回值：**
- 成功：在父进程中返回子进程 PID；在子进程中返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
pid_t pid = fork();
if (pid == -1) {
    perror("fork");
} else if (pid == 0) {
    // 子进程代码
    execlp("/bin/ls", "ls", NULL);
} else {
    // 父进程代码
    wait(NULL);
}
```

**实现原理（内部机制）：**
1. 内核为子进程分配进程控制块（PCB）和内存空间（写时复制技术，实际先共享父进程内存页）。
2. 复制父进程的页表，标记为只读，当任一进程写入时触发缺页异常，再复制物理页。
3. 复制父进程的文件描述符表，引用计数增加。
4. 子进程的 PID 新分配，父进程 ID 设为父进程的 PID。
5. 子进程开始运行（可能先于父进程，取决于调度）。

**线程安全提示：**
`fork()` 本身是线程安全的，但在多线程程序中调用 `fork` 需谨慎。POSIX 规定，`fork` 后子进程中只有调用线程存在，其他线程不会复制。因此，应在 `fork` 前确保互斥锁等资源状态正确，或使用 `pthread_atfork` 注册回调。

### 9. exec 族函数
**函数原型（常见）：**
```c
int execl(const char *path, const char *arg, ...);
int execlp(const char *file, const char *arg, ...);
int execle(const char *path, const char *arg, ..., char *const envp[]);
int execv(const char *path, char *const argv[]);
int execvp(const char *file, char *const argv[]);
int execve(const char *path, char *const argv[], char *const envp[]);
```

**作用：**  
将当前进程映像替换为一个新程序。`exec` 执行后，原进程代码、数据、堆栈被新程序覆盖，但进程 ID、文件描述符等保留（除非设置了 `FD_CLOEXEC`）。

**参数：**
- `path` / `file`：可执行文件路径（`exec*` 中若包含 `/` 则直接作为路径，否则在 `PATH` 中搜索）。
- `arg` / `argv`：参数列表，第一个参数通常是程序名，最后一个必须为 `NULL`。
- `envp`：环境变量数组。

**返回值：**
- 成功：不返回。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
execlp("ls", "ls", "-l", NULL);
perror("execlp");  // 只有失败才会执行到这里
```

**实现原理（内部机制）：**
1. 系统调用 `execve` 是真正实现，其他 `exec` 函数是对它的封装。
2. 内核检查可执行文件格式（ELF、脚本等），验证权限。
3. 释放原进程的内存映射，加载新程序的可执行段和共享库。
4. 初始化新程序的堆栈（参数、环境变量）。
5. 设置新的程序入口点，开始执行。

**线程安全提示：**
`exec` 族函数通常在线程安全方面是安全的，但调用 `exec` 后，原进程的所有线程都被销毁（仅保留调用线程），因此多线程程序在调用 `exec` 前应确保没有其他线程正在执行关键操作。建议在 `fork` 后立即 `exec`，避免资源竞争。

### 10. getpid / getppid 函数
**函数原型：**
```c
pid_t getpid(void);
pid_t getppid(void);
```

**作用：**
- `getpid`：返回当前进程的进程 ID。
- `getppid`：返回父进程的进程 ID。

**返回值：** 总是成功，返回相应的进程 ID。

**示例用法（小例子）：**
```c
printf("PID: %d, PPID: %d\n", getpid(), getppid());
```

**实现原理（内部机制）：**
这些函数通常通过读取进程控制块中存储的值直接返回，效率极高，通常被实现为内联函数或系统调用。

**线程安全提示：**
完全线程安全，只读操作。

### 11. getuid / geteuid / getgid / getegid 函数
**函数原型：**
```c
uid_t getuid(void);      // 实际用户 ID
uid_t geteuid(void);     // 有效用户 ID
gid_t getgid(void);      // 实际组 ID
gid_t getegid(void);     // 有效组 ID
```

**作用：** 获取进程的用户 ID 和组 ID，用于权限检查。

**返回值：** 总是成功，返回对应的 ID。

**示例用法（小例子）：**
```c
printf("UID: %d, EUID: %d\n", getuid(), geteuid());
```

**实现原理（内部机制）：**
从进程的 PCB 中读取相应字段，通常为内联函数或快速系统调用。

**线程安全提示：**
完全线程安全。

### 12. alarm 函数
**函数原型：**
```c
unsigned int alarm(unsigned int seconds);
```

**作用：** 设置一个定时器，在指定秒数后向进程发送 `SIGALRM` 信号。之前设置的定时器被取消，并返回剩余秒数。

**参数：**
- `seconds`：秒数，若为 0 则取消之前的定时器。

**返回值：** 返回之前定时器剩余的秒数（若无则返回 0）。

**示例用法（小例子）：**
```c
alarm(5);      // 5 秒后收到 SIGALRM
pause();       // 等待信号
```

**实现原理（内部机制）：**
1. 内核为每个进程维护一个实时定时器。
2. 调用 `alarm` 时，将定时器值更新为指定秒数，并返回旧值。
3. 定时器到期时，内核向进程发送 `SIGALRM`。

**线程安全提示：**
`alarm` 是线程安全的，但多线程环境下，信号可能被任意线程接收，应确保信号处理函数是安全的或使用 `sigaction` 指定线程。推荐使用 `timer_create` 等更精确的定时器。

### 13. pause 函数
**函数原型：**
```c
int pause(void);
```

**作用：** 使进程挂起，直到收到一个信号（该信号的处理方式可以是默认、忽略或自定义）。如果信号导致进程终止，`pause` 不会返回；否则返回 `-1` 并设置 `errno` 为 `EINTR`。

**返回值：** 总是返回 `-1`（因信号中断）。

**示例用法（小例子）：**
```c
alarm(5);
pause();  // 等待 5 秒后被 SIGALRM 中断
printf("Interrupted\n");
```

**实现原理（内部机制）：**
1. 调用 `pause` 的进程被设置为可中断睡眠状态。
2. 当信号递送到进程时，信号处理函数执行后，系统调用返回 `-1`，`errno` 为 `EINTR`。
3. 若信号导致进程终止，则不会返回。

**线程安全提示：**
在多线程程序中，`pause` 会挂起整个进程，通常不推荐使用。可使用 `sigsuspend` 或 `sigwaitinfo` 等更精细的信号等待。

---

### 14. sleep / usleep 函数
**函数原型：**
```c
unsigned int sleep(unsigned int seconds);
int usleep(useconds_t usec);
```

**作用：**
- `sleep`：使进程休眠指定的秒数，或者被信号中断。
- `usleep`：微秒级休眠（已废弃，推荐 `nanosleep`）。

**返回值：**
- `sleep`：返回未休眠完的秒数（若被信号中断）。
- `usleep`：成功返回 0，失败返回 -1。

**示例用法（小例子）：**
```c
sleep(2);       // 休眠 2 秒
usleep(500000); // 休眠 0.5 秒
```

**实现原理（内部机制）：**
使用内核定时器，将进程置于睡眠状态，定时器到期或被信号唤醒。

**线程安全提示：**
这些函数是线程安全的，但它们会使调用线程休眠，不影响其他线程。

---

### 15. fsync / fdatasync 函数
**函数原型：**
```c
int fsync(int fd);
int fdatasync(int fd);
```

**作用：**
- `fsync`：将文件描述符 `fd` 对应的文件所有修改过的数据和元数据（如修改时间）同步到磁盘。
- `fdatasync`：只同步数据，不同步元数据（除非元数据对后续数据访问必要）。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
write(fd, buf, len);
fsync(fd);  // 确保数据落盘
```

**实现原理（内部机制）：**
1. 内核将文件对应页缓存中的脏页写入磁盘。
2. 对于 `fsync`，还会同步索引节点（inode）元数据。
3. 函数阻塞直到所有数据写入完成。

**线程安全提示：**
`fsync` 和 `fdatasync` 是线程安全的。多个线程可以同时同步不同文件描述符。但频繁同步会影响性能。

---

### 16. truncate / ftruncate 函数
**函数原型：**
```c
int truncate(const char *path, off_t length);
int ftruncate(int fd, off_t length);
```

**作用：** 将文件截断为指定长度（若原文件更大则截断，若更小则填充零）。

**参数：**
- `path`：文件路径。
- `fd`：文件描述符。
- `length`：新的文件大小。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
truncate("file.txt", 1024);   // 将文件大小设为 1024 字节
ftruncate(fd, 2048);          // 将 fd 对应文件设为 2048 字节
```

**实现原理（内部机制）：**
1. 修改文件的 inode 中的文件大小字段。
2. 如果截断，释放超出部分的磁盘块。
3. 如果扩展，新数据区域被填充为零。

**线程安全提示：**
多线程同时操作同一文件可能导致数据不一致，应使用文件锁同步。

### 17. chdir / fchdir / getcwd 函数
**函数原型：**
```c
int chdir(const char *path);
int fchdir(int fd);
char *getcwd(char *buf, size_t size);
```

**作用：**
- `chdir`：改变当前工作目录到 `path`。
- `fchdir`：改变当前工作目录到 `fd` 指向的目录。
- `getcwd`：获取当前工作目录的绝对路径。

**返回值：**
- `chdir`/`fchdir`：成功返回 0，失败返回 -1。
- `getcwd`：成功返回指向 `buf` 的指针，失败返回 NULL。

**示例用法（小例子）：**
```c
chdir("/home/user");
char cwd[1024];
if (getcwd(cwd, sizeof(cwd)) != NULL) {
    printf("Current dir: %s\n", cwd);
}
```

**实现原理（内部机制）：**
- `chdir`：修改进程控制块中的当前工作目录指针。
- `getcwd`：从内核中读取当前工作目录路径（通过查找文件系统路径）。

**线程安全提示：**
这些函数是线程安全的，但改变工作目录会影响整个进程的所有线程，因此多线程程序中使用需谨慎。`fchdir` 可以避免路径字符串的竞争。

### 18. unlink / rmdir 函数
**函数原型：**
```c
int unlink(const char *pathname);
int rmdir(const char *pathname);
```

**作用：**
- `unlink`：删除文件（减少链接计数，若计数为 0 则真正删除）。
- `rmdir`：删除空目录。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
unlink("temp.txt");
rmdir("emptydir");
```

**实现原理（内部机制）：**
- `unlink`：从目录中移除文件名，减少 inode 的链接数，若链接数变为 0 且没有进程打开该文件，则释放磁盘空间。
- `rmdir`：检查目录是否为空，若是则删除目录项并释放 inode。

**线程安全提示：**
这些函数是线程安全的，但多线程同时操作同一文件可能导致竞争（如一个线程删除文件，另一个线程正在使用），应使用同步机制。

### 19. isatty / ttyname 函数
**函数原型：**
```c
int isatty(int fd);
char *ttyname(int fd);
```

**作用：**
- `isatty`：判断文件描述符是否指向终端。
- `ttyname`：返回终端设备名。

**返回值：**
- `isatty`：是终端返回 1，否则返回 0。
- `ttyname`：成功返回设备名字符串（静态缓冲区，下次调用会覆盖），失败返回 NULL。

**示例用法（小例子）：**
```c
if (isatty(STDIN_FILENO)) {
    printf("stdin is a terminal: %s\n", ttyname(STDIN_FILENO));
}
```

**实现原理（内部机制）：**
查询文件描述符对应的设备类型，如果设备的主设备号是终端设备（如 `tty`），则返回真。

**线程安全提示：**
`isatty` 是线程安全的。`ttyname` 使用静态缓冲区，非线程安全，多线程环境应使用 `ttyname_r`（可重入版本）。

### 20. gethostname / getdomainname 函数
**函数原型：**
```c
int gethostname(char *name, size_t len);
int getdomainname(char *name, size_t len);
```

**作用：**
- `gethostname`：获取主机名（如 `localhost`）。
- `getdomainname`：获取域名（如 `example.com`）。

**返回值：**
- 成功：返回 `0`。
- 失败：返回 `-1`。

**示例用法（小例子）：**
```c
char hostname[256];
if (gethostname(hostname, sizeof(hostname)) == 0) {
    printf("Hostname: %s\n", hostname);
}
```

**实现原理（内部机制）：**
从内核的 utsname 结构（由 `uname` 系统调用获取）中读取相应字段。

**线程安全提示：**
`gethostname` 和 `getdomainname` 是线程安全的（它们将结果复制到用户提供的缓冲区）。

## 结构体详解
`<unistd.h>` 本身没有定义任何结构体。它主要定义函数原型、宏（如 `STDIN_FILENO`、`_POSIX_VERSION`）和类型（如 `ssize_t`、`pid_t`、`uid_t`、`gid_t` 等）。以下是一些相关类型说明：

### 常用类型
- `ssize_t`：有符号整数，用于表示字节数或错误（`-1`）。
- `pid_t`：进程 ID 类型。
- `uid_t`：用户 ID 类型。
- `gid_t`：组 ID 类型。
- `off_t`：文件偏移量类型（64 位时用 `off64_t`）。

这些类型在 `<sys/types.h>` 中定义，通过 `<unistd.h>` 间接包含。

## 环境判定
`<unistd.h>` 是 POSIX 标准头文件，在 Linux、macOS、BSD 等 Unix-like 系统上普遍存在。  
在 Windows 环境下，没有原生 `<unistd.h>`，但 MinGW、Cygwin 等兼容层提供了类似实现。原生 Windows 编程应使用 `<io.h>`、`<process.h>` 等头文件。因此，该头文件明确指示目标环境为 **Linux / Unix / POSIX 兼容系统**。
