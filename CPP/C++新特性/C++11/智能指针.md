# 智能指针（C++11）

**一句话定义**：智能指针是基于 RAII 原则的类模板，自动管理动态对象的生命周期，在指针离开作用域时自动释放所管理的资源，从根本上解决内存泄漏、野指针和重复释放问题。

---

## 详细语法与用法

### 三种智能指针概览

| 特性 | `std::unique_ptr` | `std::shared_ptr` | `std::weak_ptr` |
|------|-------------------|-------------------|-----------------|
| 所有权 | 独占 | 共享（引用计数） | 无所有权（观察者） |
| 复制语义 | ❌ 禁用 | ✅ 引用计数 +1 | ✅ 不影响计数 |
| 移动语义 | ✅ 转移所有权 | ✅ 不改变计数 | ✅ 转移 |
| 性能开销 | 极低（≈裸指针） | 中（控制块 + 原子计数） | 低 |
| 适用场景 | 独占资源、工厂函数 | 多对象共享资源 | 打破循环引用、缓存 |

### `std::unique_ptr`

```cpp
// C++11/14/17/20

// 基本创建（C++11）
std::unique_ptr<int> ptr1(new int(42));
std::unique_ptr<int[]> arr1(new int[10]);      // 数组版本，自动调用 delete[]

// 推荐创建方式（C++14+）
auto ptr2 = std::make_unique<int>(42);         // 更安全、更高效
auto arr2 = std::make_unique<int[]>(10);       // C++14 支持数组

// 移动语义——所有权转移
auto ptr3 = std::move(ptr2);                    // ptr2 变为 nullptr，所有权转移到 ptr3

// 释放资源（get 获取裸指针，reset 主动释放）
int* raw = ptr3.get();                          // 获取裸指针，⚠️不要 delete
ptr3.reset();                                   // 主动释放资源
ptr3.reset(new int(100));                       // 释放当前资源，接管新资源

// 自定义删除器——管理非内存资源（C++11）
struct FileDeleter {
    void operator()(FILE* fp) const {
        if (fp) fclose(fp);
    }
};
std::unique_ptr<FILE, FileDeleter> filePtr(fopen("data.txt", "r"));

// 使用无捕获 Lambda 作为删除器（零开销）
auto fileDeleter = [](FILE* fp) { if (fp) fclose(fp); };
std::unique_ptr<FILE, decltype(fileDeleter)> filePtr2(fopen("data.txt", "r"), fileDeleter);
```

### `std::shared_ptr`

```cpp
// C++11/14/17/20

// 创建方式
std::shared_ptr<int> sp1(new int(42));          // 两次分配：对象 + 控制块
auto sp2 = std::make_shared<int>(42);           // ⭐推荐：一次分配，性能更优

// 共享所有权——引用计数变化
auto sp3 = sp2;                                  // 引用计数 1 → 2
std::cout << sp2.use_count();                   // 输出 2

// 主动释放
sp3.reset();                                     // 引用计数 2 → 1，不释放对象
sp2.reset();                                     // 引用计数 1 → 0，释放对象

// 数组支持（C++17+）
auto arr = std::make_shared<int[]>(10);          // 管理动态数组

// 自定义删除器
std::shared_ptr<int> sp4(new int(100), [](int* p) {
    std::cout << "Custom delete: " << *p << std::endl;
    delete p;
});
```

### `std::weak_ptr`

```cpp
// C++11

// 从 shared_ptr 构造，不增加引用计数
std::shared_ptr<int> sp = std::make_shared<int>(42);
std::weak_ptr<int> wp = sp;

// 访问对象：通过 lock() 临时获取 shared_ptr
if (auto locked = wp.lock()) {                   // 对象仍存活
    std::cout << *locked << std::endl;
} else {
    std::cout << "Object already destroyed" << std::endl;
}

// 检查对象是否存活（不提升引用计数）
if (wp.expired()) { /* 对象已销毁 */ }

// 典型场景：打破循环引用
class Node {
public:
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;                    // 使用 weak_ptr 打破循环
};
auto node1 = std::make_shared<Node>();
auto node2 = std::make_shared<Node>();
node1->next = node2;
node2->prev = node1;                             // ✅ 不会造成循环引用
```

## 底层原理与实现机制

### 1. RAII 原则

智能指针是 RAII 的经典应用：在构造函数中获取资源（持有裸指针），在析构函数中自动释放资源。**RAII 保证了异常安全**——当异常被抛出时，会暂停当前执行流并逐层退出作用域，在退出每个作用域时调用所有局部对象的析构函数，资源因此被正确释放。

### 2. `std::unique_ptr` 原理

`unique_ptr` 的核心是**独占所有权**：拷贝构造函数和拷贝赋值运算符被显式删除（`= delete`），仅允许移动构造和移动赋值。

简化实现的核心结构如下：

```cpp
template <typename T, typename Deleter = std::default_delete<T>>
class UniquePtr {
private:
    T* ptr_;
    Deleter deleter_;
public:
    explicit UniquePtr(T* ptr = nullptr) : ptr_(ptr) {}
    ~UniquePtr() { if (ptr_) deleter_(ptr_); }
    
    // 禁用拷贝
    UniquePtr(const UniquePtr&) = delete;
    UniquePtr& operator=(const UniquePtr&) = delete;
    
    // 移动构造：转移所有权
    UniquePtr(UniquePtr&& other) noexcept 
        : ptr_(other.ptr_), deleter_(std::move(other.deleter_)) {
        other.ptr_ = nullptr;
    }
    
    T* operator->() const { return ptr_; }
    T& operator*() const { return *ptr_; }
};
```

#### 内存布局与优化

`unique_ptr` 的大小取决于删除器的类型：
- **无状态删除器**（如默认 `std::default_delete`、无捕获 Lambda）：利用**空基类优化（EBO）**，`sizeof(unique_ptr) == sizeof(void*)`，与裸指针相同。
- **函数指针删除器**：`sizeof(unique_ptr) == 2 * sizeof(void*)`
- **有状态仿函数**：体积包含删除器的成员变量大小

### 3. `std::shared_ptr` 原理

`shared_ptr` 通过**控制块（Control Block）**实现引用计数管理，通常包含：
- **共享引用计数**（strong count）：管理对象的 `shared_ptr` 数量
- **弱引用计数**（weak count）：观察该对象的 `weak_ptr` 数量
- **删除器**：资源释放函数
- **分配器**：用于控制块内存管理
- **管理对象指针**：指向实际管理的对象

```cpp
// shared_ptr 内存布局（典型实现）
struct ControlBlock {
    std::atomic<int> strong_cnt;  // 共享引用计数
    std::atomic<int> weak_cnt;    // 弱引用计数
    Deleter deleter;
};

class shared_ptr<T> {
    T* ptr_;           // 指向管理对象
    ControlBlock* cb_; // 指向控制块
};
```

#### 引用计数操作

- 拷贝 `shared_ptr`：`strong_cnt.fetch_add(1)`（原子操作）
- 析构 `shared_ptr`：`strong_cnt.fetch_sub(1)`，若变为 0 则调用 `deleter_(ptr_)` 释放对象
- `weak_ptr` 不影响 `strong_cnt`，只影响 `weak_cnt`

#### `std::make_shared` 的优化

`std::make_shared` 将**控制块和管理对象在单次内存分配中连续存放**，相比分开分配的优势：
- **内存碎片减少**：一次分配代替两次
- **缓存局部性提升**：控制块和对象在相邻内存地址
- **分配速度提升约 20%**

### 4. `std::weak_ptr` 原理

`weak_ptr` 与控制块中的**弱引用计数**协同工作：
- 从 `shared_ptr` 构造 `weak_ptr` 时，弱引用计数 +1
- `weak_ptr` 销毁时，弱引用计数 -1
- **当强引用计数变为 0 时**：管理对象被销毁，但控制块保留（因弱引用计数可能 > 0）
- **当弱引用计数也变为 0 时**：控制块被释放

```cpp
// weak_ptr 简化实现（核心）
template <typename T>
class WeakPtr {
    T* ptr_;
    ControlBlockBase* control_block_;
public:
    // lock() 检查对象是否存活
    std::shared_ptr<T> lock() const {
        if (control_block_ && control_block_->strong_cnt > 0) {
            return std::shared_ptr<T>(*this);  // 提升为 shared_ptr
        }
        return nullptr;
    }
};
```

### 5. 线程安全分析

| 操作 | 线程安全 | 说明 |
|------|---------|------|
| 不同 `shared_ptr` 对象共享同一控制块 | ✅ 安全 | 引用计数修改是原子操作 |
| 多个线程同时拷贝同一个 `shared_ptr` | ✅ 安全 | `fetch_add` 原子操作保证 |
| **同一个** `shared_ptr` 对象被多线程读写 | ❌ 不安全 | `reset()` 或 `operator=` 期间另一线程可能读到中间态|
| 被管理对象本身的并发访问 | ❌ 不安全 | 需要外部加锁保护 |

> C++20 引入了 `std::atomic<std::shared_ptr<T>>`，提供对 `shared_ptr` 自身的原子操作。

## 与相关特性的对比

### 1. `std::unique_ptr` vs `std::auto_ptr`（C++98，C++17 移除）

| 方面 | `std::auto_ptr`（已弃用） | `std::unique_ptr` |
|------|--------------------------|-------------------|
| 拷贝语义 | 拷贝时转移所有权，原指针变空 | 拷贝构造被禁用（编译期检查） |
| 数组支持 | ❌ 不支持 | ✅ 支持（`unique_ptr<T[]>`） |
| 容器兼容性 | ❌ 不可放入 STL 容器 | ✅ 可放入容器（通过移动） |
| 删除器 | 仅支持 `delete` | ✅ 支持自定义删除器 |
| 缺陷 | 违反常规值语义，易引发 bug | 语义明确，编译期保证安全 |

`auto_ptr` 的核心问题在于其不寻常的拷贝语义——复制 `auto_ptr` 会转移所有权，使源指针变为空，这在常规值语义中难以预测，故在 C++11 中被弃用、C++17 中完全移除。

### 2. `std::shared_ptr` vs 裸指针 + 手动内存管理

| 方面 | 裸指针 + `new`/`delete` | `std::shared_ptr` |
|------|------------------------|-------------------|
| 异常安全 | ❌ 易因提前返回或异常导致泄漏 | ✅ 自动释放 |
| 所有权清晰度 | ❌ 无明确语义 | ✅ 引用计数清晰表达共享 |
| 性能 | 最快 | 有控制块和原子计数开销 |
| 调试难度 | 高（泄漏、悬垂指针难以追踪） | 低（RAII 自动管理） |

## 常见面试问题与解答

### 问题 1：`std::shared_ptr` 是线程安全的吗？

**答**：**部分线程安全，需要具体分析。**

**线程安全的部分（✅ 安全）**：
- 引用计数的修改是原子操作（通常用 `std::atomic::fetch_add` 实现）
- 多个线程在不同 `shared_ptr` 对象上拷贝指向同一资源是安全的
- 控制块的并发访问是线程安全的

**线程不安全的场景（❌ 不安全）**：
1. **同一 `shared_ptr` 对象被多线程并发修改**：当线程 A 调用 `reset()` 或 `operator=` 时，线程 B 可能正在读取该 `shared_ptr`，此时内部状态处于中间态，导致未定义行为。
2. **被管理对象本身的并发访问**：`shared_ptr` 仅管理引用计数安全，不保证对象成员的线程安全，多线程同时修改对象需要外部加锁。

**解决方案**：对于同一 `shared_ptr` 的多线程访问，使用 C++11 提供的原子操作函数（`std::atomic_load`、`std::atomic_store`、`std::atomic_exchange`）或 C++20 的 `std::atomic<std::shared_ptr<T>>`。

---

### 问题 2：`std::make_shared` 有什么优势？什么情况下不能用？

**答**：`std::make_shared` 主要有三大优势：

1. **性能优化**：将控制块和管理对象在单次内存分配中连续存放，减少内存碎片，分配速度提升约 20%。
2. **异常安全**：若使用 `new` 直接构造，`shared_ptr` 构造函数可能抛出异常导致内存泄漏。
3. **代码简洁**：避免显式 `new`，符合现代 C++ 风格。

**不能使用 `make_shared` 的场景**：
- 需要**自定义删除器**时
- 需要**接管已存在的裸指针**时
- **内存敏感场景**：`make_shared` 将控制块和对象绑定在同一块内存，即使强引用计数归零，只要还有 `weak_ptr` 存活，整块内存都无法释放。若对象体积很大且有大量 `weak_ptr` 长期存活，应分开分配（使用 `shared_ptr(new T(...))`）。

---

### 问题 3：循环引用是如何产生的？如何解决？

**答**：当两个或多个对象通过 `shared_ptr` 相互持有时，会形成引用环，导致所有对象的引用计数永远无法归零，造成内存泄漏。

```cpp
// ❌ 错误：循环引用导致内存泄漏
class Node {
public:
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "Node destroyed\n"; }
};
auto node1 = std::make_shared<Node>();
auto node2 = std::make_shared<Node>();
node1->next = node2;
node2->next = node1;  // 循环引用！node1 和 node2 的引用计数均为 2
// 离开作用域后，引用计数减为 1，永远不为 0，内存泄漏
```

**解决方案**：将循环中的一个方向改为 `std::weak_ptr`。

```cpp
// ✅ 正确：使用 weak_ptr 打破循环
class Node {
public:
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;      // 弱引用，不增加引用计数
    ~Node() { std::cout << "Node destroyed\n"; }
};
```

`weak_ptr` 不参与引用计数，不影响对象生命周期，通过 `lock()` 安全访问，若对象已销毁则返回空 `shared_ptr`。

## 典型错误与最佳实践

### ❌ 典型错误

#### 错误 1：同一裸指针构造多个独立 `shared_ptr`

```cpp
int* raw = new int(42);
std::shared_ptr<int> sp1(raw);
std::shared_ptr<int> sp2(raw);  // ❌ 致命错误！两个独立控制块，双重释放
```

**正确做法**：始终使用 `std::make_shared` 或从一个 `shared_ptr` 拷贝构造。

---

#### 错误 2：使用 `shared_ptr` 管理数组但不使用正确的删除器

```cpp
// ❌ 错误（C++17 之前）
std::shared_ptr<int> arr(new int[10]);   // 析构时调用 delete，而非 delete[]，未定义行为
```

**正确做法**：
```cpp
// C++17 及之后
auto arr = std::make_shared<int[]>(10);

// C++11/14 需显式指定删除器
std::shared_ptr<int> arr(new int[10], std::default_delete<int[]>());
```

---

#### 错误 3：使用 `get()` 获取裸指针后手动 `delete`

```cpp
std::shared_ptr<int> sp = std::make_shared<int>(42);
int* raw = sp.get();
delete raw;  // ❌ 致命错误！shared_ptr 析构时会再次释放，双重释放
```

---

#### 错误 4：`shared_ptr` 多线程下不加保护访问同一对象

```cpp
std::shared_ptr<std::vector<int>> vec = std::make_shared<std::vector<int>>();
// 线程 A 和 B 同时执行 vec->push_back() ❌ 数据竞争
```

---

### ✅ 最佳实践

| 实践 | 说明 |
|------|------|
| **默认使用 `unique_ptr`** | 除非确实需要共享所有权，优先使用 `unique_ptr`，语义清晰且零开销 |
| **优先使用 `make_unique` / `make_shared`** | 更安全、更高效，避免显式 `new` |
| **用 `weak_ptr` 打破循环引用** | 树/图结构中，将父节点对子节点的引用设为 `shared_ptr`，子节点对父节点设为 `weak_ptr` |
| **用 `enable_shared_from_this`** | 当需要在类的成员函数中获取自身的 `shared_ptr` 时继承 `std::enable_shared_from_this<T>` |
| **避免混用裸指针和智能指针** | 同一资源的生命周期应由智能指针全权负责，`get()` 仅用于传递给不支持智能指针的遗留 API |
| **警惕 `shared_ptr` 性能开销** | 高频拷贝场景下，`shared_ptr` 的原子计数开销不可忽略；考虑使用 `unique_ptr` 或对象池优化 |
