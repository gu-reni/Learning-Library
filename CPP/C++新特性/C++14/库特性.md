# C++14 主要库特性

C++14 标准库在 C++11 基础上进行了增强，引入了一些实用的新组件和语法糖，同时改进了现有功能。本文档覆盖 C++14 中最主要、最常用的库特性，每个特性独立成节，保持深度与实用性。

---

## 特性总览

| 特性 | 一句话描述 |
|------|------------|
| `std::make_unique` | 安全创建 `std::unique_ptr`，类似 `std::make_shared` |
| `std::integer_sequence` | 编译期整数序列，用于元编程展开 |
| `std::exchange` | 原子替换对象值并返回旧值 |
| `std::quoted` | I/O 流中带引号字符串的方便处理 |
| `std::shared_timed_mutex` | 支持超时的共享互斥锁（读写锁） |
| `std::tuple` 增强 | `std::tuple_size_v`、`std::tuple_element_t` 等别名模板 |
| 标准用户定义字面量 | `s`（string）、`h`/`min`/`s`/`ms`/`us`/`ns`（chrono）、`if`/`i`/`il`（complex） |
| `std::cbegin`/`std::cend` | 获取 const 迭代器的非成员函数 |
| `std::is_final` | 类型特征，判断类是否为 `final` |

## 1. `std::make_unique`

**一句话定义**：`std::make_unique` 是 C++14 引入的工厂函数，用于安全、高效地创建 `std::unique_ptr`，与 C++11 的 `std::make_shared` 相对应。

### 详细语法与用法

```cpp
#include <memory>

// 单个对象
auto p1 = std::make_unique<int>(42);
auto p2 = std::make_unique<std::string>(5, 'a');  // "aaaaa"

// 数组版本（C++14 支持）
auto arr = std::make_unique<int[]>(10);   // 10 个 int 值初始化
// 注意：不能指定初始值，所有元素默认初始化（内置类型为不确定值）
// 若需初始化，可使用初始化列表：
auto arr2 = std::make_unique<int[]>(std::initializer_list<int>{1,2,3}); // 错误？实际上不支持
// 正确做法：使用 new 或 vector

// 自定义删除器仍需直接构造
auto deleter = [](FILE* f) { if (f) fclose(f); };
std::unique_ptr<FILE, decltype(deleter)> fp(fopen("test.txt", "r"), deleter);
```

### 底层原理与实现机制

`std::make_unique` 的实现本质上是完美转发参数并调用 `new`，然后返回 `unique_ptr`：

```cpp
template<typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```

对于数组版本（`T[]`），调用 `new T[n]()`（值初始化，对于内置类型会零初始化）。与 `make_shared` 不同，`make_unique` 没有控制块与对象合并分配的优势，因为 `unique_ptr` 的控制块很简单（仅删除器），但使用 `make_unique` 仍能避免显式 `new` 并提高异常安全。

### 与相关特性的对比

| 创建方式 | 异常安全 | 代码简洁 | 适用场景 |
|----------|----------|----------|----------|
| `make_unique` | ✅ 最佳 | 简洁 | 推荐默认方式 |
| `unique_ptr<T>(new T(...))` | ⚠️ 有潜在泄漏（若构造函数异常） | 冗长 | 需要自定义删除器或数组初始化 |
| `make_shared` | ✅ | 简洁 | 需要共享所有权 |

### 常见面试问题与解答

**问题：为什么 C++11 有 `make_shared` 却没有 `make_unique`？**

答：`make_shared` 在 C++11 中被加入是因为它能优化性能（单次分配）。`make_unique` 被遗漏是一个疏忽，C++14 予以补充。`make_unique` 的实现简单且没有性能特殊优化，但其价值在于避免显式 `new`，提升异常安全性和代码一致性。

### 典型错误与最佳实践

```cpp
// ❌ 错误：make_unique 不支持指定数组初始值
auto bad = std::make_unique<int[]>({1,2,3}); // 编译错误

// ✅ 正确：使用直接 new 或 vector
auto ok = std::unique_ptr<int[]>(new int[3]{1,2,3});

// ✅ 最佳实践：始终优先使用 make_unique 而非 new
auto p = std::make_unique<Widget>(arg1, arg2);
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 2. `std::integer_sequence`

**一句话定义**：`std::integer_sequence` 是一个编译期整数序列容器，用于模板元编程中展开参数包或生成编译期索引序列，常与 `std::index_sequence` 配合实现 `std::tuple` 遍历、函数参数展开等。

### 详细语法与用法

```cpp
#include <utility>   // std::integer_sequence, std::index_sequence

// 基本定义
template<typename T, T... Ints>
struct integer_sequence;

// 常用别名：size_t 版本
template<size_t... Ints>
using index_sequence = integer_sequence<size_t, Ints...>;

// 辅助模板：生成 0,1,...,N-1 的序列
template<size_t N>
using make_index_sequence = integer_sequence<size_t, /* 0...N-1 */>;

// 典型用法：遍历 tuple
template<typename Tuple, typename F, size_t... I>
void for_each_impl(Tuple&& t, F f, std::index_sequence<I...>) {
    (f(std::get<I>(t)), ...);
}

template<typename Tuple, typename F>
void for_each(Tuple&& t, F f) {
    for_each_impl(std::forward<Tuple>(t), f,
                  std::make_index_sequence<std::tuple_size_v<std::decay_t<Tuple>>>{});
}

// 示例：打印 tuple
std::tuple<int, double, std::string> t(1, 2.5, "hello");
for_each(t, [](const auto& x) { std::cout << x << " "; });
```

### 底层原理与实现机制

`std::integer_sequence` 是一个空类模板，仅存储类型 `T` 和参数包 `Ints`。编译器在实例化时展开参数包。`make_index_sequence<N>` 通过递归继承或编译器内置实现生成 `0` 到 `N-1` 的序列。典型实现使用模板递归和 `std::index_sequence` 的拼接技巧。

C++14 标准库要求 `make_index_sequence` 能在 O(1) 深度内生成，但实际实现通常使用对数递归或编译器内建。

### 与相关特性的对比

| 特性 | 用途 | 编译期开销 |
|------|------|------------|
| `integer_sequence` | 存储任意整数类型的序列 | 小 |
| `index_sequence` | 专门用于 `size_t` 索引 | 小 |
| 变参模板展开 | 直接展开参数包 | 无额外存储 |
| `std::tuple` + 递归访问 | 逐个元素访问 | 递归实例化开销 |

`integer_sequence` 提供了将编译期整数序列作为类型传递的能力，是许多元编程技巧的基础。

### 常见面试问题与解答

**问题：`std::index_sequence` 如何实现 `std::tuple` 的遍历？**

答：`std::tuple` 的元素数量在编译期已知。通过 `std::make_index_sequence<N>` 生成 `0..N-1` 的编译期整数序列，然后利用参数包展开或折叠表达式，将每个索引传给 `std::get<I>`，实现对每个元素的访问。这使得无需递归模板即可遍历 tuple。

### 典型错误与最佳实践

```cpp
// ❌ 错误：尝试运行时使用 index_sequence
size_t n = 5;
auto seq = std::make_index_sequence<n>{}; // 错误：n 必须编译期常量

// ✅ 最佳实践：与模板参数或 constexpr 一起使用
template<size_t N>
void process() {
    auto seq = std::make_index_sequence<N>{};
    // ...
}
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 3. `std::exchange`

**一句话定义**：`std::exchange` 用新值替换对象的值，并返回旧值，以原子方式执行（不涉及多线程原子性，仅指操作不可分割）。

### 详细语法与用法

```cpp
#include <utility>

int x = 10;
int old = std::exchange(x, 20);   // old = 10, x = 20

// 常用于移动赋值中交换资源
struct Widget {
    int* p;
    Widget(Widget&& other) noexcept : p(std::exchange(other.p, nullptr)) {}
};
```

### 底层原理与实现机制

```cpp
template<typename T, typename U = T>
T exchange(T& obj, U&& new_value) {
    T old = std::move(obj);
    obj = std::forward<U>(new_value);
    return old;
}
```

`exchange` 返回旧值（移动构造），新值通过完美转发赋值。它比手动写三行代码更清晰，且保证异常安全（若赋值抛出异常，旧值已被移出，但标准未明确保证强异常安全，实际实现通常先保存旧值再赋值）。

### 与相关特性的对比

| 操作 | 手动实现 | `std::exchange` |
|------|----------|-----------------|
| 移动置空 | `auto* old = ptr; ptr = nullptr; return old;` | `std::exchange(ptr, nullptr)` |
| 循环移位 | 需临时变量 | 一行完成 |

`exchange` 是移动赋值中窃取资源并置空源对象的惯用写法。

### 常见面试问题与解答

**问题：`std::exchange` 与 `std::atomic::exchange` 有何区别？**

答：`std::exchange` 是普通函数，不保证多线程原子性；`std::atomic<T>::exchange` 是原子操作，保证线程安全。`std::exchange` 适用于单线程环境或非原子类型。

### 典型错误与最佳实践

```cpp
// ❌ 错误：对 const 对象使用
const int x = 10;
std::exchange(x, 20); // 编译错误

// ✅ 最佳实践：在移动构造函数和移动赋值中使用
Buffer(Buffer&& other) noexcept
    : data(std::exchange(other.data, nullptr))
    , size(std::exchange(other.size, 0)) {}
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 4. `std::quoted`

**一句话定义**：`std::quoted` 是 I/O 操作符辅助函数，用于在输入输出流中处理带引号的字符串，自动处理转义字符。

### 详细语法与用法

```cpp
#include <iomanip>
#include <sstream>

std::string s = R"(hello "world")";
std::stringstream ss;
ss << std::quoted(s);   // 输出: "hello \"world\""
std::string t;
ss >> std::quoted(t);   // t = hello "world"
```

### 底层原理与实现机制

`std::quoted` 返回一个代理对象，重载了 `operator<<` 和 `operator>>`。输出时，它在字符串前后添加双引号，并转义内部的双引号为 `\"`。输入时，它读取引号内的内容并正确解析转义序列。

### 与相关特性的对比

| 方式 | 自动处理转义 | 适用于流 |
|------|--------------|----------|
| 手动处理 | 繁琐易错 | 是 |
| `std::quoted` | ✅ | ✅ |
| 第三方库（如 Boost） | 类似 | 类似 |

### 常见面试问题与解答

**问题：`std::quoted` 如何自定义分隔符和转义字符？**

答：`std::quoted` 的第二个参数允许指定分隔符（默认为 `'"'`），第三个参数指定转义字符（默认为 `'\\'`）。例如：`std::quoted(s, '|', '^')` 使用 `|` 作为分隔符，`^` 作为转义。

### 典型错误与最佳实践

```cpp
// ❌ 错误：对非字符串类型使用
int x = 42;
std::cout << std::quoted(x); // 编译错误

// ✅ 最佳实践：读写 CSV 等格式时使用 quoted 处理带引号字段
std::string csv_line;
std::ifstream file("data.csv");
while (std::getline(file, csv_line)) {
    std::stringstream ss(csv_line);
    std::string field;
    while (ss >> std::quoted(field)) {
        // 处理字段
    }
}
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 5. `std::shared_timed_mutex`（及 `std::shared_lock`）

**一句话定义**：`std::shared_timed_mutex` 是一种支持共享（读）锁和独占（写）锁的互斥量，并允许超时等待，`std::shared_lock` 是用于管理共享锁的 RAII 包装器。

### 详细语法与用法

```cpp
#include <shared_mutex>

std::shared_timed_mutex mtx;

// 读操作：共享锁
void reader() {
    std::shared_lock<std::shared_timed_mutex> lock(mtx);
    // 读取共享数据
}

// 写操作：独占锁
void writer() {
    std::unique_lock<std::shared_timed_mutex> lock(mtx);
    // 修改数据
}

// 尝试加锁并超时
void try_read() {
    std::shared_lock<std::shared_timed_mutex> lock(mtx, std::chrono::milliseconds(100));
    if (lock.owns_lock()) {
        // 成功获取锁
    }
}
```

### 底层原理与实现机制

`shared_timed_mutex` 通常基于操作系统提供的读写锁（如 POSIX 的 `pthread_rwlock_t`）实现。内部维护读者计数和写者状态。`shared_lock` 是 `unique_lock` 的变体，专门用于管理共享锁，提供 `lock()`、`try_lock()`、`unlock()` 等成员。

### 与相关特性的对比

| 互斥量类型 | 共享锁 | 超时 | 递归 |
|------------|--------|------|------|
| `mutex` | ❌ | ❌ | ❌ |
| `recursive_mutex` | ❌ | ❌ | ✅ |
| `timed_mutex` | ❌ | ✅ | ❌ |
| `shared_timed_mutex` | ✅ | ✅ | ❌ |
| `shared_mutex` (C++17) | ✅ | ❌ | ❌ |

`shared_timed_mutex` 在 C++14 引入，C++17 又引入了不带超时的 `shared_mutex`。

### 常见面试问题与解答

**问题：读写锁的典型应用场景是什么？**

答：读多写少的场景，如缓存、配置表、数据库索引等。多个读者可以并发访问，写者独占访问，提高并发性能。

### 典型错误与最佳实践

```cpp
// ❌ 错误：在持有共享锁时修改数据
void bad_reader() {
    std::shared_lock lock(mtx);
    data_modify();  // 未定义行为
}

// ✅ 最佳实践：使用 shared_lock 读，unique_lock 写
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 6. `std::tuple` 增强：`std::tuple_size_v` 与 `std::tuple_element_t`

**一句话定义**：C++14 为 `std::tuple` 相关的类型特征添加了 `_v` 和 `_t` 辅助别名模板，简化了使用。

### 详细语法与用法

```cpp
#include <tuple>

using MyTuple = std::tuple<int, double, std::string>;

// C++11 方式
constexpr size_t sz = std::tuple_size<MyTuple>::value;
using First = std::tuple_element<0, MyTuple>::type;

// C++14 方式
constexpr size_t sz2 = std::tuple_size_v<MyTuple>;
using First2 = std::tuple_element_t<0, MyTuple>;

static_assert(sz == sz2);
static_assert(std::is_same_v<First, First2>);
```

### 底层原理与实现机制

`tuple_size_v` 定义为 `template<typename T> inline constexpr size_t tuple_size_v = tuple_size<T>::value;`。`tuple_element_t` 类似。这些别名模板是标准库对 C++14 统一 `_v`/`_t` 命名约定的实践。

### 典型错误与最佳实践

```cpp
// ❌ 错误：对非 tuple 类型使用
int x;
auto bad = std::tuple_size_v<decltype(x)>; // 编译错误

// ✅ 最佳实践：在泛型代码中使用 _v/_t 简化代码
template<typename Tuple>
void print_size() {
    std::cout << std::tuple_size_v<Tuple> << '\n';
}
```

## 7. 标准用户定义字面量（C++14 新增）

C++14 标准库预定义了一些用户定义字面量，位于 `std::literals` 命名空间。

### 7.1 字符串字面量 `s`

```cpp
#include <string>
using namespace std::string_literals;

auto str = "hello"s;   // std::string，而非 const char*
auto multi = R"(raw\string)"s; // 支持原始字符串
```

### 7.2 时间字面量

```cpp
#include <chrono>
using namespace std::chrono_literals;

auto sec = 10s;        // std::chrono::seconds
auto ms = 500ms;       // milliseconds
auto us = 100us;       // microseconds
auto ns = 50ns;        // nanoseconds
auto min = 2min;       // minutes
auto hour = 1h;        // hours
```

### 7.3 复数字面量

```cpp
#include <complex>
using namespace std::complex_literals;

auto z1 = 1.0 + 2.0i;   // std::complex<double>
auto z2 = 1.0if;        // std::complex<float>
auto z3 = 1.0il;        // std::complex<long double>
```

### 底层原理

这些字面量是用户定义字面量运算符（`operator""`）的标准库实现。例如 `"hello"s` 调用 `std::string operator"" s(const char* str, size_t len)`。

### 典型错误与最佳实践

```cpp
// ❌ 错误：未引入命名空间
auto s = "hello"s;   // 编译错误，需 using namespace std::string_literals

// ✅ 最佳实践：在局部作用域使用 using
void f() {
    using namespace std::string_literals;
    auto s = "hello"s;
}
```

## 8. `std::cbegin` / `std::cend`

**一句话定义**：返回容器的常量迭代器（const_iterator）的非成员函数，方便在泛型代码中获得只读迭代器。

### 语法与用法

```cpp
#include <iterator>
#include <vector>

std::vector<int> v = {1,2,3};
auto it1 = std::cbegin(v);  // 等价于 v.cbegin()
auto it2 = std::cend(v);    // v.cend()
// 对内置数组也适用
int arr[] = {1,2,3};
auto it3 = std::cbegin(arr); // const int*
```

### 底层原理

对于容器，调用 `c.begin()`；对于数组，返回指向首元素的 const 指针。

### 常见面试问题与解答

**问题：`std::cbegin` 与 `std::begin` 的区别？**

答：`std::begin` 返回普通迭代器（iterator），`std::cbegin` 返回常量迭代器（const_iterator）。在只读访问时使用 `cbegin` 可以避免通过迭代器修改元素。

### 最佳实践

```cpp
// 在只读遍历中使用 cbegin/cend
for (auto it = std::cbegin(container); it != std::cend(container); ++it) {
    // 只读访问
}
```

## 9. `std::is_final`

**一句话定义**：类型特征，判断一个类是否被声明为 `final`。

### 用法

```cpp
#include <type_traits>

class A {};
class B final {};

static_assert(!std::is_final_v<A>);
static_assert(std::is_final_v<B>);
```

### 典型应用

在模板中根据类是否为 `final` 启用不同的优化策略（如避免虚函数开销）。

## 总结

C++14 标准库特性虽不如 C++11 革命性，但提供了大量实用工具，使代码更简洁、安全、高效。面试中常考的有 `std::make_unique`、`std::integer_sequence`、`std::exchange`、`std::quoted` 以及用户定义字面量。掌握这些特性有助于编写现代 C++ 代码。

**编译器支持总结**：GCC 5.0+、Clang 3.4+、MSVC 2015+ 基本完整支持 C++14 标准库。
