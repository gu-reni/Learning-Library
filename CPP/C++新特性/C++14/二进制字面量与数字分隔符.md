# 二进制字面量与数字分隔符（C++14）

**一句话定义**：二进制字面量允许使用 `0b` 或 `0B` 前缀直接书写二进制数值，数字分隔符（单引号 `'`）允许在数字字面量中插入分隔符以提高可读性，两者均不影响数值的编译期值，仅改善代码表达力。

---

## 详细语法与用法

### 二进制字面量

```cpp
// C++14 二进制字面量：0b 或 0B 前缀
int a = 0b1010;        // 十进制 10
int b = 0B11110000;    // 十进制 240
unsigned long long c = 0b11111111111111111111111111111111ULL; // 32 位全1

// 可与原始字符串结合
std::string bits = R"(0b101010)";
```

### 数字分隔符

单引号 `'` 可作为数字分隔符，出现在整数、浮点数、二进制、十六进制等字面量中。

```cpp
// 十进制分隔
int million = 1'000'000;           // 1000000
int large = 123'456'789;           // 123456789

// 二进制分隔
int bits = 0b1111'0000'1010'0101;   // 清晰分组

// 十六进制分隔
int hex = 0xDEAD'BEEF;              // 0xDEADBEEF

// 浮点数分隔
double pi = 3.141'592'653'589;
double sci = 1.602'176'634e-19;     // 科学计数法也支持

// 八进制分隔
int oct = 01'234'567;               // 八进制 1234567

// 数字分隔符可连续多个（但无意义）
int weird = 1''''2;                 // 12（但通常不这么用）

// 不能出现在前缀后或后缀前
// int bad = 0b'1111;               // 错误：不能在 0b 后立即放分隔符
// int bad2 = 0x'DEAD;              // 错误
// auto f = 3.14'f;                 // 错误：不能放在浮点后缀前
```

### 组合使用

```cpp
// 二进制 + 分隔符
uint32_t mask = 0b1111'1111'0000'0000'1111'1111'0000'0000;

// 模板元编程中的字面量
constexpr unsigned long long all_ones = 0b1111'1111'1111'1111'1111'1111'1111'1111ULL;
static_assert(all_ones == 0xFFFFFFFF, "should be 32 ones");
```

## 底层原理与实现机制

### 1. 二进制字面量的编译期处理

编译器在词法分析阶段识别 `0b` 或 `0B` 前缀，将后续的 `0`/`1` 字符序列转换为对应整数值。该过程与十六进制字面量处理完全类似，仅进制不同。转换后的数值以二进制形式存储在目标类型中，无运行时开销。

### 2. 数字分隔符的解析规则

数字分隔符 `'` 在词法分析阶段被**完全忽略**，仅作为数字字符的分组提示。编译器扫描数字字面量时，跳过所有单引号，仅保留数字字符（`0-9`、`a-f`、`A-F`）和前缀（`0x`、`0b`）及后缀（`U`、`L`、`f` 等）。因此，分隔符不影响数值、类型或编译期求值。

**示例处理流程**：
```
源码：1'234'567
↓ 去除引号
数值：1234567
```

分隔符不能出现在：
- 数字前缀之后立即（如 `0x'DEAD`）
- 数字后缀之前立即（如 `3.14'f`）
- 浮点数的小数点两侧（如 `3.'14` 或 `3.'14` 非法，但 `3.14'15` 合法，因为引号在数字之间）

### 3. 与用户定义字面量的交互

数字分隔符与用户定义字面量（UDL）兼容。编译器先去除分隔符，再解析数字，最后调用用户定义的字面量运算符。

```cpp
long long operator"" _km(unsigned long long x) { return x * 1000; }
auto dist = 1'000_km;   // 调用 operator"" _km(1000)
```

### 4. 对模板元编程的影响

二进制字面量可用于非类型模板参数，因为其值在编译期确定。

```cpp
template<unsigned long long N>
struct BinarySize { static constexpr unsigned long long value = N; };

using Size = BinarySize<0b1101'1010'0001'1110>;  // 合法
```

## 与相关特性的对比

### 1. 二进制字面量 vs 十六进制/八进制字面量

| 进制 | 前缀 | 可读性 | 适用场景 |
|------|------|--------|----------|
| 二进制 | `0b` | 位操作清晰 | 位掩码、标志位、协议字段 |
| 十六进制 | `0x` | 紧凑，适合字节分组 | 内存地址、颜色值、编码 |
| 八进制 | `0` | 较少使用 | Unix 权限、某些历史代码 |

二进制字面量直接反映位模式，避免手动将二进制转换为十六进制，减少错误。

### 2. 数字分隔符 vs 无分隔符

| 写法 | 可读性 | 错误风险 |
|------|--------|----------|
| `1000000000` | 难以快速计数 | 容易漏写或多写 0 |
| `1'000'000'000` | 清晰分组（千分位） | 低 |

分隔符不改变值，仅提升代码可维护性，尤其适用于大数、二进制分组（如 `0b1111'0000`）、十六进制双字节分组（`0xDEAD'BEEF`）。

### 3. C++14 字面量增强 vs 其他语言

- **C++14**：二进制字面量 + 数字分隔符（单引号）
- **C#**：二进制字面量（`0b`）和数字分隔符（下划线 `_`）
- **Python**：二进制字面量（`0b`），数字分隔符（下划线 `_`，Python 3.6+）
- **Rust**：二进制字面量（`0b`），数字分隔符（下划线 `_`）
- **Java**：二进制字面量（`0b`），无数字分隔符（Java 7 支持下划线 `_`，但 C++ 用单引号）

C++ 选择单引号是因为下划线已用于用户定义字面量后缀（如 `123_km`），避免歧义。

## 常见面试问题与解答

### 问题 1：二进制字面量 `0b1010` 与 `10` 在编译后的代码中有区别吗？

**答**：**没有区别**。二进制字面量仅仅是源代码层面的语法糖，编译器将其转换为相同的整数值。在编译后的汇编代码中，两者都生成同样的立即数 `10`（或对应机器码）。二进制字面量的唯一作用是提高代码可读性，尤其适合位操作场景。

---

### 问题 2：数字分隔符是否影响数值的字面量类型或后缀解析？

**答**：**不影响**。分隔符在词法分析阶段被完全移除，因此后缀（如 `U`、`LL`、`f`）的识别不受影响。例如 `1'000ULL` 被处理为 `1000ULL`，仍然是 `unsigned long long` 类型。分隔符也不能出现在后缀之前（如 `1000'ULL` 非法），因为单引号只允许在数字字符之间。

---

### 问题 3：如何利用二进制字面量和数字分隔符定义一个 32 位掩码，表示第 31、15、0 位为 1？

```cpp
constexpr uint32_t mask = 0b1000'0000'0000'0000'1000'0000'0000'0001;
// 或者用十六进制对照
constexpr uint32_t mask_hex = 0x80008001;
```

二进制写法清晰显示哪些位被置 1，分组（每 8 位一组）便于定位字节边界。

## 典型错误与最佳实践

### ❌ 典型错误

#### 错误 1：在二进制字面量中使用非 0/1 字符

```cpp
int x = 0b1201;   // 错误：'2' 不是二进制数字
```

#### 错误 2：分隔符放置在非法位置

```cpp
int a = 0b'1111;   // 错误：不能在 0b 后立即放引号
int b = 0x'DEAD;   // 错误
double c = 3.14'f; // 错误：不能在浮点后缀前放引号
double d = 3.'14;  // 错误：小数点后不能直接跟引号
```

#### 错误 3：在 C++11 模式中使用二进制字面量

```cpp
// 使用 -std=c++11 编译时
int x = 0b1010;   // 警告或错误，C++14 才支持
```

**解决**：确保编译器标准设置为 C++14 或更高。

#### 错误 4：分隔符导致数值歧义（不存在）

```cpp
int x = 1'2;   // 12，不是 1 和 2 分开
```

分隔符不改变数值，只是视觉分组。

---

### ✅ 最佳实践

| 实践 | 说明 |
|------|------|
| **位掩码使用二进制字面量** | 清晰表达每一位，如 `0b0010'1100` |
| **大数使用千分位分隔符** | `1'000'000'000` 比 `1000000000` 更易读 |
| **十六进制按字节或双字节分组** | `0xDEAD'BEEF'1234'5678` 清晰 |
| **二进制按 4 位或 8 位分组** | `0b1111'0000'1010'0101` |
| **一致性** | 同一项目中统一分隔符分组规则（如每 3 位十进制、每 8 位二进制） |
| **C++14 模式必须开启** | 确保编译器支持（GCC 5+、Clang 3.4+、MSVC 2015+） |

```cpp
// 好的示例：配置寄存器位掩码
constexpr uint32_t SPI_CONFIG = 
    0b0111'0000'0000'0000'0000'0000'0000'0001;
    // 模式选择: 0111 (Mode 7)
    // 时钟极性: 0
    // 使能位: 1

// 好的示例：文件权限常量（八进制仍适用）
constexpr int owner_all = 0b111'000'000;  // 0700
```

| 标准 | 特性 | 编译器最低版本 |
