# C++14 语言特性

C++14 在 C++11 的基础上进行了“完成”和“改进”，没有引入革命性的新范式，但修复了诸多不便之处，使代码更加简洁、高效和直观。以下是 C++14 中所有主要语言特性的深度讲解。

---

## 特性总览

| 特性 | 一句话描述 |
|------|------------|
| 泛型 Lambda | Lambda 参数可使用 `auto`，使 `operator()` 成为模板 |
| 变量模板 | 参数化变量，允许定义类型相关的常量或静态数据成员 |
| `decltype(auto)` | 保持表达式的精确类型（含引用）用于自动类型推导 |
| `constexpr` 增强 | 允许局部变量、循环、分支、修改对象等多条语句 |
| 二进制字面量 | `0b` 或 `0B` 前缀直接书写二进制数 |
| 数字分隔符 | 单引号 `'` 分隔数字字面量，提高可读性 |
| 返回值优化（RVO）保证 | 编译器必须省略返回局部对象的拷贝/移动（即使有副作用） |
| 聚合体成员初始化 | 允许在类内为聚合体的非静态成员提供默认初始化器 |
| `std::exchange` 引入标准库（但此属库） | 实际是库特性，但常被提及 |

**注意**：本文仅聚焦语言特性，库特性（如 `std::make_unique`、`std::integer_sequence` 等）已在另一文档中详述。

## 1. 泛型 Lambda（Generic Lambdas）

**一句话定义**：泛型 Lambda 允许 Lambda 表达式的参数使用 `auto` 关键字，编译器将其转换为模板化的 `operator()`，使 Lambda 能够接受任意类型的参数，极大提高了复用性。

详细内容已在《泛型 Lambda》专题文档中完整覆盖，此处仅总结核心要点：

- 语法：`[](auto x, auto y) { return x + y; }`
- 底层：编译器生成具有模板 `operator()` 的匿名函数对象。
- 与普通 Lambda 区别：参数类型推导，支持多种类型调用。
- 注意事项：参数推导规则同模板；可使用 `auto&`、`const auto&`、`auto&&`。
- 典型错误：返回类型不一致；误用导致拷贝；不能直接存于 `std::function`。
- 编译器支持：GCC 5+、Clang 3.4+、MSVC 2015+。

（为避免重复，此处不展开，请参考专门文档）

## 2. 变量模板（Variable Templates）

**一句话定义**：变量模板允许将变量本身参数化，定义一族变量或静态数据成员，其类型和初始值可以依赖于模板参数。

详细内容已在《变量模板》专题文档中完整覆盖，此处仅总结核心要点：

- 语法：`template<typename T> T pi = T(3.14159);`
- 使用：`pi<double>` 得到 `double` 类型的 π。
- 支持特化（全特化、部分特化）。
- 可修饰 `constexpr`，用于编译期常量。
- 与类模板静态成员对比：更简洁。
- 头文件中定义需 `constexpr` 或 `inline`（C++17）避免多重定义。
- 编译器支持：GCC 5+、Clang 3.4+、MSVC 2015+。

（详细内容请参考《变量模板》文档）

## 3. `decltype(auto)`

**一句话定义**：`decltype(auto)` 结合了 `decltype` 的精确类型推导和 `auto` 的自动推导语法，用于变量声明或函数返回值，完美保留表达式的值类别（左值/右值）和引用属性。

### 详细语法与用法

```cpp
// 基本用法：变量声明
int x = 10;
int& r = x;
decltype(auto) a = x;  // a 的类型是 int（x 是左值，decltype(x) 为 int）
decltype(auto) b = r;  // b 的类型是 int&（r 是左值引用表达式，decltype(r) 为 int&）

// 函数返回类型推导
int& foo() {
    static int y = 42;
    return y;
}
decltype(auto) ret = foo();  // ret 是 int&

// 常用于完美转发函数
template<typename F, typename... Args>
decltype(auto) wrapper(F&& f, Args&&... args) {
    return std::forward<F>(f)(std::forward<Args>(args)...);
}
```

### 底层原理与实现机制

`decltype(auto)` 不是新的类型，而是一个占位符。编译器将初始化表达式作为参数传递给 `decltype`，然后将变量的类型设为 `decltype(expr)` 的结果。

```cpp
// 伪实现：decltype(auto) var = expr; 等价于 using T = decltype(expr); T var = expr;
```

与 `auto` 的区别：
- `auto` 去除引用和顶层 cv 限定（值语义）。
- `decltype(auto)` 保留所有类型信息（包括引用）。

### 与相关特性的对比

| 推导方式 | 示例（int x = 10; int& r = x;） | 结果类型 |
|----------|----------------------------------|----------|
| `auto` | `auto a = r;` | `int` |
| `decltype(r)` | `decltype(r) b = r;` | `int&` |
| `decltype(auto)` | `decltype(auto) c = r;` | `int&` |

`decltype(auto)` 与 `decltype` 的区别在于语法便利性：前者用于声明时自动推导，后者需要显式写出类型。

### 常见面试问题与解答

**问题 1：`decltype(auto)` 和 `auto` 在返回类型推导中有什么区别？**

答：`auto` 会退化类型（去除引用），而 `decltype(auto)` 保留引用。例如，若函数返回 `int&`，使用 `auto` 作返回类型会退化为 `int`（导致返回局部引用的悬垂风险被掩盖），而 `decltype(auto)` 正确保留引用。

**问题 2：何时应该使用 `decltype(auto)`？**

答：主要用于完美转发函数、返回代理对象（如 `std::vector<bool>::reference`）或需要保持引用性的场景。一般情况用 `auto` 即可。

### 典型错误与最佳实践

```cpp
// ❌ 错误：误用 decltype(auto) 导致悬垂引用
decltype(auto) bad() {
    int x = 42;
    return x;   // 返回的是 int，不是引用，安全（但 x 是局部变量，返回拷贝）
    // 但若误写成 return (x); 则 decltype((x)) 是 int&，导致悬垂引用！
}
decltype(auto) dangerous() {
    int x = 42;
    return (x);  // 括号使表达式为左值，返回 int&，x 已销毁，UB
}

// ✅ 最佳实践：明确意图，必要时加括号要小心
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 4. `constexpr` 增强（C++14）

**一句话定义**：C++14 大幅放宽了 `constexpr` 函数的限制，允许局部变量、循环、分支、修改对象、`if`/`switch` 等多条语句，使 `constexpr` 函数更接近普通函数。

### 详细语法与用法

```cpp
// C++11：只能有单个 return 语句
constexpr int square_cpp11(int x) { return x * x; }

// C++14：允许局部变量、循环、分支
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}
static_assert(factorial(5) == 120, "factorial error");

// 允许修改局部对象
constexpr int max(int a, int b) {
    if (a > b) return a;
    else return b;
}

// 允许 switch、多个语句
constexpr int digit_sum(int n) {
    int sum = 0;
    while (n > 0) {
        sum += n % 10;
        n /= 10;
    }
    return sum;
}
```

### 底层原理与实现机制

C++14 编译器在常量求值时，需要模拟执行更复杂的控制流。编译期虚拟机支持了循环、分支和局部变量。编译器仍会检查函数体中是否存在不允许的操作（如 `static` 变量、`goto`、`try-catch` 等）。

放宽限制后，许多原本需要模板元编程的算法可以用普通 `constexpr` 函数实现，代码可读性大幅提升。

### 与相关特性的对比

| 版本 | 允许的语句 | 典型限制 |
|------|------------|----------|
| C++11 | 单条 `return` 语句（可包含条件运算符递归） | 无局部变量，无循环 |
| C++14 | 多条语句、局部变量、循环、分支 | 无 `goto`、`try-catch`、`static` 变量 |
| C++17 | 允许 `if constexpr`，`constexpr` lambda | 同 C++14，增加 lambda |
| C++20 | 允许虚函数、`dynamic_cast`、`new`/`delete` | 有限支持 |

### 常见面试问题与解答

**问题：C++14 的 `constexpr` 函数能否使用 `new` 和 `delete`？**

答：不能。C++20 才允许在 `constexpr` 函数中使用 `new`/`delete`（且必须在编译期释放）。

**问题：C++14 中 `constexpr` 函数是否可以修改传入的非 const 引用参数？**

答：可以，只要该参数在常量求值上下文中是可修改的（如全局常量或字面量类型）。

### 典型错误与最佳实践

```cpp
// ❌ 错误：在 constexpr 函数中使用静态变量
constexpr int bad() {
    static int x = 0; // 错误：静态变量不允许
    return ++x;
}

// ✅ 最佳实践：用 constexpr 函数替代复杂的模板元编程
template<int N>
struct Fib { static constexpr int value = Fib<N-1>::value + Fib<N-2>::value; };
// 改写成 constexpr 函数
constexpr int fib(int n) {
    int a = 0, b = 1;
    for (int i = 0; i < n; ++i) {
        int t = a + b;
        a = b; b = t;
    }
    return a;
}
static_assert(fib(10) == 55);
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 5. 二进制字面量（Binary Literals）

**一句话定义**：允许使用 `0b` 或 `0B` 前缀书写二进制整数文字，直接表达位模式。

（详细内容已在《二进制字面量与数字分隔符》文档中完整覆盖，此处仅要点）

- 语法：`int mask = 0b1111'0000;`（可配合数字分隔符）
- 类型与普通整数相同，遵循整数后缀规则。
- 编译期处理，无运行时开销。
- 编译器支持：GCC 5+、Clang 3.4+、MSVC 2015+。

## 6. 数字分隔符（Digit Separators）

**一句话定义**：允许在数字字面量中使用单引号 `'` 作为分隔符，增强可读性，不影响数值。

（详细内容已在专题文档中覆盖，此处仅要点）

- 语法：`int million = 1'000'000;` `double pi = 3.141'592'653;` `int bits = 0b1000'1111;`
- 不能出现在前缀后或后缀前。
- 编译器在词法阶段去除引号。
- 编译器支持：GCC 5+、Clang 3.4+、MSVC 2015+。

## 7. 返回值优化（RVO）保证

**一句话定义**：C++14 强制要求编译器在某些情况下省略拷贝/移动操作（即使拷贝/移动构造函数有副作用），即“复制省略”（Copy Elision）从允许变为必须。

### 详细说明

C++11 中，当返回局部对象时，编译器被允许（但非必须）执行复制省略。C++14 在标准中明确：当 `return` 语句的操作数是一个与函数返回类型相同的**非 volatile 局部对象**时，编译器**必须**省略该对象的拷贝/移动构造（即使不满足 as-if 规则）。这被称作“保证复制省略”（Guaranteed Copy Elision）。

```cpp
struct NonCopyable {
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable(NonCopyable&&) = delete;  // 即使移动也被删除
};

NonCopyable make() {
    NonCopyable local;
    return local;  // C++14 之前错误（因为不能拷贝/移动），C++14 起合法（保证省略）
}
```

### 底层原理与实现机制

编译器直接将返回的对象构造在调用方的栈帧上（通过隐藏引用参数），避免了临时对象的创建和析构。即使拷贝/移动构造函数被 `delete`，只要满足条件，代码依然合法。

### 与相关特性的对比

| 标准 | 拷贝省略 | 保证 |
|------|----------|------|
| C++98/03 | 允许（作为优化） | 否 |
| C++11 | 允许（某些场景必须） | 部分（临时对象初始化） |
| C++14 | 返回局部对象必须省略 | 是（对于非 volatile 局部对象） |
| C++17 | 扩大保证范围（纯右值传递） | 是 |

### 常见面试问题与解答

**问题：为什么 C++14 要强制 RVO？**

答：为了支持不可拷贝、不可移动的类型（如 `std::atomic`、`std::mutex`）也能从工厂函数返回，同时提高性能。强制 RVO 使这类类型的使用成为可能。

### 典型错误与最佳实践

```cpp
// ❌ 错误：显式使用 std::move 会阻止 RVO
NonCopyable make_bad() {
    NonCopyable local;
    return std::move(local);  // 会尝试移动，因移动被删除而编译失败
}

// ✅ 正确：直接返回
NonCopyable make_good() {
    NonCopyable local;
    return local;  // 保证省略
}
```

### 编译器支持

GCC 5.0+、Clang 3.9+（早期版本可能未完全实现）、MSVC 2015+。

## 8. 聚合体成员初始化（Aggregate Member Initialization）

**一句话定义**：C++11 允许在类内为成员提供默认初始化器，C++14 将其扩展至聚合体（aggregate），允许聚合体使用成员初始化器而不需要提供用户定义构造函数。

### 详细语法与用法

```cpp
// C++11 聚合体：只能使用花括号初始化，不能在声明时初始化成员（除非是非静态成员，但那时不允许）
struct Point {
    int x;
    int y;
};
Point p = {1, 2};  // OK

// C++14 允许在聚合体中使用成员初始化器
struct Point2D {
    int x = 0;
    int y = 0;
};
Point2D p1;           // x=0, y=0
Point2D p2 = {1};     // x=1, y=0
Point2D p3 = {1, 2};  // x=1, y=2
```

### 底层原理与实现机制

聚合体的定义在 C++14 中放宽：允许具有类内成员初始化器的聚合体仍然是聚合体（只要没有用户提供构造函数、没有基类、没有虚函数等）。初始化过程：首先按成员初始化器（如果有）初始化，然后用花括号中的值覆盖。

### 与相关特性的对比

| 标准 | 聚合体是否可以有类内成员初始化器 |
|------|----------------------------------|
| C++11 | 否（有类内初始化器则不再是聚合体） |
| C++14 | 是 |

### 常见面试问题与解答

**问题：聚合体的定义在 C++14 中是什么？**

答：聚合体是以下类型：数组类型，或类类型（含 struct/class/union）满足：无用户提供的构造函数（允许显式默认/删除的）、无私有/保护的非静态数据成员、无虚函数、无虚基类、无基类（C++17 放宽允许有基类）。C++14 允许聚合体拥有类内成员初始化器。

### 典型错误与最佳实践

```cpp
// ✅ 最佳实践：为聚合体成员提供默认值，简化初始化
struct Config {
    int timeout = 30;
    bool enabled = true;
    std::string name = "default";
};
Config c1;                // 全默认
Config c2 = {60};         // timeout=60, enabled=true, name="default"
Config c3 = {60, false};  // timeout=60, enabled=false, name="default"
```

### 编译器支持

GCC 5.0+、Clang 3.4+、MSVC 2015+。

## 9. `std::exchange`（库特性，但经常与语言特性一同讨论）

虽然 `std::exchange` 是库特性，但在 C++14 语言特性总结中常被提及。它用于替换对象值并返回旧值，常用于移动构造/赋值中置资源指针为空。

```cpp
struct Buffer {
    int* data;
    Buffer(Buffer&& other) noexcept
        : data(std::exchange(other.data, nullptr)) {}
};
```

## 总结

C++14 语言特性定位为“改进版”，主要解决 C++11 中的不便和缺漏：

| 特性 | 核心价值 |
|------|----------|
| 泛型 Lambda | 模板化函数对象，减少重复代码 |
| 变量模板 | 参数化常量，简化类型相关全局值 |
| `decltype(auto)` | 保留引用的自动类型推导 |
| `constexpr` 增强 | 编译期计算能力接近普通函数 |
| 二进制字面量 + 数字分隔符 | 提高位操作和大数值可读性 |
| 强制 RVO | 支持不可拷贝/移动类型的返回 |
| 聚合体成员初始化 | 简化聚合体默认值设置 |

掌握这些特性是编写现代、高效、可维护 C++14 代码的基础，也是面试中高频考察点（尤其是泛型 Lambda、`constexpr` 增强、`decltype(auto)`）。

**编译器支持汇总**：GCC 5.0+、Clang 3.4+、MSVC 2015+ 完整支持所有 C++14 语言特性。
