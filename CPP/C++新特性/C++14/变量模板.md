# 变量模板（C++14）

**一句话定义**：变量模板允许将变量本身参数化，定义一族变量或静态数据成员，其类型和初始值可以依赖于模板参数，使得模板不仅可以生成函数和类，还能生成类型相关的全局变量或静态成员。

---

## 详细语法与用法

### 基本语法

```cpp
// 变量模板的基本形式
template<typename T>
T pi = T(3.1415926535897932385);

// 使用：实例化为特定类型
double pi_double = pi<double>;
float pi_float = pi<float>;
int pi_int = pi<int>;        // 隐式转换为 3
```

### constexpr 变量模板

C++14 中变量模板可声明为 `constexpr`，用于定义编译期常量。

```cpp
template<typename T>
constexpr T pi = T(3.1415926535897932385L);

// 编译期使用
template<typename T>
T area(T radius) {
    return pi<T> * radius * radius;
}

constexpr double area1 = area(5.0);    // 编译期计算
```

### 特化与偏特化

变量模板支持**全特化**和**部分特化**，与类模板类似。

```cpp
// 主模板
template<typename T>
constexpr T default_value = T();

// 全特化：为 int 提供特定值
template<>
constexpr int default_value<int> = 42;

// 部分特化：所有指针类型默认为 nullptr
template<typename T>
constexpr T* default_value<T*> = nullptr;

// 使用示例
int x = default_value<int>;          // 42
double y = default_value<double>;    // 0.0
int* p = default_value<int*>;        // nullptr
```

**特化类型的灵活性**：变量模板的特化可以指定与主模板不同的类型。

```cpp
template<typename T>
T value = T(100);

// 特化可以改变类型
template<>
std::string value<std::string> = "hello";

// 此时 value<std::string> 的类型是 std::string，而非 std::string
```

### 类作用域的静态数据成员模板

变量模板可以出现在类作用域，表示静态数据成员模板。

```cpp
template<typename T>
class MyClass {
public:
    // 静态数据成员模板
    static T static_value;
};

// 定义静态成员
template<typename T>
T MyClass<T>::static_value = T();

// 使用
MyClass<int>::static_value = 42;
MyClass<double>::static_value = 3.14;
```

### 变参变量模板

结合变参模板，变量模板可以接受多个模板参数。

```cpp
template<typename... Args>
constexpr std::size_t size_of = 0;

template<typename T, typename... Args>
constexpr std::size_t size_of<T, Args...> = sizeof(T) + size_of<Args...>;

// 编译期计算结构体大小总和
static_assert(size_of<int, double, char> == sizeof(int) + sizeof(double) + sizeof(char));
```

### 命名空间作用域的使用

变量模板最常用于命名空间作用域，定义一组全局变量家族。

```cpp
namespace math_constants {
    // 类型安全的数学常量
    template<typename T>
    constexpr T pi = T(3.1415926535897932385L);
    
    template<typename T>
    constexpr T e = T(2.7182818284590452354L);
    
    template<typename T>
    constexpr T sqrt2 = T(1.4142135623730950488L);
}

// 使用
double angle = math_constants::pi<double> * 2.0;
float rad = math_constants::pi<float>;
```

## 底层原理与实现机制

### 1. 引入背景：C++14 前的替代方案

在 C++14 引入变量模板之前，实现类型参数化的常量通常需要采用以下两种方式：

**方式一：类模板的静态数据成员**

```cpp
template<typename T>
struct Pi {
    static constexpr T value = T(3.1415926535897932385L);
};

// 使用
double d = Pi<double>::value;
float f = Pi<float>::value;
```

这种方式的问题：需要定义一个完整的类模板，语法冗长。

**方式二：返回期望值的 constexpr 函数模板**

```cpp
template<typename T>
constexpr T pi() { return T(3.1415926535897932385L); }

// 使用：必须使用函数调用语法
double d = pi<double>();
```

这种方式的问题：必须添加函数调用括号，且返回值是右值。

变量模板将这些方案统一为更直观的语法，直接定义变量模板本身即可。

### 2. 编译器的处理机制

变量模板的实例化遵循与类模板类似的规则：

- **隐式实例化**：当变量模板被引用时，编译器根据模板参数生成具体实例。
- **每个模板参数的组合对应唯一的实例**：如同函数模板的不同类型会生成不同的函数。
- **实例化位置**：变量模板的实例化发生在使用它的翻译单元中，类似于内联变量。

### 3. 内存布局与链接属性

```cpp
template<typename T>
T global_var = T();

// 对于不同类型，编译器生成不同的全局变量
// global_var<int> 和 global_var<double> 是内存中两个完全独立的变量
```

变量模板的每个实例化都生成一个独立的全局对象，具有外部链接属性。在不同翻译单元中对同一类型的实例化，ODR 规则要求它们必须指向同一实体。这与内联变量（C++17）的行为类似。

### 4. constexpr 变量模板的编译期计算

变量模板与 `constexpr` 结合时，编译器在编译期计算其值并直接嵌入使用位置。这是实现编译期泛型常量计算的核心机制。

```cpp
template<typename T>
constexpr T half = T(0.5);

// 使用 half<int> 时，编译器直接计算 0.5 转换为 int 的结果（0）
// 使用 half<double> 时，编译器直接嵌入 0.5 字面量
int arr[half<int> + 1];        // 数组大小为 1
```

## 与相关特性的对比

### 1. 变量模板 vs 类模板静态成员

| 特性 | 变量模板 | 类模板静态成员 |
|------|----------|----------------|
| 语法简洁性 | 更简洁（一行定义） | 冗长（需定义类模板 + 静态成员） |
| 使用方式 | `pi<double>` | `Pi<double>::value` |
| 适用范围 | 全局变量、静态成员 | 仅限于类作用域 |
| 偏特化支持 | ✅ 支持 | ✅ 支持 |
| 代码可读性 | 更高 | 较低（需额外命名空间） |

### 2. 变量模板 vs constexpr 函数模板

| 特性 | 变量模板 | constexpr 函数模板 |
|------|----------|---------------------|
| 语法 | `pi<double>`（变量） | `pi<double>()`（函数调用） |
| 值类别 | 左值（可取地址） | 右值（不能取地址） |
| 使用场景 | 需要变量语义（地址、引用） | 仅需数值 |
| ODR 风险 | 有（需小心多重定义） | 无（函数天然内联） |

### 3. 变量模板 vs 普通全局变量

| 特性 | 变量模板 | 普通全局变量 |
|------|----------|--------------|
| 类型灵活性 | 参数化类型 | 固定类型 |
| 代码复用 | 一次定义，多类型使用 | 每类型需单独定义 |
| 类型安全 | 编译期检查 | 编译期检查 |
| 适用场景 | 需要类型相关常量时 | 类型固定时 |

## 常见面试问题与解答

### 问题 1：变量模板和普通的模板有什么区别？为什么需要引入变量模板？

**答**：C++ 标准库已有类模板和函数模板，但缺少变量模板。若需要定义一个与类型相关的常量（如 `pi` 对不同类型取不同值），C++14 前需使用类模板静态成员或 `constexpr` 函数模板。这些方案语法不够直接，变量模板提供了更简洁、直观的定义方式，实现了对模板化常量的直接支持。变量模板允许在命名空间或类作用域直接定义参数化变量，提升了模板系统的完整性。

---

### 问题 2：变量模板的全特化和偏特化有什么规则？

**答**：变量模板支持全特化和部分特化，与类模板规则类似。

- **全特化**：为特定模板参数提供完整实现，可改变变量类型。
- **部分特化**：为模板参数的某一类别提供实现，如所有指针类型、所有数组类型等。
- **特化顺序**：部分特化必须在主模板之后声明；当多个特化匹配时，选择最特殊的一个。

**注意事项**：
- 当使用 `auto` 推导类型时，特化的类型由初始化器推导，可能与主模板类型不同。
- 变量模板不能用作模板模板参数。

---

### 问题 3：在头文件中定义变量模板时如何避免多重定义链接错误？

**答**：变量模板的每个实例化在不同翻译单元中可能产生多重定义符号。常见解决方案如下：

1. **使用 `constexpr`（C++11/14）**：`constexpr` 变量隐含 `inline`，可避免多重定义，但要求初始化表达式为常量。
2. **使用 `inline`（C++17 起）**：`inline` 变量模板允许在头文件定义，链接器会合并多个定义。
3. **声明 + 单一定义**：在头文件中声明（`extern template`），在单个源文件中显式实例化并定义。
4. **匿名命名空间**：将变量模板定义在匿名命名空间（`.cpp` 内），每个翻译单元获得独立副本。

```cpp
// 方案1：constexpr（推荐）
template<typename T>
constexpr T pi = T(3.14159);

// 方案2：inline（C++17）
template<typename T>
inline T version = T(1.0);
```

---

### 问题 4：变量模板和 constexpr 变量模板在编译期计算中如何配合使用？

**答**：变量模板与 `constexpr` 结合，可在编译期定义类型相关的常量表达式，广泛应用于模板元编程、编译期断言和性能优化。

```cpp
// 类型特征辅助变量模板（C++17 标准库实践）
template<typename T>
inline constexpr bool is_integral_v = std::is_integral<T>::value;

template<typename T>
inline constexpr T pi_v = T(3.1415926535897932385L);

// 编译期使用
static_assert(is_integral_v<int>, "int should be integral");
static_assert(!is_integral_v<double>, "double should not be integral");

constexpr double area = pi_v<double> * 25.0;
```

这种模式在 C++17 标准库中被广泛采用（如 `std::is_integral_v<T>`），极大简化了类型特征的使用。

## 典型错误与最佳实践

### ❌ 典型错误

#### 错误 1：变量模板在头文件中未使用 constexpr 导致多重定义

```cpp
// header.h
template<typename T>
T pi = T(3.14159);   // ❌ 多重定义链接错误
```

**解决方案**：使用 `constexpr`（C++11/14）或 `inline`（C++17）修饰。

---

#### 错误 2：变量模板特化时类型不一致导致意外行为

```cpp
template<typename T>
T value = T(100);

// 特化改变了类型
template<>
std::string value<std::string> = "hello";

auto x = value<int>;     // int，100
auto s = value<std::string>;  // std::string，"hello"
// 注意：value<std::string> 的类型是 std::string，并非 std::string
```

**注意**：特化可以改变类型，但要确保使用方理解这一行为。

---

#### 错误 3：在需要常量的地方使用非 constexpr 变量模板

```cpp
template<typename T>
T pi = T(3.14159);   // 非 constexpr

template<typename T>
T area(T r) {
    return pi<T> * r * r;   // ✅ 运行时可以
}

constexpr double a = area(5.0);  // ❌ 编译错误：pi<T> 不是常量表达式
```

**解决方案**：声明为 `constexpr` 变量模板。

---

### ✅ 最佳实践

| 实践 | 说明 |
|------|------|
| **头文件中使用 `constexpr` 变量模板** | 自动获得内联语义，避免多重定义 |
| **为数学常量定义变量模板** | 如 `pi<T>`、`e<T>`，实现类型安全的数学运算 |
| **配合类型特征使用** | 用变量模板简化类型特征访问（如 `is_integral_v<T>` 模式） |
| **命名空间封装** | 将相关变量模板放入命名空间，避免全局命名空间污染 |
| **特化时保持语义一致** | 特化应维持与主模板相同的语义，避免行为意外 |
| **C++17 起可用 `inline` 变量模板** | 若无法使用 `constexpr`（如需要运行时初始化），使用 `inline` |

```cpp
// 好的示例：类型特征辅助变量模板
template<typename T>
inline constexpr bool is_floating_point_v = std::is_floating_point<T>::value;

// 好的示例：编译期类型相关常量
template<typename T>
constexpr T speed_of_light = T(299792458);

// 好的示例：封装在命名空间中
namespace constants {
    template<typename T>
    constexpr T pi = T(3.1415926535897932385L);
}
```
