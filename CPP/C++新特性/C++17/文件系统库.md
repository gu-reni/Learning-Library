# 文件系统库（std::filesystem）（C++17）

**一句话定义**：`std::filesystem` 是一个跨平台的文件系统操作库，提供了对文件、目录、路径的统一抽象，支持路径操作、文件元数据查询、目录遍历、文件拷贝/移动/删除等常见文件系统操作，替代了 POSIX 的 `opendir/readdir` 和 Windows API 的 `FindFirstFile/FindNextFile` 等平台相关接口。

---

## 详细语法与用法

### 核心组件

| 组件 | 说明 |
|------|------|
| `std::filesystem::path` | 路径对象，处理不同平台的路径格式（`/` 或 `\`） |
| `std::filesystem::directory_entry` | 目录条目，包含路径和文件属性 |
| `std::filesystem::directory_iterator` | 目录迭代器，遍历目录内容 |
| `std::filesystem::recursive_directory_iterator` | 递归目录迭代器 |
| `std::filesystem::file_status` | 文件状态（类型、权限） |
| `std::filesystem::space_info` | 磁盘空间信息 |
| `std::filesystem::file_time_type` | 文件时间戳（`std::chrono::time_point`） |

### 基本路径操作

```cpp
#include <filesystem>
#include <iostream>
namespace fs = std::filesystem;

// 路径构造
fs::path p1("/usr/local/bin");
fs::path p2 = "C:\\Program Files\\MyApp";  // Windows
fs::path p3 = "C:/Program Files/MyApp";    // 也支持正斜杠

// 路径拼接
fs::path p = p1 / "gcc" / "g++";           // 使用 / 运算符
p += ".exe";                                // 字符串追加

// 路径分解
std::cout << p.root_name() << '\n';        // "C:" (Windows)
std::cout << p.root_directory() << '\n';   // "/" 或 "\\"
std::cout << p.root_path() << '\n';        // 根路径
std::cout << p.relative_path() << '\n';    // 相对部分
std::cout << p.parent_path() << '\n';      // 父目录
std::cout << p.filename() << '\n';         // 文件名（含扩展名）
std::cout << p.stem() << '\n';             // 主干（不含扩展名）
std::cout << p.extension() << '\n';        // 扩展名（含点）

// 路径格式转换
std::string s = p.string();                // 本地编码字符串
std::wstring ws = p.wstring();             // 宽字符串
p.make_preferred();                        // 转换为平台首选分隔符
```

### 文件系统查询

```cpp
fs::path p = "example.txt";

// 存在性检查
if (fs::exists(p)) {
    std::cout << "exists\n";
}

// 文件类型
if (fs::is_regular_file(p))     // 普通文件
if (fs::is_directory(p))        // 目录
if (fs::is_symlink(p))          // 符号链接
if (fs::is_block_file(p))       // 块设备
if (fs::is_character_file(p))   // 字符设备
if (fs::is_fifo(p))             // FIFO/管道
if (fs::is_socket(p))           // Socket

// 文件大小
uintmax_t size = fs::file_size(p);

// 时间戳
auto ftime = fs::last_write_time(p);
auto ltime = fs::last_write_time(p);  // 最后修改时间
// 转换为 time_t（C++20 有更方便的转换）
auto sys_time = std::chrono::file_clock::to_sys(ftime);

// 权限
auto perms = fs::status(p).permissions();
bool can_read = (perms & fs::perms::owner_read) != fs::perms::none;
```

### 目录操作

```cpp
// 创建目录
fs::create_directory("mydir");              // 创建单层目录
fs::create_directories("a/b/c/d");          // 递归创建多层目录

// 复制文件/目录
fs::copy("source.txt", "dest.txt");                  // 复制文件
fs::copy("srcdir", "dstdir", fs::copy_options::recursive); // 递归复制目录

// 移动/重命名
fs::rename("old.txt", "new.txt");

// 删除
fs::remove("file.txt");                     // 删除文件
fs::remove_all("dir");                      // 递归删除目录

// 获取当前路径
fs::path cur = fs::current_path();
fs::current_path("/new/path");              // 更改当前工作目录

// 磁盘空间
auto space = fs::space("/");
std::cout << "free: " << space.free << " bytes\n";
```

### 目录遍历

```cpp
// 非递归遍历
for (const auto& entry : fs::directory_iterator("/tmp")) {
    std::cout << entry.path() << '\n';
}

// 递归遍历
for (const auto& entry : fs::recursive_directory_iterator(".")) {
    if (fs::is_regular_file(entry.path())) {
        std::cout << entry.path().filename() << " (" << entry.file_size() << " bytes)\n";
    }
}

// 带过滤的遍历
for (const auto& entry : fs::directory_iterator(".")) {
    if (entry.path().extension() == ".cpp") {
        // 处理 cpp 文件
    }
}
```

### 错误处理

```cpp
// 抛出异常的版本（默认）
try {
    auto size = fs::file_size("nonexistent.txt");
} catch (const fs::filesystem_error& e) {
    std::cout << e.what() << '\n';
    std::cout << "path1: " << e.path1() << '\n';
    std::cout << "path2: " << e.path2() << '\n';
}

// 不抛出异常的版本（通过 error_code）
std::error_code ec;
auto size = fs::file_size("nonexistent.txt", ec);
if (ec) {
    std::cout << "Error: " << ec.message() << '\n';
}
```

### 权限操作

```cpp
// 设置权限
fs::permissions("script.sh",
                fs::perms::owner_exec | fs::perms::group_exec | fs::perms::others_exec,
                fs::perm_options::add);

// 移除写权限
fs::permissions("readonly.txt", fs::perms::owner_write, fs::perm_options::remove);
```

### 符号链接操作

```cpp
fs::create_symlink("target", "link");       // 创建符号链接
fs::create_directory_symlink("target_dir", "dir_link");
fs::is_symlink(link_path);                  // 检查是否为链接
fs::read_symlink(link_path);                // 读取链接目标
```

## 底层原理与实现机制

### 1. 跨平台抽象

`std::filesystem` 封装了不同操作系统的文件系统 API：
- **POSIX 系统**（Linux/macOS）：使用 `stat`、`opendir`/`readdir`/`closedir`、`unlink`、`rmdir`、`symlink`、`readlink` 等。
- **Windows**：使用 `GetFileAttributesW`、`FindFirstFileW`/`FindNextFileW`、`DeleteFileW`、`RemoveDirectoryW`、`CreateSymbolicLinkW` 等。

路径类 `path` 内部使用 `std::string` 或 `std::wstring` 存储，并提供格式转换（通用正斜杠与平台分隔符）。路径比较、拼接等操作在 C++ 层实现，不依赖系统调用。

### 2. 性能考虑

- `directory_iterator` 在构造时获取目录内容列表（可能一次性读取或懒加载，取决于实现）。
- `recursive_directory_iterator` 使用栈或递归实现深度遍历。
- 频繁调用 `exists`、`is_directory` 等会导致多次 `stat` 系统调用，可考虑缓存 `directory_entry`（它缓存了文件状态）。
- 在循环中访问文件属性时，使用 `directory_entry` 的成员函数（如 `entry.file_size()`）比先取 `path` 再调用 `fs::file_size(path)` 更高效，因为 `entry` 已缓存了状态。

### 3. 时间类型

`file_time_type` 是 `std::chrono::time_point<std::chrono::file_clock>`，`file_clock` 是 C++20 引入的时钟，C++17 中可能使用系统时钟。不同平台的时间精度和纪元不同，转换需注意。

### 4. 错误处理机制

大多数 `filesystem` 函数提供两个重载：
- 抛出异常版本：失败时抛出 `std::filesystem::filesystem_error`，包含相关路径和错误码。
- `error_code` 版本：通过引用参数返回错误码，不抛出异常。

### 5. 原子性

文件系统操作通常不是原子的（如 `rename` 在同一文件系统内通常是原子的，但跨设备不是）。标准不保证任何操作的原子性，需外部同步。

## 与相关特性的对比

### 1. `std::filesystem` vs POSIX API vs Windows API

| 方面 | `std::filesystem` | POSIX | Windows API |
|------|-------------------|-------|-------------|
| 跨平台 | 是 | 否（仅 Unix-like） | 否 |
| 类型安全 | 高（`path` 类型） | 低（字符串指针） | 低（字符串指针） |
| 异常安全 | 支持异常/error_code | 需检查返回值 | 需检查返回值 |
| 代码量 | 少 | 多 | 多 |
| 性能 | 略低于原生 API（有抽象开销） | 最高 | 最高 |

### 2. `std::filesystem` vs Boost.Filesystem

C++17 的 `std::filesystem` 基于 Boost.Filesystem 演化而来，接口基本兼容，但有以下区别：
- `std::filesystem` 在 C++17 标准库中，无需额外依赖。
- Boost 版本支持更多编译器（包括旧版）和更多功能（如某些扩展）。
- `std::filesystem` 某些行为（如权限操作）略有不同。

### 3. `directory_iterator` vs 手动遍历

手动遍历需调用平台 API，`directory_iterator` 提供了统一的 RAII 接口，支持范围 for 循环，更安全、更简洁。

## 常见面试问题与解答

### 问题 1：`std::filesystem::path` 如何保证跨平台兼容性？如何处理 Windows 和 Linux 路径分隔符差异？

**答**：`path` 内部存储路径为通用格式（使用正斜杠 `/` 作为分隔符），在输出时可根据平台转换为本地分隔符（通过 `make_preferred()` 或 `operator<<`）。`path` 的 `/` 运算符会自动处理分隔符，无论输入使用何种分隔符。例如：

```cpp
fs::path p = "C:/Users/name";   // Windows 风格
p /= "file.txt";                // 自动添加正确分隔符
std::cout << p << '\n';         // 输出 "C:\Users\name\file.txt" (Windows)
```

### 问题 2：`std::filesystem::remove_all` 是如何实现递归删除的？是否安全？

**答**：`remove_all` 递归删除目录及其所有内容，返回删除的文件/目录数量。实现通常使用后序遍历（先删除子项，再删除自身）。它是安全的，但需注意：
- 如果删除过程中出现错误（如权限不足），某些实现可能提前停止。
- 对符号链接的处理：默认删除符号链接本身，不删除其目标。
- 在多线程环境下，删除过程中其他线程可能修改文件系统，导致未定义行为。

### 问题 3：如何高效地遍历一个包含数百万文件的大目录？`directory_iterator` 是否会一次性加载所有条目？

**答**：`directory_iterator` 的实现通常不会一次性加载所有条目，而是每次迭代时调用系统 API 获取下一个条目（如 POSIX 的 `readdir`）。因此它可以处理大目录而不消耗过多内存。但频繁调用 `entry.status()` 或 `entry.file_size()` 等会触发系统调用，影响性能。如果需要多次访问同一文件的属性，考虑将 `directory_entry` 存储到容器中，或使用 `recursive_directory_iterator` 的 `disable_recursion_pending` 等选项。

### 问题 4：`std::filesystem` 操作失败时如何获得详细错误信息？

**答**：有两种方式：
1. 使用抛出异常的重载，捕获 `filesystem_error`，调用 `.path1()` 和 `.path2()` 获取相关路径，`.code()` 获取错误码。
2. 使用 `std::error_code` 版本，检查 `ec`，调用 `ec.message()` 获取错误描述，`ec.value()` 获取平台相关错误码。

## 典型错误与最佳实践

### ❌ 典型错误

#### 错误 1：拼接路径时使用字符串拼接而非 `/` 运算符

```cpp
fs::path p = "dir";
p += "/file.txt";   // 错误：得到 "dir/file.txt"，但未处理平台分隔符
p /= "file.txt";    // 正确：使用 /
```

#### 错误 2：假定文件扩展名包含点

```cpp
fs::path p = "archive.tar.gz";
std::string ext = p.extension().string();  // ".gz"，不是 ".tar.gz"
// 如需获取多个扩展名，需手动处理
```

#### 错误 3：在遍历目录时修改目录内容导致迭代器失效

```cpp
for (auto& entry : fs::directory_iterator("dir")) {
    if (entry.is_regular_file())
        fs::remove(entry.path());   // 可能使迭代器失效（实现相关）
}
// 安全做法：先收集路径，再删除
std::vector<fs::path> to_remove;
for (auto& entry : fs::directory_iterator("dir")) {
    if (entry.is_regular_file()) to_remove.push_back(entry.path());
}
for (auto& p : to_remove) fs::remove(p);
```

#### 错误 4：忽略权限和符号链接的安全性

```cpp
// 递归删除时可能删除不希望删除的内容
fs::remove_all("/");      // 危险！可能删除整个文件系统（需要权限，但不应尝试）
// 应始终验证路径
```

#### 错误 5：混淆绝对路径和相对路径

```cpp
fs::path p = "file.txt";
if (!p.is_absolute()) {
    p = fs::current_path() / p;   // 转换为绝对路径
}
```

#### 错误 6：在多线程环境中无保护地使用 `current_path()`

`current_path()` 不是线程安全的（修改全局进程状态）。应尽量避免在多线程中更改工作目录，或使用互斥锁保护。

### ✅ 最佳实践

| 实践 | 说明 |
|------|------|
| **使用 `/` 运算符拼接路径** | 自动处理分隔符，跨平台安全 |
| **优先使用 `error_code` 版本** | 在 GUI 应用或需要细粒度错误处理的场景，避免异常 |
| **遍历目录时缓存 `directory_entry`** | 减少系统调用 |
| **递归删除前检查路径** | 避免删除根目录或关键系统目录 |
| **使用 `fs::path::lexically_normal()` 标准化路径** | 去除 `.` 和 `..`，便于比较 |
| **避免频繁调用 `exists` 后再操作** | 存在竞态条件（TOCTOU），应直接操作并处理错误 |
| **使用 `std::error_code` 而非字符串拼接错误信息** | 便于分类处理 |
| **对用户提供的路径进行合法性检查** | 防止路径遍历攻击（`../`） |

```cpp
// 好的示例：安全地复制文件
bool safe_copy(const fs::path& src, const fs::path& dst) {
    std::error_code ec;
    fs::copy(src, dst, fs::copy_options::overwrite_existing, ec);
    if (ec) {
        std::cerr << "copy failed: " << ec.message() << '\n';
        return false;
    }
    return true;
}

// 好的示例：递归查找特定扩展名的文件
std::vector<fs::path> find_files(const fs::path& dir, const std::string& ext) {
    std::vector<fs::path> result;
    for (const auto& entry : fs::recursive_directory_iterator(dir)) {
        if (entry.is_regular_file() && entry.path().extension() == ext) {
            result.push_back(entry.path());
        }
    }
    return result;
}
```

## 编译器支持与版本演进

（根据用户要求，本节省略详细表格，仅简述）

- **C++17**：引入 `std::filesystem`。
- **C++20**：添加 `std::filesystem::path` 的 `std::format` 支持，`file_time_type` 转换为 `std::chrono::sys_time` 更方便。
- **C++23**：增加 `std::filesystem::path` 的 `std::string_view` 构造函数等细微改进。

**编译器支持**：GCC 8+（需要 `-lstdc++fs` 或后续版本无需）、Clang 7+（需要 `-lc++fs`）、MSVC 2017 15.7+（完整支持）。

---

**总结**：`std::filesystem` 是 C++17 中重要的跨平台文件操作库，替代了以往依赖平台 API 或 Boost.Filesystem 的做法。面试中常考路径操作、目录遍历、错误处理、与旧 API 的对比以及安全注意事项。掌握 `std::filesystem` 能显著提高文件处理代码的可移植性和安全性。
