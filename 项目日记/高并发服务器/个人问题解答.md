```cpp
        std::cerr<<"Failed to create socket"<<std::endl;

    }

    std::cout << "Socket created successfully, fd = " << listen_fd << std::endl;

    close(listen_fd);

    return 0;

```
### 问题描述：**为什么`fd=3`**
```bash
ubuntu_user@codeubuntu:~/shared_files/code/CPP$ ./tcp_server 
Server starting...
Socket created successfully, fd = 3
```
### 原因：
因为文件描述符 0、1、2 已经被系统预先占用：
- **0**：标准输入（stdin）
- **1**：标准输出（stdout）
- **2**：标准错误（stderr）
当程序调用 `socket()` 创建第一个套接字时，系统会分配当前可用的最小未使用文件描述符，即 **3**。
## 问题：二
```cpp
struct sockaddr_in server_addr;
memset(&server_addr, 0, sizeof(server_addr));
```
### 问题描述**为什么要用 `memset`**：
### 原因：
我们创建一个局部变量 `server_addr`，它的初始值是随机的（栈上的垃圾数据）。为了确保结构体中未使用的字段（如 `sin_zero`）是干净的，我们用 `memset` 将整个结构体清零。这是一种常见的防御性编程。
## 问题：三
```cpp
server_addr.sin_family = AF_INET;
server_addr.sin_port = htons(8080);
server_addr.sin_addr.s_addr = htonl(INADDR_ANY);
```
### 问题描述**为什么需要`htons`转换？**：
### 原因：
因为不同的 CPU 对多字节整数的存储顺序不同（小端或大端），而网络协议规定使用大端序。所以发送到网络的数据必须转换为网络字节序。htons可以将 16 位整数从主机字节序转换为网络字节序（大端）。
## 问题：四
```cpp
if (bind(listen_fd, (struct sockaddr*)&server_addr, sizeof(server_addr)) < 0) {
    std::cerr << "bind failed" << std::endl;
    close(listen_fd);
    return 1;
}
```
### 问题描述：**为什么`(struct sockaddr*)&server_addr`强制转换？**
### 原因：
因为 `bind` 可以用于多种地址族（IPv4、IPv6、Unix 域等），所以参数类型是通用的 `struct sockaddr *`。我们实际用的是 `struct sockaddr_in`，但它和 `struct sockaddr` 的内存布局兼容（前两个字段相同），所以可以安全转换。

```cpp
    struct sockaddr_in client_addr;
```

### 问题描述**为什么要新建一个`sockaddr_in`**：
### 原因：
因为监听 socket 和已连接 socket 是不同的。`监听 socket 保持打开`，继续接受新连接；`已连接 socket 用于与特定客户端通信`。

#  阶段二
## 问题：一
### 问题描述：如何让服务器**同时处理多个客户端**？
### 解决方法：
1. **多进程**：`fork` 一个子进程处理每个客户端，父进程继续等待新连接。
2. **多线程**：`pthread_create` 创建新线程处理每个客户端，主线程继续 `accept`。
3. **I/O 多路复用**：使用 `select`/`poll`/`epoll` 在一个线程内监听多个文件描述符。
## 问题：二
### 问题描述：为什么只用`g++ tcp_server.cpp -o tcp_server` 没有加`-pthread`也能编译成功：
### 原因：
从 glibc 2.34 开始，**pthread 库的函数被直接整合进了 libc 中**，因此编译时不再需要显式链接 `-pthread` 或 `-lpthread`。

# 阶段三
## 问题：一
### 问题描述：## 为什么要用 epoll？
### 原因：
多线程模型虽然简单，但每个客户端需要一个线程，当并发连接数达到几千时，线程创建、切换、内存开销都非常大。  epoll允许一个线程同时监听数百、数千个 socket，只在 socket 就绪（有数据可读、可写等）时才去处理，从而避免了大量线程的浪费。epoll 是 Linux 特有的高效 I/O 多路复用机制，性能远高于传统的 select/poll。
