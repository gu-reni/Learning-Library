## 1. 身份证输入框测试用例设计。
#### 

#### 一句话总结

 身份证输入框测试需覆盖**格式校验、业务规则（年龄/性别/地域）、兼容性、安全性、用户体验**五大维度，设计正向与反向用例验证合法性识别、错误提示及容错处理。

---

#### 详细测试用例设计

 一、**格式校验**（核心：18位编码规则）

 - **正向用例** 输入有效18位身份证（尾号含X）：11010119900101123X→ 通过

 - 输入有效15位旧身份证（仅兼容老系统）：110101900101123→ 通过

 - **反向用例位数错误**：17位（11010119900101123）、19位（1101011990010112345）→ 提示“身份证应为18位”

 - **非法字符**：含字母（除尾号X外）、符号（110101!9900101123X）→ 提示“包含非法字符”

 - **校验位错误**：修改校验位（110101199001011234→ 真实校验位应为X）→ 提示“身份证不合法”

---

 二、**业务规则验证**（解析编码含义）

 - **出生日期** 有效日期：110101*19900101*123X（1990年1月1日）→ 通过

 - 无效日期： 未来日期（110101203001011234）→ 提示“出生日期无效”

 - 不存在的日期（110101199002301234）→ 提示“日期错误”

 - **性别识别** 第17位奇数：*...11*...X→ 识别为**男**

 - 第17位偶数：*...12*...X→ 识别为**女**

 - 验证系统是否正确显示/使用该性别数据

 - **地域码校验** 有效地域码（如110101=北京东城区）→ 通过

 - 不存在的地域码（999999）→ 提示“地区码无效”

---

 三、**交互与兼容性** 

 - **输入体验** 自动格式化：输入时自动分段（如110101-19900101-123X）

 - 粘贴支持：从剪贴板粘贴身份证号 → 正常识别

 - 键盘适配：移动端自动弹出**数字键盘**（含X键）

 - **兼容性** 浏览器：Chrome/Firefox/Safari 下输入框样式、校验逻辑一致

 - 移动端：iOS/Android 不同输入法（全角/半角）兼容性

---

 四、**安全性与容错** 

 - **安全防护** SQL注入测试：输入110101' OR 1=1--→ 拦截并提示非法输入

 - XSS攻击测试：输入<script>alert(1)</script>→ 前端转义或拦截

 - **容错处理** 空格处理：首尾空格自动去除（11010119900101123X→ 通过）

 - 中间空格：110101 19900101 123X→ 提示“请勿输入空格”

---

 五、**特殊场景** 

 - **边界值测试** 最小日期：最早有效日期（如19000101）

 - 最大日期：当前日期（避免未来日期）

 - **加密传输** 抓包验证：接口传输是否加密（非明文110101...）

 - **重复提交** 同一身份证连续提交 → 系统是否去重或提示“已存在”

## 2. 登录页面测试用例设计。
#### 

#### 一句话总结

 登录页面测试需覆盖**功能流程、安全性、兼容性、用户体验、性能及容错处理**六大核心维度，设计用例验证合法/非法输入、防御机制、多端适配及异常场景恢复能力。

---

#### 详细测试用例设计

 一、**功能测试**（核心：输入校验与流程验证）

 - **合法登录** 正确用户名+密码 → 跳转至首页（验证Welcome, [用户名]显示）

 - 记住密码 → 关闭页面重开自动填充

 - 密码显示/隐藏切换 → 明文不可见（●●●●）

 - **非法登录用户名错误**（存在但错误）→ 提示“账号或密码错误”

 - **密码错误**（账号存在）→ 同上，**不明确提示“密码错误”**（防暴力破解）

 - **空输入**： 用户名为空 → 实时提示“请输入账号”

 - 密码为空 → 提交后提示“请输入密码”

 - **已注销/禁用账号** → 提示“账号不可用，请联系管理员”

 - **密码管理** 忘记密码 → 跳转重置页，验证邮件/SMS链接有效性

 - 修改密码后 → 用旧密码登录失败，新密码成功

---

 二、**安全性测试**（关键防御场景）

 - **暴力破解防护** 连续错误5次 → 强制锁定账号/需验证码 → 解锁后恢复登录

 - 验证码失效机制：60秒后自动刷新，**一次性使用**

 - **数据传输安全** 抓包工具（如Fiddler）检查：密码字段 **HTTPS加密传输**（非明文）

 - 请求头验证：禁用HTTP弱协议（仅允许TLS 1.2+）

 - **注入攻击防御** SQL注入：输入admin' --→ 拦截并提示非法字符

 - XSS攻击：输入<script>alert(1)</script>→ 前端转义为文本显示

 - **敏感信息泄露** 错误提示**不暴露细节**（如避免“用户名不存在”“密码强度弱”）

 - 浏览器控制台**无密码明文输出**（禁用console.log(password)）

---

 三、**兼容性与多端适配** 

 - **浏览器兼容** Chrome/Firefox/Safari/Edge：布局无错位，功能正常

 - 低版本IE：优雅降级（提示升级或基础功能可用）

 - **移动端适配** 键盘适配：输入账号自动弹出**英文键盘**，密码弹出**数字+符号键盘**

 - 横竖屏切换：布局自适应，输入框不被遮挡

 - 生物识别：指纹/人脸登录（iOS/Android）→ 绑定后快捷登录

 - **分辨率响应** 手机小屏（320px）：输入框垂直排列，按钮大小可触控

 - PC大屏（1920px）：表单居中显示，比例协调

---

 四、**性能与容错能力** 

 - **性能边界** 100用户并发登录 → 平均响应时间 <2秒，无超时失败

 - 弱网络测试（3G）：登录按钮置灰防重复提交，超时后提示“网络超时”

 - **异常恢复** 登录中途断网 → 恢复网络后自动重试/手动提交成功

 - 会话超时：登录后闲置30分钟 → 操作时跳转回登录页

 - **数据一致性** 登录后刷新页面 → 保持登录状态（验证Cookie/Token有效期）

 - 多设备登录：手机登录后PC端**强制下线**（或允许并行）

---

 五、**特殊场景覆盖** 

 - **多语言环境** 切换英文界面 → 错误提示同步翻译（如“Invalid password”）

 - 长文本兼容：德语长单词布局不溢出

 - **无障碍访问** 屏幕阅读器朗读：焦点移至密码框时提示“密码输入区，加密内容”

 - 键盘导航：Tab键按顺序切换输入框，Enter提交

 - **边界值测试** 超长输入：用户名输入1000字符 → 前端截断或后端拒收

 - 特殊字符：用户名含@._-→ 允许通过（如邮箱格式）

## 3. `rm -rf path`命令功能的测试用例设计设计。
#### 

#### 一句话总结

 rm -rf path命令的测试需覆盖**路径类型、权限控制、特殊字符、递归深度、防误删机制及异常场景**，验证其**强制递归删除能力**与**风险边界**，同时设计**防护性用例**避免灾难性操作。

---

#### 详细测试用例设计

 一、**基础功能验证**（正确删除目标）

| 测试场景 | 命令示例 | 预期结果 |
| --- | --- | --- |
| 删除空目录 | rm -rf ./empty_dir/ | 目录被删除，无错误提示 |
| 删除非空目录 | rm -rf ./data/ | 目录及内部所有文件/子目录递归删除 |
| 删除单个文件 | rm -rf important.log | 文件被删除 |
| 删除软链接 | rm -rf symlink_to_dir | 仅删除软链接本身，不删除目标目录 |
| 删除硬链接 | rm -rf hardlink_to_file | 删除硬链接，原文件保留（inode引用数减1） |

---

 二、**权限与安全控制** 

| 场景 | 命令 | 预期结果 |
| --- | --- | --- |
| 无权限目录 | rm -rf /root/protected/ | 普通用户执行失败，提示Permission denied |
| 部分文件无写权限 | rm -rf ./mixed_perms_dir/ | 有权限的文件/目录被删除，无权限的保留并报错 |
| root用户删除系统文件 | sudo rm -rf /bin/ls | 文件被删除（高危！仅限测试环境） |

---

 三、**路径与参数边界** 

| 场景 | 命令 | 预期结果 |
| --- | --- | --- |
| 路径含空格 | rm -rf "dir with space/" | 正确识别路径，删除成功 |
| 路径含特殊字符 | rm -rf 'dir_!@#$%^/'` | 正确处理字符，删除成功 |
| 路径为.（当前目录） | rm -rf . | 递归删除当前目录下所有内容（危险！） |
| 路径为..（上级目录） | rm -rf .. | 尝试删除上级目录 → 权限不足报错（防误删） |
| 路径为空字符串 | rm -rf "" | 报错cannot remove '': No such file |

---

 四、**防误删保护机制** 

| 场景 | 测试重点 | 预期结果 |
| --- | --- | --- |
| 根目录防护 | rm -rf / | 现代Linux系统拒绝执行（提示--no-preserve-root或直接报错） |
| 通配符误用 | rm -rf * /data/ | 因空格误解析为删除*和/data→ 拒绝执行并报错 |
| 变量未赋值误删 | rm -rf $UNSET_VAR/ | 变量为空 → 解析为rm -rf /→ 触发根目录防护 |

---

 五、**异常与故障处理** 

| 场景 | 模拟方式 | 预期结果 |
| --- | --- | --- |
| 删除不存在的路径 | rm -rf /fake_path | 报错No such file or directory，返回非0状态码 |
| 文件被占用中删除 | 另一个进程持有文件句柄 | 文件被标记删除（ls不可见），但磁盘空间在进程结束后释放 |
| 文件系统只读（ro remount） | mount -o remount,ro / | 执行失败 → 提示Read-only file system |

---

 六、**递归深度与性能** 

| 场景 | 测试方法 | 预期结果 |
| --- | --- | --- |
| 超深嵌套目录 | 创建1000层嵌套目录 | 递归删除成功，无栈溢出 |
| 百万小文件删除 | mkdir mass; cd mass; touch {1..1000000} | 删除耗时可控，不卡死系统 |
| 删除大文件（10GB+） | fallocate -l 10G bigfile | 立即释放磁盘空间（df可验证） |

---

#### 防护性测试设计原则

 - **隔离环境执行**： 使用docker容器或虚拟机测试高危操作（如删除根目录）。 ```bash docker run -it --rm alpine sh -c "mkdir test; rm -rf /test" # 安全测试 ```

 - **权限最小化**： 测试时使用普通用户账号，避免sudo提权。

 - **备份与快照**： 测试前对系统/磁盘做快照，误删后可快速恢复。

 - **命令别名防护**： 生产环境配置alias rm='rm -i'或使用safe-rm工具拦截危险路径。

## 5. 进入某短视频App长期无响应原因分析。
#### 

#### 一句话总结

 短视频App长期无响应主要由**客户端资源异常（内存泄漏/主线程阻塞）、服务端故障（接口超时/微服务崩溃）、网络传输中断（弱网/DNS污染）、设备性能瓶颈（硬件老化/系统资源耗尽）及本地数据损坏（缓存冲突/数据库异常）** 五大类原因导致，需结合日志与场景复现定位根源。

#### 详细解释

 一、**客户端资源与代码缺陷** 

 - **内存泄漏/溢出表现**：应用长时间运行后卡死，后台进程未释放资源（如图片缓存、未注销监听器），导致内存占满触发OOM（Out of Memory）。

 - **典型案例**：短视频播放页未释放解码器资源，连续刷视频后崩溃。

 - **排查**：Android使用LeakCanary检测泄漏点；iOS通过Xcode Instruments分析内存峰值。

 - **主线程阻塞原因**：耗时操作（如大文件读写、复杂计算）占用UI线程，触发ANR（Application Not Responding）。

 - **场景**：视频下载同时进行特效渲染，界面冻结超5秒。

 - **解决**：异步任务（Android的Coroutine/iOS的DispatchQueue）分离耗时逻辑。

 - **渲染逻辑缺陷表现**：画面撕裂、白屏/黑屏，多因视频解码器兼容性问题或GPU资源争用。

 - **诱因**：硬编解码器与设备驱动不匹配（如某些骁龙芯片机型）。

---

 二、**服务端故障** 

 - **接口超时与崩溃特征**：App卡在内容加载页，抓包显示HTTP 504（Gateway Time-out）或服务不可用。

 - **根源**： 高并发请求压垮服务器（如热门直播突发流量）。

 - 微服务雪崩（依赖服务链故障，如推荐算法服务宕机）。

 - **数据返回异常案例**：视频元数据（如URL、分辨率）格式错误，客户端解析崩溃。

 - **排查**：日志分析服务端响应体是否含null字段或超长字符串。

---

 三、**网络传输问题** 

 - **弱网与断网重传现象**：请求持续挂起无超时，界面假死。

 - **机制缺陷**：未设合理超时（如TCP连接超时＞30秒）或重试策略无限循环。

 - **DNS污染/CDN故障表现**：特定区域用户无法加载视频，其他功能正常。

 - **验证**：切换WiFi/4G对比或pingCDN节点延迟。

---

 四、**设备与系统层问题** 

 - **硬件性能不足场景**：某些低端机运存＜3GB时，多视频流并行解码卡死。

 - **数据**：Android 8.0以下系统因内存管理缺陷更易ANR。

 - **系统资源耗尽原因**： 存储空间不足（＜1GB）：视频缓存写入失败阻塞I/O。

 - 后台进程抢占CPU（如系统更新服务）。

 - **碎片化兼容问题典型**： 折叠屏展开/折叠时分辨率切换未适配，渲染引擎崩溃。

 - 权限未动态申请（如Android 11+的MANAGE_EXTERNAL_STORAGE）导致文件读取失败。

---

 五、**数据与缓存异常** 

 - **本地缓存损坏表现**：仅特定用户无响应，清除缓存后恢复。

 - **根源**： 缓存文件写入中断（如断电）致结构错误。

 - 多线程并发写冲突。

 - **数据库锁竞争场景**：观看历史频繁写入时SQLite死锁，界面冻结。

 - **方案**：启用WAL模式或异步数据库操作。

---

#### 关键排查流程

 - **日志定位**： 客户端：抓取adb logcat或Xcode控制台日志，过滤ANR/OOM/Exception关键词。

 - 服务端：分析Nginx/Apache错误日志（如504状态码峰值）。

 - **场景复现**： 低端机+弱网模拟：Android Studio模拟器限制CPU/网络。

 - 压力测试：JMeter模拟千人并发请求接口。

 - **降级与监控**： 服务端：熔断机制（如Hystrix）隔离故障模块。

 - 客户端：APM工具（Firebase Crashlytics）实时监控崩溃率。
