# 一.磁盘配额与进阶文件系统管理

## 磁盘配额（Quota）

### 什么是 Quota

Quota 即磁盘配额，用于限制用户或群组在特定文件系统上的磁盘使用量（block）或文件数量（inode），以确保系统资源公平分配。常见应用场景包括：
- 限制邮件服务器用户的邮件空间。
- 限制 Web 服务器用户的网页空间。
- 限制文件服务器用户的共享空间。

### Quota 的使用限制
- **文件系统依赖**：EXT 家族只能对整个文件系统进行配额限制；XFS 可通过 project 模式对特定目录进行限制。
- **内核支持**：Linux 内核必须支持 Quota（CentOS 默认支持）。
- **仅对一般用户有效**：root 不受 Quota 限制。
- **SELinux 影响**：若启用 SELinux，默认可能仅允许对 `/home` 设置 Quota，其他目录需调整 SELinux 规则。

### Quota 的规范设置
- **限制对象**：用户（user）、群组（group）、特定目录（project）。
- **限制项目**：
  - **block**：磁盘容量限制（常用）。
  - **inode**：文件数量限制。
- **限制值类型**：
  - **soft（软限制）**：超过后给予警告，并启动宽限时间（grace time），用户需在宽限期内将用量降至 soft 以下，否则 soft 将作为 hard 限制。
  - **hard（硬限制）**：绝对不可超过的值，超过则禁止写入。
- **宽限时间（grace time）**：默认 7 天，可自定义。

### XFS 文件系统的 Quota 实作流程
1. **文件系统支持**：在 `/etc/fstab` 的挂载参数中添加 `usrquota`（用户）、`grpquota`（群组）、`prjquota`（项目），然后重新挂载。
2. **观察配额状态**：使用 `xfs_quota -x -c "state"` 查看配额功能是否启用。
3. **设置配额限制**：
   - 用户/群组限制：`xfs_quota -x -c "limit -u bsoft=数值 bhard=数值 用户名" 挂载点`
   - 目录（project）限制：
     - 配置 `/etc/projects` 和 `/etc/projid`，定义项目 ID 与目录的对应关系。
     - 初始化项目：`xfs_quota -x -c "project -s 项目名" 挂载点`
     - 设置限制：`xfs_quota -x -c "limit -p bsoft=数值 bhard=数值 项目名" 挂载点`
4. **设置宽限时间**：`xfs_quota -x -c "timer -ug -b 天数" 挂载点`
5. **查看报告**：`xfs_quota -x -c "report -ubih" 挂载点`
6. **配额管理**：
   - `disable`：暂时关闭配额限制（但仍在计算）。
   - `enable`：重新启用配额。
   - `off`：完全关闭配额，需重新挂载才能再次启用。
   - `remove`：移除配额设置。

### 不更动既有系统的 Quota 实例
若目标目录（如 `/var/spool/mail`）与 `/home` 不在同一文件系统，可通过以下方式整合：
- 将 `/var/spool/mail` 移动到 `/home` 下。
- 创建符号链接：`ln -s /home/mail /var/spool/mail`
- 对 `/home` 设置 Quota，即可间接限制邮件空间。

## 软件磁盘阵列（Software RAID）

### 什么是 RAID
RAID（Redundant Arrays of Inexpensive Disks）将多个磁盘组合成一个大容量设备，并提供数据冗余或性能提升。常用等级：

| 等级 | 最少磁盘数 | 最大容错 | 数据安全性 | 理论写入性能 | 理论读出性能 | 可用容量 | 应用场景 |
|------|------------|----------|------------|--------------|--------------|----------|----------|
| RAID0 | 2 | 无 | 无 | n | n | n | 性能优先，数据不重要 |
| RAID1 | 2 | n-1 | 最佳 | 1 | n | 1 | 数据备份 |
| RAID5 | 3 | 1 | 好 | < n-1 | < n-1 | n-1 | 数据与备份均衡 |
| RAID6 | 4 | 2 | 比 RAID5 好 | < n-2 | < n-2 | n-2 | 更高数据可靠性 |
| RAID10 | 4 | n/2 | 最佳 | n/2 | n | n/2 | 服务器、云系统常用 |

- **RAID0（条带）**：数据分散写入所有磁盘，性能最佳，但无冗余，任何磁盘损坏则数据全毁。
- **RAID1（镜像）**：数据同时写入两磁盘，性能写入略降，读取可并行，数据安全高。
- **RAID5**：需 3 块以上磁盘，数据和校验信息分散存储，允许一块磁盘损坏。
- **RAID6**：类似 RAID5，但有两份校验信息，允许两块磁盘损坏。
- **RAID10（RAID1+0）**：先镜像后条带，兼顾性能与安全，推荐用于高可用环境。

### 硬件 RAID 与软件 RAID
- **硬件 RAID**：通过专用 RAID 卡实现，不占用系统资源，性能好，但成本高。
- **软件 RAID**：通过操作系统软件实现，如 Linux 的 `mdadm`，占用 CPU 和 I/O 资源，但成本低，灵活性高。
- **设备文件名**：硬件 RAID 在 Linux 下显示为普通磁盘（如 `/dev/sdb`），软件 RAID 设备为 `/dev/md0`、`/dev/md1` 等。

### 软件 RAID 的设置（mdadm）
1. **准备分区**：使用 `gdisk` 或 `fdisk` 创建相同大小的分区，并将系统 ID 设为 `FD00`（Linux RAID）。
2. **创建 RAID**：
   ```bash
   mdadm --create /dev/md0 --auto=yes --level=5 --chunk=256K \
         --raid-devices=4 --spare-devices=1 /dev/sda{5,6,7,8,9}
   ```
   - `--chunk`：条带大小，影响性能。
3. **查看 RAID 状态**：
   - `mdadm --detail /dev/md0`
   - `cat /proc/mdstat`
4. **格式化与挂载**：
   - 根据条带参数优化 XFS：`mkfs.xfs -d su=256k,sw=3 -r extsize=768k /dev/md0`
   - 挂载使用。
5. **仿真 RAID 错误与恢复**：
   - 模拟磁盘故障：`mdadm --manage /dev/md0 --fail /dev/sda7`
   - 移除故障盘：`mdadm --manage /dev/md0 --remove /dev/sda7`
   - 添加新盘（需先分区并设为 FD00）：`mdadm --manage /dev/md0 --add /dev/sda7`
6. **开机自动启动 RAID**：
   - 获取 UUID：`mdadm --detail /dev/md0 | grep UUID`
   - 写入配置文件 `/etc/mdadm.conf`：`ARRAY /dev/md0 UUID=...`
   - 在 `/etc/fstab` 中添加挂载项。
7. **关闭软件 RAID**（重要：避免后续分区错误）：
   - 卸载文件系统，删除或注释掉 `/etc/fstab` 和 `/etc/mdadm.conf` 相关项。
   - 停止 RAID：`mdadm --stop /dev/md0`
   - 使用 `dd` 清除分区上的 RAID 元数据。

## 逻辑卷轴管理员（Logical Volume Manager, LVM）

### LVM 的核心概念
LVM 将多个物理分区或磁盘组合成一个逻辑卷组，再从中划分逻辑卷供文件系统使用，实现容量的弹性调整。

| 组件 | 全称 | 说明 |
|------|------|------|
| **PV** | Physical Volume（实体卷轴） | 物理分区或磁盘，需将系统 ID 改为 `8E00`（Linux LVM），并通过 `pvcreate` 初始化。 |
| **VG** | Volume Group（卷轴群组） | 由多个 PV 组合而成的大存储池，是 LVM 的管理单元。 |
| **PE** | Physical Extent（实体范围区块） | VG 的最小存储单元，默认 4MB，可在创建 VG 时通过 `-s` 指定。 |
| **LV** | Logical Volume（逻辑卷轴） | 从 VG 中划分的逻辑分区，可格式化后挂载使用。设备路径为 `/dev/卷组名/逻辑卷名`。 |

### LVM 的读写模式
- **线性模式（linear）**：数据先写满一个 PV 再写下一个，默认模式，适合弹性扩容。
- **交错模式（striped）**：类似 RAID0，数据分散写入多个 PV，提升性能，但任一 PV 损坏将导致数据丢失。

### LVM 实作流程
1. **准备 PV**：
   - 使用 `gdisk` 将分区 ID 设为 `8E00`。
   - `pvcreate /dev/sda{5,6,7,8}` 初始化 PV。
   - `pvscan`、`pvdisplay` 查看 PV 状态。
2. **创建 VG**：
   - `vgcreate -s 16M vbirdvg /dev/sda{5,6,7}`（指定 PE 大小为 16MB）。
   - `vgdisplay vbirdvg` 查看 VG 信息。
   - 可动态添加 PV：`vgextend vbirdvg /dev/sda8`
3. **创建 LV**：
   - `lvcreate -L 2G -n vbirdlv vbirdvg`（分配 2GB 给 LV）。
   - 或按 PE 数量分配：`lvcreate -l 128 -n vbirdlv vbirdvg`
   - `lvdisplay /dev/vbirdvg/vbirdlv` 查看 LV 信息。
4. **格式化与挂载**：
   - `mkfs.xfs /dev/vbirdvg/vbirdlv`
   - `mount /dev/vbirdvg/vbirdlv /srv/lvm`

### 放大 LV 容量（XFS 仅支持扩大）
1. **确保 VG 有剩余容量**：`vgdisplay vbirdvg` 查看 Free PE。
2. **扩大 LV**：`lvresize -L +500M /dev/vbirdvg/vbirdlv`
3. **扩大文件系统**：`xfs_growfs /srv/lvm`
   - `xfs_growfs` 是 XFS 的在线扩容工具，无需卸载。

### LVM thin Volume（精简卷）
- **概念**：先创建一个 thin pool（存储池），再从中创建多个“超额分配”的 LV。这些 LV 的标称容量可以远大于 thin pool 的实际容量，实际使用时按需分配空间。
- **适用场景**：需要创建大量大容量设备但实际使用率不高的环境，如虚拟机镜像、测试环境。
- **风险**：若所有 LV 实际使用总和超过 thin pool 容量，会导致数据损坏。
- **实作**：
  ```bash
  lvcreate -L 1G -T vbirdvg/vbirdtpool          # 创建 1GB thin pool
  lvcreate -V 10G -T vbirdvg/vbirdtpool -n vbirdthin1  # 创建标称 10GB 的 LV
  mkfs.xfs /dev/vbirdvg/vbirdthin1
  mount /dev/vbirdvg/vbirdthin1 /srv/thin
  ```

### LVM 快照（Snapshot）
- **原理**：快照区记录原始 LV 中被修改的数据块，未修改部分与原始 LV 共享。快照区大小应能容纳预计变更的数据量。
- **用途**：
  - 备份：挂载快照 LV 进行备份，不影响原始数据。
  - 测试：在快照 LV 上进行实验，完成后可丢弃快照，不影响原始 LV。
- **注意事项**：传统快照要求原始 LV 与快照 LV 在同一 VG 内；thin pool 也可制作快照，但限制较多。
- **实作**：
  ```bash
  lvcreate -s -l 26 -n vbirdsnap1 /dev/vbirdvg/vbirdlv  # 创建快照
  mount -o nouuid /dev/vbirdvg/vbirdsnap1 /srv/snapshot1 # 挂载快照（忽略 UUID 冲突）
  ```
- **恢复**：从快照备份数据（如使用 `xfsdump`），然后重新格式化原始 LV 并恢复数据。

### LVM 相关指令汇总

| 任务 | PV 阶段 | VG 阶段 | LV 阶段 | 文件系统阶段（XFS） |
|------|---------|---------|---------|---------------------|
| 扫描 | `pvscan` | `vgscan` | `lvscan` | `lsblk`, `blkid` |
| 创建 | `pvcreate` | `vgcreate` | `lvcreate` | `mkfs.xfs` |
| 查看 | `pvdisplay` | `vgdisplay` | `lvdisplay` | `df`, `mount` |
| 增加 | | `vgextend` | `lvextend` (`lvresize`) | `xfs_growfs` |
| 减少 | | `vgreduce` | `lvreduce` (`lvresize`) | 不支持（XFS） |
| 删除 | `pvremove` | `vgremove` | `lvremove` | `umount`, 重新格式化 |
| 改变容量 | | | `lvresize` | `xfs_growfs` |
| 改变属性 | `pvchange` | `vgchange` | `lvchange` | `/etc/fstab`, `remount` |

### 关闭 LVM（移除所有 LVM 结构）
1. 卸载所有相关文件系统。
2. 删除 LV：`lvremove /dev/vbirdvg/vbirdlv`（按依赖顺序删除）。
3. 停用 VG：`vgchange -a n vbirdvg`
4. 删除 VG：`vgremove vbirdvg`
5. 删除 PV：`pvremove /dev/sda5 /dev/sda6 /dev/sda7 /dev/sda8`
6. 用 `gdisk` 将分区 ID 改回 `8300`（Linux filesystem）。

## 重点

- **Quota**：限制用户/群组/目录的磁盘容量或文件数，支持 soft/hard/grace time 机制。XFS 支持 project 模式对目录进行限制。
- **RAID**：通过多磁盘组合提升性能或数据可靠性，常用等级包括 0、1、5、6、10。软件 RAID 使用 `mdadm` 管理。
- **LVM**：弹性调整文件系统容量，核心组件为 PV、VG、PE、LV。支持在线扩容（XFS）、thin volume（超额分配）、快照（备份与测试）。
