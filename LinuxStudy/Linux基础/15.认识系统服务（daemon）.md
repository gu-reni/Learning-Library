# 系统服务（daemon）与 systemd 管理

## 1. 什么是 daemon 与服务

- **服务（service）**：系统或网络功能的提供者，通常由常驻内存的程序实现。
- **daemon**：执行服务的程序，通常以 `d` 结尾（如 `crond`、`sshd`）。
- **早期 System V init 管理**：
  - 服务脚本位于 `/etc/init.d/`
  - 启动/关闭命令：`/etc/init.d/daemon start|stop|restart|status`
  - 开机启动管理：`chkconfig daemon on|off`
  - 运行级别（runlevel）：0~6，通过 `/etc/rc.d/rc?.d/` 链接控制。
- **systemd 优势**：
  - 并行启动，加速开机。
  - 按需启动（on-demand），减少资源占用。
  - 自动处理服务依赖。
  - 统一管理工具 `systemctl`。
  - 将服务定义为 **unit**，分为多种类型（service、socket、target、timer 等）。

## 2. systemctl 管理服务

### 2.1 基本命令

| 操作 | 命令 |
|------|------|
| 立即启动 | `systemctl start unit.service` |
| 立即停止 | `systemctl stop unit.service` |
| 重启 | `systemctl restart unit.service` |
| 重新加载配置 | `systemctl reload unit.service` |
| 查看状态 | `systemctl status unit.service` |
| 开机启动 | `systemctl enable unit.service` |
| 取消开机启动 | `systemctl disable unit.service` |
| 查看是否激活 | `systemctl is-active unit.service` |
| 查看是否开机启动 | `systemctl is-enabled unit.service` |
| 屏蔽服务（禁止启动） | `systemctl mask unit.service` |
| 取消屏蔽 | `systemctl unmask unit.service` |

### 2.2 服务状态

- `active (running)`：正在运行。
- `active (exited)`：执行一次即结束，不常驻。
- `active (waiting)`：运行中但等待事件。
- `inactive`：未运行。
- `enabled`：开机启动。
- `disabled`：开机不启动。
- `static`：不能独立启动，可能被其他服务依赖。
- `mask`：被屏蔽，无法启动。

### 2.3 查看所有服务

- 查看已启动的 unit：`systemctl list-units --type=service`
- 查看所有安装的 unit（包括未启动）：`systemctl list-unit-files --type=service`

### 2.4 操作 target（运行环境）

- **常用 target**：
  - `graphical.target`：图形界面模式。
  - `multi-user.target`：纯文本模式。
  - `rescue.target`：救援模式。
  - `emergency.target`：紧急模式。
  - `reboot.target`：重启。
  - `poweroff.target`：关机。
- **查看当前 target**：`systemctl get-default`
- **设置默认 target**：`systemctl set-default multi-user.target`
- **切换 target**：`systemctl isolate graphical.target`
- **关机/重启/休眠**：`systemctl poweroff`、`systemctl reboot`、`systemctl suspend`、`systemctl hibernate`

### 2.5 服务依赖分析

- 查看 unit 依赖：`systemctl list-dependencies [unit] [--reverse]`

## 3. systemd 配置文件

### 3.1 配置文件目录

- `/usr/lib/systemd/system/`：软件包默认配置（不建议修改）。
- `/run/systemd/system/`：运行时动态配置。
- `/etc/systemd/system/`：管理员自定义配置（优先级最高）。
- 可创建 `.d` 目录或 `.wants/`、`.requires/` 目录添加额外配置或链接。

### 3.2 配置文件结构

以 `sshd.service` 为例：

```ini
[Unit]
Description=OpenSSH server daemon
After=network.target sshd-keygen.service
Wants=sshd-keygen.service

[Service]
EnvironmentFile=/etc/sysconfig/sshd
ExecStart=/usr/sbin/sshd -D $OPTIONS
ExecReload=/bin/kill -HUP $MAINPID
KillMode=process
Restart=on-failure
RestartSec=42s

[Install]
WantedBy=multi-user.target
```

**说明**：

- **[Unit]**：
  - `Description`：描述信息。
  - `After`、`Before`：启动顺序（非强制）。
  - `Requires`：强依赖，不满足则服务无法启动。
  - `Wants`：弱依赖，建议启动但不强制。
  - `Conflicts`：冲突服务。
- **[Service]**（适用于 `.service` 类型）：
  - `Type`：启动类型（`simple`、`forking`、`oneshot`、`dbus`、`idle`）。
  - `EnvironmentFile`：环境变量文件。
  - `ExecStart`、`ExecStop`、`ExecReload`：对应操作的命令。
  - `Restart`：自动重启策略。
  - `KillMode`：终止方式（`process`、`control-group`、`none`）。
- **[Install]**：
  - `WantedBy`：挂载到哪个 target。
  - `Also`：同时启用的其他 unit。
  - `Alias`：别名。

### 3.3 自定义服务实例

**例：创建 backup.service**

```bash
# /etc/systemd/system/backup.service
[Unit]
Description=backup my server
Requires=atd.service

[Service]
Type=simple
ExecStart=/bin/bash -c "echo /backups/backup.sh | at now"

[Install]
WantedBy=multi-user.target
```

创建后需执行 `systemctl daemon-reload` 重新加载配置。

### 3.4 多实例服务（使用 `@`）

- 模板文件：`[email protected]`。
- 启动实例：`systemctl start [email protected]`，其中 `tty1` 会替换配置文件中的 `%i` 或 `%I`。
- 常用于 getty、vsftpd 等需要多个实例的服务。

## 4. systemd timer（定时任务）

### 4.1 优势
- 与 systemd 集成，日志完善。
- 支持秒级精度。
- 可与 cgroup 结合限制资源。

### 4.2 必要条件
- `timer.target` 必须启动。
- 有一个对应的 `.service` 文件（例如 `backup.service`）。
- 有一个 `.timer` 文件定义时间规则。

### 4.3 常用配置选项（[Timer] 部分）

| 选项 | 说明 |
|------|------|
| `OnActiveSec` | 相对于 timer 激活的时间 |
| `OnBootSec` | 相对于开机的时间 |
| `OnUnitActiveSec` | 相对于上次服务激活的时间 |
| `OnUnitInactiveSec` | 相对于上次服务停止的时间 |
| `OnCalendar` | 基于日历时间（如 `daily`、`weekly`、`*-*-* 02:00:00`） |
| `Persistent` | 若启用，错过的时间点也会执行（类似 anacron） |
| `Unit` | 指定要启动的服务（默认与 timer 同名） |

### 4.4 时间格式示例
- `2h`、`300m`、`5min 10s`
- `daily`、`weekly`、`monthly`
- `Sun 02:00:00`、`*-*-* 00:00:00`

### 4.5 实例：每2天执行 backup

```ini
# /etc/systemd/system/backup.timer
[Unit]
Description=backup timer

[Timer]
OnBootSec=2h
OnUnitActiveSec=2d

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable backup.timer
systemctl start backup.timer
```

### 4.6 实例：每周日凌晨2点执行

```ini
# /etc/systemd/system/backup2.timer
[Unit]
Description=backup timer2

[Timer]
OnCalendar=Sun *-*-* 02:00:00
Persistent=true
Unit=backup.service

[Install]
WantedBy=multi-user.target
```

## 5. CentOS 7 默认启动服务说明

**系统必需服务**（建议保留）：
- `systemd-*`：系统核心服务。
- `auditd`：SELinux 审计。
- `rsyslog`：日志记录。
- `crond`：计划任务。
- `atd`：一次性任务。
- `sshd`：远程登录。
- `postfix`：本地邮件传输。
- `lvm2-*`：LVM 管理。
- `irqbalance`：多核中断平衡。
- `smartd`：硬盘健康监测。
- `sysstat`：系统性能数据收集。

**可关闭的服务**（服务器环境）：
- `abrtd`：应用程序崩溃报告（桌面用）。
- `accounts-daemon`：用户账户信息（桌面用）。
- `alsa-*`：音效（服务器用不到）。
- `avahi-daemon`：零配置网络（常用于笔记本）。
- `cups`：打印服务。
- `gdm`：图形登录管理器。
- `hyper*`、`libvirt*`：虚拟化相关（若不使用可关）。
- `kdump`：内核崩溃转储（除非调试内核）。
- `ModemManager`：调制解调器管理。
- `NetworkManager`：若用固定网络，可改用 `network` 服务（但建议保留 NetworkManager）。
- `plymouth`：开机动画（服务器可关）。
- `upower`：电源管理（服务器可关）。

**网络服务**（按需启用）：
- `httpd`（Web）、`vsftpd`（FTP）、`named`（DNS）、`dovecot`（邮件收取）、`smb`（Samba）等。

## 6. 重点
- systemd 是 CentOS 7 的服务管理器，使用 `systemctl` 统一管理。
- 服务分为多种 unit 类型，最常见的是 `.service` 和 `.target`。
- 服务状态分为启动状态（`active/inactive`）和开机启用状态（`enabled/disabled`）。
- 可通过 `systemctl enable/disable` 控制开机启动。
- 自定义服务需在 `/etc/systemd/system/` 创建配置文件，编写 [Unit]、[Service]、[Install] 段落。
- 使用 `@` 模板可实现多实例服务。
- systemd timer 可替代 crond，支持精确时间和复杂调度。
- 根据服务器角色关闭不必要的服务可提升安全性和性能。
