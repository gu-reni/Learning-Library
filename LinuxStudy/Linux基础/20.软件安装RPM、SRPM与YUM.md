# 软件管理：RPM、SRPM 与 YUM

## 1. 软件管理概述

### 1.1 Linux 两大主流软件管理机制
| 机制 | 发行版代表 | 指令 | 线上升级 |
|------|------------|------|----------|
| **RPM** | Red Hat, Fedora, CentOS, SuSE | `rpm`, `rpmbuild` | YUM (`yum`) |
| **DPKG** | Debian, Ubuntu | `dpkg` | APT (`apt-get`) |

### 1.2 RPM 与 SRPM 的区别
- **RPM**（RedHat Package Manager）：已编译的二进制文件，可直接安装；文件名如 `xxx.rpm`；不可修改编译参数。
- **SRPM**（Source RPM）：包含源代码和编译配置（spec文件），需重新编译生成 RPM；文件名如 `xxx.src.rpm`；可修改编译参数。

### 1.3 RPM 文件名中的硬件平台标识
- `i386`：适用于所有 x86 平台（32位）
- `i586`：针对 Pentium 级别 CPU
- `i686`：针对 Pentium II 以上 CPU（含 K7）
- `x86_64`：针对 64 位 CPU（AMD64 / Intel Core 2 以上）
- `noarch`：无硬件限制（如脚本、文档）

## 2. RPM 命令详解

### 2.1 安装（install）
```bash
rpm -ivh package.rpm          # 安装并显示进度
rpm -ivh --test package.rpm   # 测试安装，检查依赖
rpm -ivh --nodeps package.rpm # 忽略依赖强制安装（危险）
rpm -ivh --replacepkgs package.rpm  # 重新安装
```

### 2.2 升级（upgrade / freshen）
- `-Uvh`：若未安装则安装，已安装则升级。
- `-Fvh`：仅升级已安装的软件，不安装新软件。

### 2.3 查询（query）
```bash
rpm -qa                # 列出所有已安装软件
rpm -q 软件名           # 查询指定软件是否安装
rpm -qi 软件名          # 显示软件详细信息
rpm -ql 软件名          # 列出软件所有文件
rpm -qc 软件名          # 列出配置文件
rpm -qd 软件名          # 列出文档文件
rpm -qR 软件名          # 列出依赖关系
rpm -qf /path/to/file   # 查询文件属于哪个已安装软件
rpm -qp[ilcdR] package.rpm  # 查询未安装的RPM文件信息
```

### 2.4 验证（verify）
```bash
rpm -V 软件名           # 验证已安装软件的文件是否被修改
rpm -Va                 # 验证所有已安装软件
rpm -Vp package.rpm     # 验证RPM文件
```
验证输出中各字母含义：
- `S`：文件大小改变
- `M`：权限/类型改变
- `5`：MD5 校验和改变
- `D`：设备主/次号码改变
- `L`：符号链接路径改变
- `U`：属主改变
- `G`：属组改变
- `T`：修改时间改变
- `P`：功能（capability）改变

文件类型标识：
- `c`：配置文件
- `d`：文档文件
- `g`：鬼文件（ghost）
- `l`：授权文件
- `r`：README

### 2.5 数码签章（digital signature）
```bash
rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-CentOS-7  # 导入公钥
rpm -qa | grep pubkey        # 查看已导入的GPG密钥
```

### 2.6 移除（erase）与数据库重建
```bash
rpm -e 软件名               # 卸载软件（需注意依赖）
rpm --rebuilddb             # 重建RPM数据库（/var/lib/rpm）
```

## 3. YUM 线上升级机制

YUM（Yellowdog Updater Modified）自动解决依赖，从软件仓库（repository）下载并安装/升级软件。

### 3.1 配置文件
主配置文件：`/etc/yum.conf`
仓库配置文件：`/etc/yum.repos.d/*.repo`

典型仓库配置（`/etc/yum.repos.d/CentOS-Base.repo`）：
```ini
[base]
name=CentOS-$releasever - Base
baseurl=http://mirror.centos.org/centos/$releasever/os/$basearch/
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-CentOS-7
```
- `[仓库ID]`：唯一标识
- `name`：描述
- `baseurl`：仓库URL（支持 `file://`、`http://`、`ftp://`）
- `mirrorlist`：镜像列表（可替代 baseurl）
- `enabled=1`：启用（默认）
- `gpgcheck=1`：启用GPG验证
- `gpgkey`：公钥文件路径

### 3.2 常用 YUM 命令
| 命令 | 作用 |
|------|------|
| `yum search 关键字` | 搜索软件 |
| `yum list` | 列出所有可用软件 |
| `yum list installed` | 列出已安装软件 |
| `yum list updates` | 列出可升级软件 |
| `yum info 软件名` | 查看软件信息 |
| `yum provides 文件` | 查找文件所属软件（类似 rpm -qf） |
| `yum install 软件名` | 安装（可带 `-y` 自动确认） |
| `yum update 软件名` | 升级指定软件 |
| `yum update` | 升级所有软件 |
| `yum remove 软件名` | 卸载（会检查依赖） |
| `yum clean all` | 清除缓存（/var/cache/yum） |
| `yum repolist all` | 列出所有仓库状态 |
| `yum grouplist` | 列出软件群组 |
| `yum groupinfo "群组名"` | 查看群组包含的软件 |
| `yum groupinstall "群组名"` | 安装整个群组 |
| `yum groupremove "群组名"` | 移除群组 |

### 3.3 启用/禁用仓库
- `--enablerepo=仓库ID`：临时启用指定仓库
- `--disablerepo=仓库ID`：临时禁用指定仓库

### 3.4 第三方仓库示例（EPEL、ELRepo）
**EPEL**（Extra Packages for Enterprise Linux）：
```bash
# 安装 epel-release 即可自动配置
yum install epel-release
# 或手动创建 repo 文件
vim /etc/yum.repos.d/epel.repo
[epel]
name=epel packages
baseurl=https://dl.fedoraproject.org/pub/epel/7/x86_64/
enabled=0
gpgcheck=0
# 使用时临时启用
yum --enablerepo=epel install netcdf R
```

**ELRepo**（主要用于内核/硬件驱动）：
类似配置，URL 为 `http://elrepo.org/linux/elrepo/el7/x86_64/`

### 3.5 全系统自动升级
利用 cron 定时任务：
```bash
echo '10 1 * * * root /usr/bin/yum -y update' > /etc/cron.d/yumupdate
```

### 3.6 使用本地光盘作为仓库
```bash
mount /dev/sr0 /mnt
vim /etc/yum.repos.d/cdrom.repo
[cdrom]
name=cdrom
baseurl=file:///mnt
enabled=0
gpgcheck=0
# 使用时临时启用
yum --enablerepo=cdrom install 软件名
```

## 4. SRPM 与 rpmbuild

### 4.1 SRPM 使用场景
- 需要修改编译参数（如 `./configure` 选项）
- 为当前硬件优化（如指定 `-march`）
- 移植软件到不同发行版
- 学习软件编译过程

### 4.2 安装 SRPM
```bash
rpm -ivh package.src.rpm
```
默认解包到 `~/rpmbuild/` 目录下：
- `SOURCES/`：存放源代码（.tar.gz）和补丁文件（.patch）
- `SPECS/`：存放 spec 配置文件（如 `package.spec`）
- `BUILD/`：编译临时目录
- `RPMS/`：生成的 RPM 存放目录
- `SRPMS/`：生成的 SRPM 存放目录

### 4.3 编译 SRPM
```bash
cd ~/rpmbuild/SPECS
rpmbuild -ba package.spec   # 编译并生成 RPM 和 SRPM
rpmbuild -bb package.spec   # 仅生成 RPM
```

### 4.4 spec 文件主要段落
- **基本信息**：`Name`, `Version`, `Release`, `Summary`, `License`, `Group`, `URL`, `SourceN`, `PatchN`
- **依赖**：`Requires`（安装时需），`BuildRequires`（编译时需）
- **%description**：详细描述
- **%prep**：准备阶段（解压源码、应用补丁）
- **%build**：编译阶段（`./configure`, `make`）
- **%install**：安装阶段（`make install` 或手动复制）
- **%files**：列出最终包含的文件
- **%changelog**：更新日志

### 4.5 简单打包示例（main 程序）
```bash
# 准备源码
cp main-0.1.tgz main_0.1_to_0.2.patch ~/rpmbuild/SOURCES/
# 编写 spec
vim ~/rpmbuild/SPECS/main.spec
```
```spec
Name: main
Version: 0.1
Release: 1%{?dist}
Summary: Shows sin and cos value.
Group: Scientific Support
License: GPLv2
Source0: main-0.1.tgz
Patch0: main_0.1_to_0.2.patch
%description
This package will let you input your name and calculate sin cos value.
%prep
%setup -q
%patch0 -p1
%build
make clean main
%install
mkdir -p %{buildroot}/usr/local/bin
install -m 755 main %{buildroot}/usr/local/bin
%files
/usr/local/bin/main
```
```bash
rpmbuild -ba main.spec
# 生成的 RPM 在 ~/rpmbuild/RPMS/x86_64/
```

## 5. 软件管理选择建议

| 场景 | 推荐方式 |
|------|----------|
| 系统基础软件、常见服务 | 优先使用官方 RPM（通过 yum） |
| 第三方流行软件 | 查找官方提供的 RPM 仓库（如 EPEL） |
| 需要最新版本但官方未提供 | 使用第三方仓库（如 ELRepo）或编译 SRPM |
| 单机特殊软件、测试新版本 | Tarball 手动安装至 /usr/local |
| 需要在多台相同环境批量安装 | 自制 RPM（通过 SRPM）便于分发 |

---

## 6. 重点

- RPM 是 Red Hat 系列 Linux 的标准软件包格式，包含已编译的二进制文件；SRPM 包含源代码。
- RPM 软件包文件名标识硬件平台（i386, i686, x86_64, noarch）。
- `rpm` 命令用于本地安装、查询、验证、卸载等操作，但无法自动处理依赖。
- YUM 基于仓库，自动解决依赖，通过 `yum` 命令进行安装、升级、搜索、群组管理。
- 可配置本地光盘或第三方仓库（如 EPEL、ELRepo）扩展软件源。
- SRPM 的编译需安装 `rpmbuild` 和开发工具组（`Development Tools`），通过编写 spec 文件控制编译过程。
- 使用 `rpmbuild -ba` 从 spec 生成 RPM 和 SRPM。
- 自制 RPM 可简化在多台相同系统上的软件分发。
