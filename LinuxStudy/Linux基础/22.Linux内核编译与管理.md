# 核心编译管理

## 1. 核心概念与编译目的

- **核心（Kernel）**：操作系统的底层文件（通常为 `/boot/vmlinuz-xxx`），负责硬件驱动、系统功能（如防火墙、文件系统支持）的提供。核心启动后挂载根目录，并通过核心模块（`/lib/modules/$(uname -r)/kernel/`）动态加载所需驱动。
- **核心模块**：独立于核心的驱动程序文件，可动态加载或卸载，方便硬件支持扩展。
- **编译核心的原因**：
  - 需要新功能（如新硬件驱动、新版核心特性）
  - 核心过于臃肿（精简以提升稳定性）
  - 与硬件配合优化（如特定CPU调优）
  - 特殊需求（嵌入式系统、实验性功能）

> 一般用户无需编译核心，使用发行版默认核心即可。仅在上述特殊需求下考虑编译。
---

## 2. 核心源代码获取

| 来源 | 说明 | 示例 |
|------|------|------|
| 发行版 SRPM | 使用发行版提供的源代码，包含默认配置，易于修改 | `http://vault.centos.org/` 下载 kernel 的 SRPM |
| 官方内核官网 | 获取最新稳定版源代码 | `https://www.kernel.org/` 或镜像站（如 `ftp://ftp.twaren.net/pub/Unix/Kernel/`） |
| Patch 文件 | 从旧版本升级到新版本，需依次应用补丁 | `patch-3.10.86`, `patch-3.10.87`... |

- **解压源代码**：通常放置于 `/usr/src/kernels/`
  ```bash
  tar -Jxvf linux-3.10.89.tar.xz -C /usr/src/kernels/
  ```

- **源代码目录结构**：包含 `arch/`、`block/`、`drivers/`、`fs/`、`net/` 等子目录，以及 `Documentation/` 说明文档。

---

## 3. 核心编译前准备

- **清理源代码**：
  - `make mrproper`：彻底清理（包括配置文件 `.config`），仅首次编译前使用。
  - `make clean`：仅删除编译产生的目标文件，保留配置文件。
- **获取当前核心配置**（可选）：
  ```bash
  cp /boot/config-$(uname -r) /usr/src/kernels/linux-xxx/.config
  ```

---

## 4. 核心功能选择

- **配置工具**：
  - `make menuconfig`：文本菜单（推荐，无需X）
  - `make oldconfig`：基于现有 `.config` 升级新版本选项
  - `make xconfig` / `make gconfig`：图形界面（需X支持）

- **关键配置区域**（以 `make menuconfig` 为例）：
  - **General setup**：核心版本标识（可追加自定义字符串如 `-vbird`）、initramfs 支持等。
  - **Loadable module support**：启用模块支持，建议全部启用。
  - **Processor type and features**：选择 CPU 类型、SMP 支持、抢占模型（服务器选 No Forced Preemption）、时钟频率（服务器 300Hz，桌面 1000Hz）。
  - **Power management**：启用省电功能（如 CPU 频率调节，选 `ondemand`）。
  - **Bus options**：PCI/PCI-E 支持，虚拟化相关如 PCI Stub。
  - **Networking support**：网络协议栈、Netfilter 防火墙（编译为模块）。
  - **Device Drivers**：硬件驱动（显卡、网卡、SATA、USB 等），建议将未知项编为模块。
  - **File systems**：支持 ext4、xfs、NTFS（可读写）、网络文件系统（NFS、CIFS）、Quota 等。
  - **Virtualization**：KVM 支持（若需虚拟化）。
  - **Security options**：SELinux 支持（应启用）。
  - **Cryptographic API**：加密算法支持（默认即可）。

配置完成后保存为 `.config`。

## 5. 核心与模块的编译及安装

### 5.1 编译
```bash
make -j N clean          # N 为 CPU 核心数，可选
make -j N bzImage        # 编译压缩内核
make -j N modules        # 编译模块
```

- 编译后的内核文件：`arch/x86/boot/bzImage`

### 5.2 安装模块
```bash
make modules_install
```
模块将被安装到 `/lib/modules/$(uname -r)/`。

### 5.3 安装内核及相关文件
```bash
cp arch/x86/boot/bzImage /boot/vmlinuz-新版本
cp .config /boot/config-新版本
cp System.map /boot/System.map-新版本
gzip -c Module.symvers > /boot/symvers-新版本.gz
```

### 5.4 创建 initramfs
```bash
dracut -v /boot/initramfs-新版本.img 新版本
```

### 5.5 更新 grub 菜单
```bash
grub2-mkconfig -o /boot/grub2/grub.cfg
```

重启选择新内核测试。

## 6. 单一核心模块编译

### 6.1 场景
- 核心已编译，但漏编某个模块（如 NTFS）。
- 硬件厂商提供驱动模块。

### 6.2 编译单个模块
```bash
make modules SUBDIRS=path/to/module   # 或直接 make path/to/module/
```
例如编译 ntfs 模块：
```bash
make fs/ntfs/
```

### 6.3 安装模块
```bash
cp module.ko /lib/modules/$(uname -r)/kernel/drivers/.../
depmod -a
```

若需开机加载，可加入 initramfs：
```bash
dracut --force --add-drivers 模块名 /boot/initramfs-版本.img 版本
```

## 7. 利用 SRPM 编译最新核心（以 ELRepo 为例）

1. 下载 ELRepo 的 SRPM（`.nosrc.rpm`）并安装：
   ```bash
   rpm -ivh kernel-ml-版本.elrepo.nosrc.rpm
   ```
2. 从 kernel.org 下载对应版本源代码，放入 `~/rpmbuild/SOURCES/`。
3. 修改配置文件（如开启 `CONFIG_VFIO_PCI_VGA=y`）和 spec 文件中的 Source 路径。
4. 编译打包：
   ```bash
   rpmbuild -bb kernel-ml-版本.spec
   ```
5. 安装生成的 RPM：
   ```bash
   yum install ~/rpmbuild/RPMS/x86_64/kernel-ml-*.rpm
   ```

---

## 8. 重点

- 核心是硬件与软件间的桥梁，核心模块机制简化了驱动管理。
- 编译核心的主要步骤：获取源代码 → 配置（`make menuconfig`） → 编译（`bzImage` 和 `modules`） → 安装模块及内核 → 创建 initramfs → 更新 grub。
- 配置时建议将不明确的功能编译为模块，核心尽量精简。
- 可单独编译模块，用于补充漏编功能或添加厂商驱动。
- 利用 SRPM 可方便地打包自定义内核，便于分发。
- 新内核测试稳定后，可设为默认启动项（修改 `/etc/default/grub` 中的 `GRUB_DEFAULT` 并重新生成 grub.cfg）。
