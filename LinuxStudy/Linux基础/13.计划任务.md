# 例行性工作调度

## 1. 工作调度概述

Linux 系统提供两种工作调度方式：
- **突发性（一次）**：使用 `at` 命令，仅执行一次。
- **例行性（循环）**：使用 `crontab` 命令，按固定周期循环执行。

系统本身也有许多例行性任务，如日志轮替、logwatch 分析、locate 数据库更新、man page 数据库更新、RPM 数据库维护、临时文件清理等。

## 2. 单一工作调度 `at`

### 2.1 `atd` 服务
- 使用 `at` 前需确保 `atd` 服务运行：
  ```bash
  systemctl restart atd
  systemctl enable atd
  systemctl status atd
  ```

### 2.2 使用限制
- 通过 `/etc/at.allow` 和 `/etc/at.deny` 控制用户权限。
- 若两个文件均不存在，仅 root 可用。
- 多数发行版默认保留一个空的 `/etc/at.deny`，允许所有用户使用。

### 2.3 `at` 命令语法
```bash
at [-mldv] TIME
at -c 作业号
```
- `-m`：任务完成后即使无输出也发邮件通知。
- `-l`：相当于 `atq`，列出当前用户的任务。
- `-d`：相当于 `atrm`，删除指定任务。
- `-c`：查看指定任务的具体内容。
- `TIME` 格式：
  - `HH:MM`：今日的 HH:MM，若已过则明天。
  - `HH:MM YYYY-MM-DD`：指定日期时间。
  - `HH:MM[am|pm] [Month] [Date]`：如 `04pm July 30`。
  - `now + number [minutes|hours|days|weeks]`：相对时间，如 `now + 5 minutes`。

### 2.4 任务管理
- 列出任务：`atq`
- 删除任务：`atrm 作业号`

### 2.5 注意事项
- 任务执行时的工作目录为执行 `at` 时的目录。
- 任务的标准输出/错误会以邮件发送给用户（若无输出且未加 `-m` 则不发送）。
- 可将输出重定向到终端设备（如 `/dev/tty1`）在屏幕上显示。

### 2.6 `batch` 命令
- 与 `at` 类似，但只在系统负载低于 0.8 时才执行。
- 用法：`batch` 后输入要执行的命令，按 `Ctrl+D` 结束。
- 通过 `atq` / `atrm` 管理。

## 3. 循环工作调度 `crontab`

#### 3.1 使用限制
- 通过 `/etc/cron.allow` 和 `/etc/cron.deny` 控制用户权限。
- 若两个文件均不存在，仅 root 可用。
- 系统默认保留一个空的 `/etc/cron.deny`，允许所有用户使用。

### 3.2 `crontab` 命令
```bash
crontab [-u username] [-l|-e|-r]
```
- `-u`：root 可指定编辑其他用户的 crontab。
- `-e`：编辑 crontab 内容。
- `-l`：列出当前 crontab 内容。
- `-r`：删除所有 crontab 内容（谨慎使用）。

### 3.3 时间字段格式
每行定义一个任务，格式为：
```
分 时 日 月 周 命令
```
- 取值范围：
  - 分：0-59
  - 时：0-23
  - 日：1-31
  - 月：1-12
  - 周：0-7（0 和 7 都表示星期日）
- 特殊符号：
  - `*`：任意值
  - `,`：列举多个值（如 `3,6` 表示第3和第6）
  - `-`：范围（如 `8-12` 表示8到12）
  - `/n`：步长（如 `*/5` 表示每5分钟）

### 3.4 示例
- 每天 12:00 发信：`0 12 * * * mail -s "at 12:00" user < /home/user/.bashrc`
- 每年 5月1日 23:59 发信：`59 23 1 5 * mail friend < /home/user/lover.txt`
- 每5分钟执行脚本：`*/5 * * * * /home/user/test.sh`
- 每周五 16:30 提醒：`30 16 * * 5 mail friend < /home/user/friend.txt`

### 3.5 注意事项
- 命令建议使用绝对路径。
- 任务的输出会以邮件发送给用户，可重定向到 `/dev/null` 忽略。
- 周与日不可同时指定具体值（避免歧义）。

## 4. 系统级 crontab 配置

### 4.1 `/etc/crontab` 文件
与用户 crontab 区别：
- 多一个“执行者”字段，格式为：
  ```
  分 时 日 月 周 执行者 命令
  ```
- 示例：
  ```
  01 * * * * root run-parts /etc/cron.hourly
  ```
- `run-parts` 会执行指定目录下的所有可执行文件。

### 4.2 `/etc/cron.d/` 目录
- 存放独立的 cron 配置文件，格式与 `/etc/crontab` 相同。
- 适合软件包放置自己的定时任务。

### 4.3 其他目录
- `/etc/cron.hourly/`：每小时执行一次（由 `/etc/cron.d/0hourly` 调用 `run-parts` 执行）。
- `/etc/cron.daily/`、`/etc/cron.weekly/`、`/etc/cron.monthly/`：每日、每周、每月执行一次（由 `anacron` 调用）。

## 5. 可唤醒停机期间的任务：anacron

### 5.1 作用
- 用于处理因系统关机而未按时执行的 crontab 任务。
- 检测时间戳文件，若超过指定天数未执行，则补执行。

### 5.2 工作机制
- anacron 是一个命令，由 crond 每小时执行（通过 `/etc/cron.hourly/0anacron`）。
- 读取配置文件 `/etc/anacrontab`，检查各任务的时间戳（存放在 `/var/spool/anacron/`）。

### 5.3 `/etc/anacrontab` 格式
```
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=45          # 随机最大延迟分钟
START_HOURS_RANGE=3-22   # 可执行的时间范围

天数 延迟分钟 工作名称 命令
1     5    cron.daily    run-parts /etc/cron.daily
7    25    cron.weekly   run-parts /etc/cron.weekly
@monthly 45 cron.monthly run-parts /etc/cron.monthly
```
- 天数：与上次执行相差超过此天数则执行。
- 延迟分钟：实际执行前延迟的时间（可加上随机延迟）。
- 工作名称：日志中标识。
- 命令：要执行的指令（通常也是 `run-parts` 调用目录）。

### 5.4 与 crond 的关系
- crond 负责按时执行任务，anacron 负责补执行过期任务。
- 两者并行，互不冲突。

## 6. 注意事项与最佳实践

- **资源分配**：避免大量任务同时执行，可错开时间。
- **输出管理**：将不需要的输出重定向到 `/dev/null`。
- **安全检验**：定期检查 `/var/log/cron`，确保没有异常任务。
- **任务放置**：
  - 个人任务：用 `crontab -e`
  - 系统维护任务：编辑 `/etc/crontab`
  - 软件自带任务：放入 `/etc/cron.d/`
  - 固定周期任务（每日/周/月）：放入对应目录（`/etc/cron.*/`）
- **周与日冲突**：避免同时指定具体的“日”和“周”。

## 7. 重点

- `at` 用于一次性任务，`crontab` 用于周期性任务。
- `at` 需 `atd` 服务，`crontab` 需 `crond` 服务。
- 控制文件：`/etc/at.allow`、`/etc/at.deny`、`/etc/cron.allow`、`/etc/cron.deny`。
- `crontab` 时间格式：分 时 日 月 周 命令（用户级）或 分 时 日 月 周 执行者 命令（系统级）。
- `anacron` 用于补执行因停机错过的任务，通过 `/etc/anacrontab` 配置，每小时由 crond 触发。
- 日志文件：`/var/log/cron` 可查看 cron 执行情况。
