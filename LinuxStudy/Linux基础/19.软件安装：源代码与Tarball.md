# 软件安装：源代码与 Tarball

## 1. 核心概念

### 1.1 开放源码、编译器与可执行文件
- **源代码**：程序员编写的纯文本文件（如 C 语言的 `.c` 文件），人类可读但机器无法直接执行。
- **编译器**：将源代码翻译成机器可执行的二进制文件的工具，Linux 下最常用的是 `gcc`（GNU C Compiler）。
- **可执行文件**：经过编译生成的二进制程序，Linux 系统通过文件属性中的 `x` 权限来识别和执行（如 `/bin/bash`）。
- **编译流程**：源代码（`.c`） → 编译 → 目标文件（`.o`） → 链接 → 可执行文件。

### 1.2 函数库
- **作用**：类似“副程序”，提供可以被其他程序调用的功能模块（如数学计算、身份认证）。
- **静态函数库（`.a`）**：编译时直接整合到可执行文件中，程序可独立运行，但升级库文件需重新编译所有依赖程序。
- **动态函数库（`.so`）**：编译时仅在可执行文件中记录“指向”位置，运行时才读取库文件。升级库文件通常无需重新编译程序，是目前主流（文件小、管理方便）。
- **存放位置**：`/lib`、`/lib64`；内核模块在 `/lib/modules/`。

### 1.3 make 与 configure
- **make**：根据 `Makefile` 文件中的规则，自动化编译过程，仅重新编译有变动的文件，大幅简化编译命令。
- **configure**：软件开发商提供的侦测脚本，用于检查系统环境（编译器、函数库、核心版本等），并根据结果生成适合当前系统的 `Makefile` 文件。
- **典型流程**：`configure` → 生成 `Makefile` → `make` → `make install`

### 1.4 Tarball
- **定义**：将源代码用 `tar` 打包并用 `gzip`/`bzip2`/`xz` 压缩后的文件，扩展名通常为 `.tar.gz`、`.tar.bz2`、`.tar.xz`。
- **内容**：解压后通常包含源代码文件、`configure` 或 `config` 脚本、以及 `INSTALL` 或 `README` 等说明文档。

## 2. 使用 gcc 编译示例

### 2.1 单一程序编译
```bash
# 编写 hello.c
gcc hello.c          # 编译生成默认的可执行文件 a.out
./a.out

gcc -c hello.c       # 仅编译生成目标文件 hello.o（不链接）
gcc -o hello hello.o # 链接生成可执行文件 hello
./hello
```

### 2.2 主、副程序编译
```bash
gcc -c thanks.c thanks_2.c        # 分别编译两个源文件，生成 thanks.o 和 thanks_2.o
gcc -o thanks thanks.o thanks_2.o # 链接生成最终可执行文件
```

### 2.3 调用外部函数库（以数学库为例）
```c
// sin.c
#include <stdio.h>
#include <math.h>
int main(void) {
    float value = sin(3.14 / 2);
    printf("%f\n", value);
}
```
```bash
gcc sin.c -lm        # -lm 表示链接数学库 libm.so
./a.out
```
- `-l`：加入某个函数库（如 `-lm` 表示 `libm.so`）。
- `-L`：指定函数库搜索路径（如 `-L/lib`）。
- `-I`：指定头文件（include）搜索路径（如 `-I/usr/include`）。

### 2.4 gcc 常用参数
| 参数 | 作用 |
|------|------|
| `-c` | 仅编译生成目标文件（`.o`），不链接 |
| `-o` | 指定输出文件名 |
| `-O` | 进行编译优化 |
| `-Wall` | 输出更详细的编译警告信息 |
| `-lm` | 链接数学库 |
| `-L` | 添加函数库搜索路径 |
| `-I` | 添加头文件搜索路径 |

## 3. 使用 make 进行自动化编译

### 3.1 makefile 基本语法
```makefile
# 目标(target): 依赖文件
main: main.o haha.o sin_value.o cos_value.o
<tab> gcc -o main main.o haha.o sin_value.o cos_value.o -lm

# 清理目标
clean:
<tab> rm -f main *.o
```
- `#` 表示注释。
- 命令行必须以 **Tab** 开头。
- 目标与依赖之间用 `:` 分隔。

### 3.2 makefile 中的变量
```makefile
LIBS = -lm
OBJS = main.o haha.o sin_value.o cos_value.o
CFLAGS = -Wall

main: ${OBJS}
<tab> gcc -o $@ ${OBJS} ${LIBS}

clean:
<tab> rm -f main ${OBJS}
```
- `$@` 代表当前目标（target）名称。
- 变量使用 `${变量}` 或 `$(变量)` 形式。
- 环境变量优先级：命令行 > makefile > shell。

### 3.3 执行 make
```bash
make        # 默认执行第一个目标（main）
make clean  # 执行清理目标
make clean main  # 先清理再编译
```

## 4. Tarball 软件安装与管理

### 4.1 安装前准备
- **必要软件**：`gcc`、`make`、`autoconfig` 等开发工具，可用 `yum groupinstall "Development Tools"` 安装。
- **建议路径**：
  - 源代码解压目录：`/usr/local/src/`
  - 安装目录：`/usr/local/软件名/`（便于卸载，直接删除目录即可）
- **阅读文档**：务必先阅读源码目录下的 `INSTALL` 或 `README`。

### 4.2 标准安装流程（以 ntp 为例）
```bash
# 1. 解压到源码目录
cd /usr/local/src
tar -zxvf /path/to/ntp-4.2.8p3.tar.gz
cd ntp-4.2.8p3

# 2. 查看帮助并配置
./configure --help
./configure --prefix=/usr/local/ntp --enable-all-clocks --enable-parse-clocks
# --prefix 指定安装路径，其他选项根据软件需求添加

# 3. 编译
make clean   # 可选，清理之前编译的残留
make         # 编译源代码

# 4. 安装
make install
```

### 4.3 安装后配置
- **PATH 环境变量**：将安装目录的 `bin` 子目录加入 `PATH`，或使用绝对路径执行。
- **man page 路径**：在 `/etc/man_db.conf` 中添加一行，如 `MANPATH_MAP /usr/local/ntp/bin /usr/local/ntp/man`。

### 4.4 使用 patch 更新源代码
```bash
# 应用补丁（假设补丁文件在主目录）
patch -p1 < ~/main_0.1_to_0.2.patch
# -p1 表示去除补丁文件中路径的第一层目录

# 重新编译
make clean
make
make install
```
- 补丁文件通常由 `diff -Naur old new > patchfile` 生成。
- 若需还原补丁：`patch -R -p1 < patchfile`。

## 5. 函数库管理

### 5.1 查看程序依赖的动态库：`ldd`
```bash
ldd /usr/bin/passwd  # 列出 passwd 依赖的所有动态库
ldd -v /lib64/libc.so.6  # 显示详细版本信息
```

### 5.2 配置动态库缓存
- **配置文件**：`/etc/ld.so.conf` 和 `/etc/ld.so.conf.d/*.conf`
- **步骤**：
  1. 将动态库所在目录（如 `/usr/local/ntp/lib`）写入 `*.conf` 文件。
  2. 执行 `ldconfig` 更新缓存（`/etc/ld.so.cache`）。
  3. 可用 `ldconfig -p` 查看当前缓存内容。

### 5.3 动态与静态库对比
| 特性 | 静态库（`.a`） | 动态库（`.so`） |
|------|----------------|------------------|
| 编译行为 | 代码整合到可执行文件中 | 仅记录指向指针 |
| 可执行文件大小 | 较大 | 较小 |
| 独立性 | 可独立执行 | 依赖库文件存在 |
| 升级便利性 | 需重新编译所有依赖程序 | 升级库文件即可 |

## 6. 软件校验与安全

### 6.1 校验工具
- **md5sum**：生成或校验 MD5 摘要。
- **sha1sum / sha256sum**：更安全的 SHA 系列摘要。

### 6.2 校验示例
```bash
# 计算文件 MD5 值
md5sum ntp-4.2.8p3.tar.gz
# 输出应与官网提供的 MD5 一致

# 批量校验（需先创建校验文件）
md5sum -c checksums.md5
```

### 6.3 应用场景
- 下载的系统镜像（如 CentOS ISO）可验证其完整性。
- 对系统关键文件（如 `/bin/login`、`/bin/ps`）建立指纹库，定期检查，防范木马篡改。

## 7. 重点
- 源代码需通过编译器（如 `gcc`）才能变成可执行文件。
- `make` 工具通过 `Makefile` 实现自动化编译，简化编译流程。
- Tarball 是源码的压缩包，典型安装流程为 `./configure` → `make` → `make install`。
- 建议将源码解压至 `/usr/local/src`，软件安装至 `/usr/local/软件名`，便于管理和卸载。
- 动态函数库（`.so`）优于静态库（`.a`），升级方便；通过 `/etc/ld.so.conf` 和 `ldconfig` 管理库缓存。
- `ldd` 可查看可执行文件的动态库依赖。
- `patch` 工具可用于更新源码，避免下载完整新包。
- 使用 `md5sum` / `sha1sum` / `sha256sum` 校验下载文件的完整性，确保软件未被篡改。
