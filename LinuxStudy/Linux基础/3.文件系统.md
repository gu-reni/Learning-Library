# 一.文件名规则

## 允许的字符：
- **字母**：a-z, A-Z
- **数字**：0-9
- **特殊字符**：`.`（点）, `_`（下划线）, `-`（连字符）, （空格）
- **特殊含义字符**（需要转义）：`*` `?` `[` `]` `(` `)` `{` `}` `<` `>` `|` `\` `"` `'` `&` `;` `$` `!` `#` `%` `~` `+` `=` `@` `^` 
## 特殊文件类型标记
- **`.`开头**：隐藏文件（如 `.rc`）
- **/结尾**：目录（使用 `ls -F` 时显示）
- \* **结尾**：可执行文件（使用 `ls -F` 时显示）
- **@结尾**：符号链接（使用 `ls -F` 时显示）
- **|结尾**：命名管道（FIFO）
- **=结尾**：套接字（socket）

## 特殊文件名处理

### **1. 带空格的文件名**：

```

# 创建
touch "file with spaces.txt"

# 访问
cat "file with spaces.txt"
cat file\ with\ spaces.txt
cat 'file with spaces.txt'

# 删除
rm "file with spaces.txt"
```

### **2. 以短横线开头的文件名**：

```
# 创建
touch -- -filename.txt  # 使用 -- 表示选项结束

# 访问
cat -- -filename.txt
cat ./-filename.txt     # 使用相对路径

# 删除
rm -- -filename.txt
rm ./-filename.txt
```

### **3. 包含特殊字符的文件名**：
```
# 创建（需要转义）
touch file\*.txt        # 文件名为 file*.txt
touch file\$\$.txt      # 文件名为 file$$.txt
touch file\>.txt        # 文件名为 file>.txt

# 或者使用单引号
touch 'file*.txt'

### **4. 包含换行符的文件名**（极罕见但可能）：



# 创建
touch $'file\nname.txt'  # 文件名为 file[换行]name.txt

# 查找并删除
find . -name $'*\n*' -delete
```

# 四.文件系统
## Linux磁盘文件名：
- 实体磁盘：`/dev/sd[a-p]`（如第一颗磁盘为 `/dev/sda`） 
- 虚拟磁盘：`/dev/vd[a-d]`（常见于虚拟机）
- 分区：`/dev/sda1`、`/dev/sda2`…
## 文件系统核心概念
- **格式化**：将分区转换为操作系统可识别的文件系统格式。
 **索引式文件系统**（如EXT2）：
 - 超级区块（**superblock**）：记录文件系统整体信息（inode/block总量、使用量等）。
 -  **inode**：记录文件属性与权限，以及文件数据所在的block编号。
 - 区块（**block**）：实际存储文件内容的区块。
## 文件系统的工作原理
**索引式文件系统（如EXT2/3/4）**：
通过inode直接记录文件数据所在的block编号，可一次性读取所有数据块，效率高。文件分散存储时（碎片化）影响较小，一般无需频繁“磁盘重组”。
![[附件：inode block数据存取示意图.png]]
**链式文件系统（如FAT）**：
每个block记录下一个block的位置，需按链式顺序读取，碎片化时性能下降明显，需定期整理。
![[附件：FAT文件系统数据存取示意图.png]]
## Linux的EXT2文件系统（inode）
- **EXT2采用inode为基础**，inode记录文件属性与权限，block存储文件实际内容。
- 文件系统分为多个**区块群组（block group）**，每个群组有独立的inode、block和superblock，便于管理。
- **Block大小**有1K、2K、4K三种，影响文件系统最大支持容量和文件大小。
- **一个block只能存储一个文件**，若文件小于block，剩余空间将被浪费。
- **inode结构**：
    - 固定128字节（ext4/xfs可设为256字节）。
    - 记录文件权限、所有者、时间戳、block指向等。
    - 支持**直接、间接、双间接、三间接**block指向，以支持大文件。


## 与目录树的关系
- **目录**占用一个inode和至少一个block，block中记录其下**文件名与对应inode号**。
- **文件**根据大小分配一个inode和多个block。
- **读取文件流程**：从根目录开始，逐级查找inode和block，最终读取文件内容。

## EXT2/EXT3/EXT4文件的存取与日志式文件系统
- **文件创建流程**：
    1. 检查目录权限；
    2. 分配inode并写入属性；
    3. 分配block并写入数据；
    4. 更新bitmap和superblock。
- **日志式文件系统（如ext3/ext4）**：
    - 在写入前先在日志区记录操作步骤，便于系统崩溃后快速恢复一致性。

## Linux文件系统的运行
- Linux采用**异步I/O**机制，文件先在内存中修改，标记为“脏（Dirty）”，再定期同步到磁盘。
- 可使用**sync命令**手动强制写回。
- 异常关机可能导致文件系统不一致，需进行磁盘检查。

## 挂载点的意义
- 文件系统必须**挂载到目录树**的某个目录（挂载点）才能被访问。
- 同一文件系统内的`.`和`..`指向同一inode。

## 其他Linux支持的文件系统与VFS

- Linux支持多种文件系统，如：
    - 传统：ext2、FAT、iso9660
    - 日志式：ext4、XFS、NTFS、ReiserFS
    - 网络：NFS、SMB
- **VFS（虚拟文件系统）** 统一管理各种文件系统，对用户透明。

## XFS文件系统简介

- **CentOS 7默认使用XFS**，适合大容量磁盘与高性能需求。
- **XFS结构**分为：
    1. **数据区（data section）**：动态分配inode和block。
    2. **日志区（log section）**：记录文件系统操作，支持外部设备（如SSD）。
    3. **实时运行区（realtime section）**：用于高效存储大文件。
- 可使用**xfs_info**查看XFS文件系统信息。
## **磁盘分区与分区表管理**
- **分区表格式与工具对应**：
    |分区表格式|适用工具|特性说明|
    |---|---|---|
    |**MBR**（传统）|`fdisk`|分区数量有限（主分区≤4），最大支持 2TB 磁盘|
    |**GPT**（现代）|`gdisk`|分区数量多（默认128），支持 >2TB 磁盘，CentOS 7 默认|
- **分区操作核心原则**：
    - 针对**整块磁盘**操作（如 `/dev/vda`），**不可**针对已存在的分区（如 `/dev/vda1`）。
    - 通过 `+容量`（如 `+1G`）指定新增分区大小，**无需手动计算扇区数**。
    - 修改分区表后需使用 **`partprobe`** 通知内核重读分区表，**否则需重启**。
## **文件系统格式化（创建文件系统）**
- **通用指令**：`mkfs` —— 根据 `-t` 参数调用对应文件系统专用格式化工具。
- **XFS 文件系统（默认）** —— `mkfs.xfs`
    - **关键可调参数**：
        - `-b`：block 大小，默认 4K。
        - `-d agcount=数值`：**分配组（Allocation Group）数量**，建议与 CPU 核心数（含超线程）匹配，提升并发性能。
        - `-d su=数值, sw=数值`：配合 **RAID 条带（stripe）** 优化，`su`=条带大小，`sw`=数据盘数量（不含校验盘）。
        - `-r extsize=数值`：** extent 大小**，建议设为 `su * sw`，减少文件碎片。
    - **强制格式化**：若设备已有文件系统，需加 `-f`。
- **EXT4 文件系统** —— `mkfs.ext4`
    - **关键可调参数**：
        - `-b`：block 大小（1K/2K/4K）。
        - `-L`：设置卷标（LABEL）。
    - 默认配置由 `/etc/mke2fs.conf` 定义，通常无需手动调整 inode 大小等。
- **其他文件系统**：支持 vfat, ext3, ext2 等，通过 `mkfs -t 类型` 调用
## **文件系统检验与修复**
- **XFS 修复** —— `xfs_repair`
    - **必须卸载文件系统**（根目录除外，需进入救援模式并使用 `-d` 选项）。
    - 分为 **7 个阶段**（Phase），依次检查 superblock、AG、inode 连接等。
    - `-n`：仅检查，不修改。
- **EXT4 修复** —— `fsck.ext4`
    - **必须卸载文件系统**。
    - `-f`：**强制检查**（即使文件系统标记为 clean）。
    - `-b 超级块备份位置`：当主超级块损坏时，使用备份超级块修复（备份位置：1K block → 8193，2K → 16384，4K → 32768）。
- **通用原则**：
    - 文件系统修复**具有风险**，仅在系统出现严重错误时使用。
    - 已挂载的文件系统不可执行修复操作。
## **文件系统挂载与卸载**
- **挂载（mount）的本质**：将文件系统与一个目录（挂载点）关联，该目录成为访问文件系统的入口。
- **挂载点原则**：
    - 一个文件系统**不可重复挂载**到不同目录。
    - 一个目录**不可挂载多个文件系统**（后挂载的会隐藏原目录内容）。
    - 挂载点**应为空目录**，否则原目录内容会被临时隐藏。
- **设备标识方法（推荐顺序）**：
    1. **UUID**（`blkid` 获取） —— **UUID 优于设备名**,设备名（`/dev/sda1`）可能因硬件变动而改变，UUID 具有全域唯一性，**是持久化挂载（如 `/etc/fstab`）的首选标识**。
    2. **LABEL**（卷标） —— 需事先设置。
    3. 设备文件名（如 `/dev/vda4`） —— 可能随硬件变动而改变。
- **常用挂载选项（-o）**：
    - `ro, rw`：只读/读写。
    - `remount`：**重新挂载**（常用于修改根目录挂载参数，如 `mount -o remount,rw /`）。
    - `noatime`：不更新文件访问时间，提升性能。
    - `bind`：**将目录挂载到另一目录**（`mount --bind 原目录 新目录`），两者共享同一 inode。
- **卸载（umount）**：
    - 可使用“设备文件名”或“挂载点”。
    - **无法卸载正在使用中的文件系统**（如进程当前目录位于挂载点下），需退出该目录或终止相关进程。
## **设备文件与文件系统参数修订**
- **设备文件手动创建** —— `mknod`
    - Linux 中设备以文件表示，通过 **major, minor 号码** 标识内核驱动。
    - `b`：块设备（磁盘），`c`：字符设备（输入设备），`p`：FIFO（命名管道）。
    - 现代系统**自动管理**设备文件，极少需手动创建（主要应用于 chroot 环境）。
- **XFS 参数修改** —— `xfs_admin`
    - `-L`：**修改 LABEL**（卷标）。
    - `-U`：**修改 UUID**（可配合 `uuidgen` 生成新 UUID）。
    - 修改后需**重新挂载**生效。
- **EXT4 参数修改** —— `tune2fs`
    - `-L`：修改卷标。
    - `-U`：修改 UUID。
    - `-l`：类似 `dumpe2fs -h`，查看 superblock 信息。
## **开机自动挂载机制 —— `/etc/fstab`**

系统开机时自动挂载文件系统的行为完全由配置文件 **`/etc/fstab`**（filesystem table）控制。该文件将手动挂载时使用的参数固化，是系统管理员必须掌握的核心配置文件。

### **1. 文件字段结构（六字段规范）**

每一行代表一个要挂载的文件系统，共六个字段，**顺序固定**，以空白或 Tab 分隔。

|字段顺序|字段名称|必填|内容说明与可用值|
|---|---|---|---|
|**1**|**设备标识**|是|可使用三种形式之一：  <br>• 设备文件名（如 `/dev/vda2`）  <br>• **UUID**（如 `UUID=xxx`，推荐）  <br>• **LABEL**（如 `LABEL=xxx`）|
|**2**|**挂载点**|是|必须是已存在的目录，作为文件系统访问入口。|
|**3**|**文件系统类型**|是|如 `xfs`, `ext4`, `vfat`, `iso9660`, `nfs` 等。|
|**4**|**挂载参数**|是|逗号分隔的选项列表，常见参数见下文表格。若无特殊需求，通常使用 `defaults`。|
|**5**|**dump 备份标记**|否|传统 `dump` 备份工具使用标志：`0` 表示不备份，`1` 表示备份。现代系统通常填 `0`。|
|**6**|**fsck 检查顺序**|否|开机时 `fsck` 检查文件系统的顺序：  <br>• `0`：不检查  <br>• `1`：根目录（/）  <br>• `2`：其他文件系统（ext 系有效，xfs 自动处理，可填 `0`）|

### **2. 常用挂载参数（第四字段）**

|参数|含义与影响|
|---|---|
|`defaults`|默认组合：`rw, suid, dev, exec, auto, nouser, async`，适用于绝大多数场景。|
|`rw` / `ro`|以可读写（rw）或只读（ro）方式挂载。|
|`async`|**异步 I/O**（默认），数据先写入内存缓冲区，稍后写入磁盘，性能较佳，但断电有丢数据风险。|
|`sync`|**同步 I/O**，数据实时写入磁盘，安全性高，性能差，通常用于关键存储（如U盘）。|
|`auto` / `noauto`|是否允许 `mount -a` 自动挂载。`noauto` 常用于需要手动挂载的设备（如光驱）。|
|`exec` / `noexec`|是否允许在该文件系统上执行二进制程序。数据分区可设为 `noexec` 提升安全性，但需谨慎。|
|`suid` / `nosuid`|是否允许 SUID/SGID 权限生效。无此需求的分区可设为 `nosuid`。|
|`user` / `nouser`|是否允许普通用户执行 `mount` 命令挂载该分区。默认 `nouser`（仅 root 可挂载）。|
|`remount`|重新挂载，通常用于修改已挂载分区的参数（如 `mount -o remount,ro /`）。|
|`loop`|将普通文件作为块设备挂载（如 ISO 镜像、虚拟磁盘文件），需要内核 `loop` 模块支持。|
## **开机挂载的核心限制与原则**
1. **根目录必须最先挂载**：`/` 是其他所有挂载点的基座，必须在任何其他挂载点之前挂载完成。
2. **挂载点必须为已存在的空目录**：若目录非空，原内容会被临时隐藏，直至文件系统卸载。
3. **同一挂载点不可重复挂载不同文件系统**。
4. **同一文件系统不可重复挂载到不同挂载点**（硬链接除外，但挂载不允许）。
5. **卸载时，当前工作目录不能位于该挂载点或其子目录内**，否则设备繁忙（`target is busy`）。
### **使用 UUID 的设备标识策略**
**强烈推荐在 `/etc/fstab` 中使用 UUID 而非设备文件名（如 `/dev/sda1`）。**
- **UUID**（Universally Unique Identifier）：文件系统格式化时生成的**全域唯一标识符**，具有极高的唯一性。
- **优势**：设备文件名可能因硬件变动（如增加/移除磁盘、更换接口）而改变，但 UUID **永恒不变**，确保挂载行为不受硬件拓扑影响。
- **获取 UUID**：`blkid` 命令直接输出设备 UUID 及文件系统类型。
- **修改 UUID**（非常规操作）：
    - XFS：`xfs_admin -U 新UUID`（配合 `uuidgen` 生成）
    - EXT4：`tune2fs -U 新UUID`
### **测试与故障恢复**
#### **1. 配置文件语法测试 —— `mount -a`**

编辑 `/etc/fstab` 后，**必须**执行以下命令测试语法正确性：
```
mount -a
```
该命令会依照 `/etc/fstab` 内容**尝试挂载所有标记为 `auto` 的文件系统**。若无错误信息，且 `df` 检查目标挂载点已成功挂载，则配置无误。

**⚠️ 重要**：测试前需确保目标文件系统**未被挂载**，否则 `mount -a` 不会重复挂载，无法验证配置。

#### **2. 紧急修复模式下的根目录重挂载**

若 `/etc/fstab` 配置错误导致无法正常开机，系统会进入**单人维护模式**（emergency/rescue）。此时根目录通常以**只读**方式挂载，无法直接编辑文件。
**解决方案**：
```
mount -n -o remount,rw /
```
- `-n`：不写入 `/etc/mtab`（避免写入只读文件系统）
- `-o remount,rw`：重新挂载根目录并赋予读写权限
执行后即可编辑 `/etc/fstab` 修正错误。
## **特殊设备挂载 —— Loop Device 机制**
**Loop 设备**是一种**伪设备**，它允许将**普通文件**模拟为块设备，进而对其格式化、挂载，如同操作物理磁盘分区。
### **1. 挂载光盘/镜像文件（ISO）**
无需烧录，直接挂载 ISO 文件读取内容：
- 内核通过 **`loop` 驱动**将 ISO 文件映射为 `/dev/loopX` 设备。
- 文件系统类型通常为 `iso9660`。
- 挂载参数：`-o loop`（现代系统可自动识别，但为兼容性建议保留）。
**典型应用**：验证镜像完整性、提取内部文件、制作自定义安装源。
### **2. 创建基于文件的虚拟文件系统**
**适用场景**：磁盘分区已用尽，但仍有剩余容量时，可通过大文件模拟新分区。
**核心流程**：
1. **生成空文件**：使用 `dd` 从 `/dev/zero` 读取零数据，写入指定文件。
    - `/dev/zero`：提供无限连续的 `0x00` 字节流。
    - 关键参数：`bs`（块大小）、`count`（块数量） → 文件大小 = `bs × count`。
2. **格式化**：直接对**文件**执行 `mkfs.xfs -f` 等命令，建立文件系统。
3. **挂载**：通过 `-o loop` 将该文件挂载到指定目录。
4. **持久化**：在 `/etc/fstab` 中写入该文件的**绝对路径**，并添加 `loop` 参数，实现开机自动挂载。
**优势**：
- 不破坏原有分区表。
- 灵活调整大小（可扩容/缩容，需相应操作）。
- 常用于虚拟机磁盘映像、加密容器、测试环境。

**⚠️ 注意**：文件系统的 UUID 记录于文件内部，但 `/etc/fstab` 中直接使用**文件路径**（如 `/srv/loopdev`）比 UUID 更可靠，因为系统在挂载前无法识别文件内的 UUID。

## **内存交换空间（Swap）管理**
### **核心概念与功能定位**
**Swap（内存交换空间）** 是磁盘上的一块特殊区域，用于**暂存物理内存（RAM）中暂时不用的数据**。当物理内存不足时，内核会将不常访问的内存页移入 Swap，释放 RAM 给急需的进程。
- **物理本质**：Swap 是**磁盘空间**，读写速度远低于内存。频繁使用 Swap 会导致系统性能严重下降（磁盘灯持续闪烁）。
- **历史角色**：早期内存昂贵且容量小，Swap 是必需组件。现代个人计算机（≥4GB）常规负载下几乎用不到 Swap。
- **服务器场景**：必须配置 Swap，作为应对突发流量或内存泄漏的**安全缓冲**，防止系统因内存耗尽（OOM）直接崩溃。
- **休眠功能**：若系统启用**休眠（Suspend to Disk）**，Swap 容量**必须大于或等于物理内存容量**，用于保存系统运行状态。
#### **实体分区 Swap 创建流程**

|步骤|操作|命令/工具|关键说明|
|---|---|---|---|
|1|**分区**|`gdisk`（GPT）或 `fdisk`（MBR）|• 新建分区，大小自定（如 +512M）  <br>• **必须将分区类型代码改为 `8200`**（Linux swap）|
|2|**格式化**|`mkswap`|• 写入 Swap 签名，生成 UUID|
|3|**立即启用**|`swapon`|• 激活 Swap 分区，立即生效|
|4|**开机自动启用（持久化）**|`/etc/fstab`|• 设备标识**强烈建议使用 UUID**  <br>• 挂载点字段填写 **`swap`**  <br>• 文件系统类型填写 **`swap`**  <br>• 挂载参数 `defaults`，后两字段 `0 0`|

**示例 `/etc/fstab` 条目**：
```
UUID=6b17e4ab-9bf9-43d6-88a0-73ab47855f9d   swap   swap   defaults   0   0
```

### **文件型 Swap 创建流程**

|步骤|操作|命令/工具|关键说明|
|---|---|---|---|
|1|**创建空文件**|`dd`|• `if=/dev/zero`（零设备）  <br>• `of=文件路径`  <br>• `bs=块大小` `count=块数` → 文件大小 = bs × count|
|2|**格式化为 Swap**|`mkswap`|• **对文件执行**格式化（⚠️ 极其危险，输错设备名可能破坏文件系统）|
|3|**立即启用**|`swapon`|• 内核通过 **loop 设备**将文件映射为虚拟块设备|
|4|**开机自动启用（持久化）**|`/etc/fstab`|• **设备标识必须使用文件的绝对路径**（如 `/tmp/swap`）  <br>• **不可使用 UUID**（系统启动时不识别文件内 UUID）  <br>• 其余字段同分区 Swap|

**示例 `/etc/fstab` 条目**：
```
/tmp/swap   swap   swap   defaults   0   0
```

**⚠️ 重要差异**：分区 Swap 与文件型 Swap 在 `/etc/fstab` 中的设备标识规则**完全不同**，切勿混淆。

### **Swap 管理核心命令**

|命令|作用说明|
|---|---|
|`mkswap`|初始化 Swap 分区或文件，写入签名，生成 UUID|
|`swapon`|激活指定的 Swap 设备/文件|
|`swapoff`|停用指定的 Swap 设备/文件|
|`swapon -s`|列出当前系统所有已激活的 Swap 资源，显示类型、大小、使用量、优先级|
|`free`|显示物理内存（Mem）与 Swap 的总量、已用量、可用量、缓存/缓冲区等信息|
|`swapon -a`|根据 `/etc/fstab` 配置，**激活所有标记为 auto 的 Swap**（用于测试配置）|

### **开机自动启用测试流程**
编辑 `/etc/fstab` 添加 Swap 条目后，**必须进行语法测试**，避免配置错误导致无法开机：
1. **停用待测 Swap 资源**（如已启用）：
```
swapoff /dev/vda6   # 分区 Swap
swapoff /tmp/swap   # 文件型 Swap
```

2. **执行自动激活测试**：
```
swapon -a
```
2. **验证激活结果**：
```
swapon -s #若目标 Swap 设备出现在列表中，且 `free` 命令显示 Swap 总量增加，则配置无误。
```

### **现代环境下的 Swap 配置建议（基于 2015+ 硬件）**

|环境类型|物理内存典型容量|Swap 配置建议|
|---|---|---|
|**个人桌面**|≥ 4GB|**可不配置**，或保留 1~2GB 以“备而不用”|
|**服务器**|视负载而定|**必须配置**，建议容量为物理内存的 1~2 倍|
|**启用休眠**|任意|Swap 容量 **必须 ≥ 物理内存容量**|

- **核心原则**：Swap 是“安全缓冲”而非性能加速手段。服务器必须“备而不用”，个人环境可酌情省略。
- **性能权衡**：分区 Swap 性能略优于文件型 Swap（无文件系统开销），但在 SSD 时代差异极小。
- **文件位置**：文件型 Swap 应存放在稳定目录（如 `/var/swap`），避免使用 `/tmp` 等可能被定期清理的路径。
### **常见误区与关键提醒**

1. **分区类型代码必须修改**：`gdisk` 默认新建分区为 `8300`（Linux filesystem），Swap 必须显式指定为 **`8200`**
2. **文件型 Swap 禁用 UUID**：在 `/etc/fstab` 中**绝对不可使用 UUID**，必须写文件路径。
3. **格式化风险**：`mkswap` 一旦误操作到现有文件系统分区，将**立即破坏该分区数据**，执行前务必确认设备名。
4. **Swap 文件不宜过大**：单个 Swap 文件不宜超过 2GB（旧内核限制），现代内核支持更大文件，但仍建议按需分配。
5. **启用前必须格式化**：直接对未执行 `mkswap` 的设备执行 `swapon` 会报错。
## **文件系统的特殊观察与操作**
### **磁盘空间占用与浪费本质**
文件系统格式化后，即使未存放任何用户数据，磁盘容量也已被部分占用。这种“损耗”主要源于两个层面：
**1. 元数据开销**
- `superblock`、`inode table`、日志（journal）等结构**预先分配固定空间**。
- 不同文件系统元数据占比不同（如 EXT4 默认预留 5% 给 root）。
**2. Block 分配粒度**
- **一个 block 只能存放一个文件**，无论文件实际大小多少，均分配**整数个 block**。
- 例：block = 4KB，1KB 的文件仍占用 4KB → 小文件越多，空间浪费越显著。
**查看文件真实占用容量的方法**
```
ls -ls          # 或 ll -sh
```
- 输出**第一列**：该文件占用的 **block 数 × block 大小**（以 KB 为单位）。
- 目录下的 **`total`** 值 = 该目录下**所有文件占用 block 的总和**（KB）。
**示例解析**
```
[root@study ~]# ll -sh
total 12K
4.0K -rw-------. 1 root root 1.8K May  4 17:57 anaconda-ks.cfg
4.0K -rw-r--r--. 2 root root  451 Jun 10  2014 crontab
0    lrwxrwxrwx. 1 root root   12 Jun 23 22:31 crontab2 -> /etc/crontab
4.0K -rw-r--r--. 1 root root 1.9K May  4 18:01 initial-setup-ks.cfg
```
- `crontab` 内容仅 451 字节，但占用 4.0KB（一个完整 block）。
- `total 12K` = 三个 4.0KB 文件之和（符号链接本身不占用 data block）。
**核心认知**：  
磁盘空间“损耗”是**文件系统固有属性**，规划分区时应根据文件平均大小合理选择 block 大小（如 1K/2K/4K）。
### **跨平台分区工具 `parted` 深度解析**
#### **核心定位与优势**
`parted` 是 GNU 开发的分区工具，**同时完整支持 MBR（msdos）与 GPT 分区表**，无需根据分区表类型切换工具（如 `fdisk`/`gdisk`）。  
**最大价值**：**命令行非交互式操作**，适合**脚本批量分区部署**。

|特性|`parted`|`fdisk` / `gdisk`|
|---|---|---|
|分区表支持|MBR + GPT（统一）|仅其一（需区分）|
|交互方式|命令行指令（可脚本化）|交互式菜单|
|单位显示|默认容量（MB/GB），直观|默认扇区（需换算）|
|适用场景|自动化运维、快速查询|日常手动分区、详细配置|

#### **常用功能与参数（概念性）**

|指令/动作|核心作用|关键注意点|
|---|---|---|
|`print`|显示分区表：分区号、起止位置、容量、文件系统等|**容量单位可调**（`unit MB`/`GB`/`s`）|
|`mkpart`|**新建分区**（指定类型、起止位置）|起始位置须 ≥ 前一分区结束|
|`rm`|删除指定分区|谨慎操作|
|`mklabel`|**重新初始化分区表**（如 `msdos`→`gpt`）|**毁灭性操作，数据全失**|
|`help [指令]`|查看指令详细参数|替代记忆，随时查询|

#### **分区表示例解读（GPT）**
```
Number  Start   End     Size    File system     Name              Flags
1      1049kB  3146kB  2097kB                  bios_grub
2      3146kB  1077MB  1074MB  xfs
3      1077MB  33.3GB  32.2GB                  lvm
4      33.3GB  34.4GB  1074MB  xfs             Linux filesystem
5      34.4GB  35.4GB  1074MB  ext4            Microsoft basic data
6      35.4GB  36.0GB   537MB  linux-swap(v1)  Linux swap
```
- **Start / End / Size**：以容量单位直接显示，**无需换算扇区**。
- **File system**：仅**检测到的**文件系统类型，非绝对准确（新建时指定类型仅作描述）。
- **Name**：GPT 专属字段（对应 gdisk 中的分区名称）。
#### **分区表类型转换（高危操作）**
```
parted /dev/sda mklabel gpt      # MBR → GPT（数据全毁）
parted /dev/sda mklabel msdos    # GPT → MBR（数据全毁）
```
⚠️ **不可逆警告**：此操作**清空整个磁盘所有分区及数据**。仅适用于全新磁盘或已完整备份的场景。

#### **应用场景与选型建议**

|场景|推荐工具|理由|
|---|---|---|
|**日常手动分区**（单机）|`gdisk` / `fdisk`|交互式界面，分步确认，不易出错|
|**批量部署/脚本自动化**|**`parted`**|**完全非交互**，一行指令完成分区创建|
|**仅查看分区表**|`parted print`|容量单位直观，无需计算扇区|
|**跨分区表类型维护**|`parted`|同一工具兼容 MBR/GPT，无需切换|

**实践要点**：
- 无论使用何种分区工具，**修改分区表后必须执行 `partprobe`** 通知内核更新分区记录。
- `parted` 的 `mkpart` 仅**记录分区边界，不执行格式化**，需额外使用 `mkfs`

# 五.文件与文件系统的压缩和备份
## **压缩原理与价值**
**压缩的本质**  
文件压缩是通过特定算法，**消除数据中“闲置空间”与“重复模式”**，以降低存储容量的技术。
- **位（bit）空闲利用**：计算机以字节（Byte）为单位存储，但实际有效数据可能仅占少数位（例如数字“1”只占1 bit），其余位被“填0”闲置。压缩算法可重新组织这些位，腾出空间。
- **重复数据统计**：将连续重复的数据（如“100个1”）记录为“100个1”而非100个独立位，极大缩减体积。
**压缩的价值**
- **节省存储空间**：同等容量可存放更多数据。
- **加速网络传输**：压缩后数据量减少，带宽利用率提升，传输时间缩短（如网站动态压缩、软件镜像分发）。
- **便于归档与分发**：大文件可拆分、打包，适应存储介质（如CD/DVD）或邮件附件限制。
## **Linux 主流压缩工具对比**
Linux 环境常见压缩指令均针对**单一文件**操作，**不具打包功能**，需配合 `tar` 使用。

|工具|扩展名|压缩比|压缩速度|解压速度|典型场景|备注|
|---|---|---|---|---|---|---|
|**gzip**|`.gz`|中|**快**|快|日常快速压缩、文本文件|应用最广，兼容性好|
|**bzip2**|`.bz2`|良|较慢|较慢|对压缩率有更高要求|明显慢于 gzip|
|**xz**|`.xz`|**优**|**极慢**|中|追求极限压缩比、归档长期存储|时间成本高，压缩率最优|

**共性特点**
- 默认压缩后**删除原始文件**（可通过 `-c` 与重定向保留原文件）。
- 均提供 `-1`（最快）至 `-9`（最优）压缩等级，默认 `-6`。
- 配套阅读工具（`zcat`/`bzcat`/`xzcat`）可直接查看压缩文本文件内容，无需解压。
- 支持从压缩包中搜索关键字（`zgrep`/`bzgrep`/`xzgrep`）。
## **打包命令 `tar` 深度解析**
`tar`（Tape ARchive）是 Linux 最核心的**打包与归档工具**，其本身**不压缩**，但可无缝调用 `gzip`/`bzip2`/`xz` 实现**打包+压缩**一体化。
### **核心功能模式**
- **创建打包/压缩档**：`tar -c` + 压缩选项 + `-f 文件名` + 源文件/目录
- **查看打包内容**：`tar -t` + 压缩选项 + `-f 文件名`
- **解包/解压缩**：`tar -x` + 压缩选项 + `-f 文件名` [+ `-C 目录`]
**注意**
- `-c`、`-t`、`-x` **三者互斥**，不可同时出现。
- `-z`（gzip）、`-j`（bzip2）、`-J`（xz）**三者互斥**。
- **`-f` 必须紧跟文件名**，建议独立写出，避免与其它选项混淆。
#### **关键选项速查**

|选项|作用说明|典型应用场景|
|---|---|---|
|`-p`|**保留原始文件权限与属性**（如所有权、ACL）|系统配置文件备份|
|`-P`|**保留绝对路径**（文件名含根目录 `/`）|极少用，解压时会覆盖原路径|
|`--exclude=FILE`|**排除指定文件/目录**（支持通配符）|跳过临时文件、缓存、备份文件自身|
|`--newer-mtime`|**仅备份 mtime 比指定时间更新的文件**|增量备份、差异备份|
|`-C 目录`|**解压时切换到指定目录**|将内容释放到非当前目录|
|`-v`|**显示处理中的文件名**|观察打包/解压进度|

#### **文件名约定**
- **纯打包**（未压缩）：`*.tar`（tarfile）
- **打包 + gzip**：`*.tar.gz` 或 `*.tgz`（tarball）
- **打包 + bzip2**：`*.tar.bz2`（tarball）
- **打包 + xz**：`*.tar.xz`（tarball）
#### **重要行为特性**
1. **自动移除绝对路径**：默认情况下，`tar` 打包时会**移除文件名开头的 `/`**，解压时文件将相对于当前目录释放。**这是安全设计**，防止误覆盖原系统文件。若需保留绝对路径，必须加 `-P`。
2. **权限保留需显式指定**：仅使用 `-p` 才能完整保留文件权限、属性。**备份系统关键目录（如 `/etc`）务必加 `-p`**。
3. **打包自身排除**：若备份目标包含输出文件自身，需用 `--exclude` 排除，否则可能无限递归或报错。
### **高级应用与实战案例**
#### **1. 单一文件提取**（不解压全部）
```
tar -jtvf etc.tar.bz2 | grep 'shadow'   # 查找目标文件在包内的精确路径
tar -jxvf etc.tar.bz2 etc/shadow        # 仅解压 etc/shadow（注意无前导/）
```

#### **2. 排除特定文件/目录**
```
tar -jcvf /root/system.tar.bz2 \
  --exclude=/root/*.bz2 \
  --exclude=/root/*.gz \
  --exclude=/home/loop* \
  /etc /home /root
```

#### **3. 增量备份**（基于时间戳）
```
tar -jcvf /root/etc.newer.tar.bz2 \
  --newer-mtime="2025-01-01" /etc/*

仅备份 `/etc` 下 **mtime 晚于指定日期**的文件，适合日常差异备份。
```

#### **4. 标准输入输出与管线应用**（无需中间文件）
```
tar -cvf - /etc | tar -xvf - -C /tmp
```
将 `/etc` 打包并直接通过管道解压到 `/tmp`，等价于 `cp -r /etc /tmp`，但更灵活。

#### **5. 系统备份典型范例**
```
mkdir /backups && chmod 700 /backups
tar -jcvf /backups/backup-system-$(date +%Y%m%d).tar.bz2 \
  --exclude=/root/*.bz2 --exclude=/root/*.gz \
  --exclude=/home/loop* \
  /etc /home /var/spool/mail /var/spool/cron /root
```

- **特点**：排除压缩文件自身、用户循环设备，保留权限（`-p` 隐含常用）。
- **命名**：动态生成日期标识，便于归档管理。
### **关键注意事项与避坑指南**
#### **1. 打包时根目录的处理**
- **默认行为**：自动移除绝对路径，解压后文件置于当前目录的相对路径。
- **安全风险**：若误用 `-P`，解压时会**直接覆盖原系统路径**（如 `/etc`），**极大概率导致系统异常**。
- **准则**：除非有绝对把握，**永远不要在生产环境使用 `-P`**。
#### **2. 权限与 SELinux 上下文**
- **权限丢失**：未加 `-p` 打包再解压的文件，所有权、权限可能变为执行解压的用户，导致服务无法启动。
- **SELinux 标签重置**：从 tarball 还原的系统文件（尤其 `/etc`），其 SELinux 上下文可能丢失或被设置为默认类型，**引发无法登录、服务拒绝访问**。
**解决方案（三选一）**
1. 解压后立即执行 `restorecon -Rv /etc` 恢复 SELinux 标签（推荐）。
2. 若已重启无法登录，在引导时进入单用户模式，创建 `/.autorelabel` 文件，重启后系统自动修复 SELinux 标签。
3. 临时禁用 SELinux（`/etc/selinux/config` 设为 `permissive`），修复后再启用。
#### **3. 压缩工具的选择权衡**
- **gzip**：速度优先，适合频繁操作、实时传输。
- **xz**：空间优先，适合长期归档、冷存储。
- **bzip2**：介于两者之间，现已逐步被 xz 替代。
**实用建议**
- 个人日常备份：`tar.gz`（兼顾速度与体积）。
- 服务器长期归档：`tar.xz`（节省存储成本）。
- 脚本自动化：优先 gzip，避免 xz 耗时阻塞流程。
#### **4. 文件扩展名的重要性**
Linux 虽不依赖扩展名识别文件类型，但**压缩/打包文件的扩展名是给“人”看的**——明确告知应由何种工具处理。**遵循 `.tar`, `.tar.gz`, `.tar.bz2`, `.tar.xz` 命名规范是良好习惯**。
### **核心概念辨析**

| 术语          | 定义                                               | 示例                    |
| ----------- | ------------------------------------------------ | --------------------- |
| **tarfile** | 仅经 `tar` 打包，**未压缩**的文件                           | `backup.tar`          |
| **tarball** | 经 `tar` 打包且**同时压缩**的文件（常与 `tar.gz`/`tar.bz2` 混用） | `backup.tar.gz`       |
| **压缩比**     | 压缩后体积 / 压缩前体积，数值越小表示压缩效果越好                       | 0.15 表示压缩至 15%        |
| **打包**      | 将多个文件/目录合并为单一文件（不改变总大小）                          | `tar -cvf`            |
| **压缩**      | 通过算法减小单个文件体积                                     | `gzip`, `bzip2`, `xz` |

## **XFS 文件系统备份与还原**
**`xfsdump` 与 `xfsrestore`** 是 XFS 文件系统专用的备份/还原工具，支持**完整备份**和**增量备份**。

### **核心概念**

- **备份等级（Level）**：`xfsdump` 使用 **0~9** 共十个等级。
    - **Level 0**：完整备份，备份整个文件系统。
    - **Level 1**：增量备份，仅备份自上一次 level 0 后变化的数据。
    - 更高等级类推。
- **备份信息记录**：每次备份的元数据（文件系统 UUID、时间戳、等级、标签等）存储在 **`/var/lib/xfsdump/inventory`** 中，供还原时查询。

#### **重要限制**
- 只能备份**已挂载**的 XFS 文件系统（不能备份未挂载的）。
- 必须使用 **root** 权限执行。
- 备份文件只能由 `xfsrestore` 解析。
- **依赖文件系统 UUID**：不能备份两个具有相同 UUID 的文件系统（可通过 `xfs_admin` 修改 UUID 规避）。
#### **常用选项（概念性）**
- `-L`：设置该次备份的 **Session 标签**（用于识别备份会话）。
- `-M`：设置**媒体标签**，用于标识存储介质。
- `-l #`：指定备份等级，默认为 0。
- `-f 备份文件`：指定备份输出的目标文件或设备。
- `-I`：列出 inventory 中所有备份信息。
#### **还原方式**
- **完整还原**：`xfsrestore -f 备份文件 -L 标签 目标目录`
- **部分还原**：使用 `-s 路径` 指定要还原的特定文件/目录。
- **交互式还原**：使用 `-i` 进入类似 FTP 的界面，浏览备份内容并选择还原项。
- **增量备份还原**：需按备份顺序依次应用（先 level 0，再 level 1…）。

## **光盘写入工具**

虽然光盘使用减少，但某些场景（如归档、可启动介质制作）仍需掌握。

### **创建镜像文件（`mkisofs`）**
- **作用**：将文件或目录制作成 ISO 9660 格式的镜像文件。
- **关键选项**：
    - `-r`：通过 Rock Ridge 扩展保留 Unix/Linux 文件权限和属性。
    - `-J`：生成 Joliet 扩展，增强与 Windows 的兼容性。
    - `-V vol`：设置光盘卷标。
    - `-m file`：排除指定文件。
    - `-graft-point`：允许将源目录映射到镜像内的不同路径（例如 `/cdrom_dir=/real_dir`）。
- **制作可启动光盘**：需指定启动文件（如 `-b isolinux/isolinux.bin`）和相关参数。
### **烧录镜像（`cdrecord` / `wodim`）**
- **作用**：将 ISO 镜像写入光盘。
- **关键步骤**：
    - 查询烧录机位置：`wodim --devices dev=/dev/sr0`
    - 抹除可重写光盘：`wodim blank=fast dev=/dev/sr0`
    - 烧录：`wodim -v dev=/dev/sr0 speed=4 -eject image.iso`
- **注意**：现代 CentOS 使用 `wodim` 作为 `cdrecord` 的替代，两者命令兼容。
## **其他常用备份工具**
### **1. `dd`：低级别复制工具**
- **特点**：直接读取磁盘**扇区（sector）**，不关心文件系统结构，可备份整个分区或磁盘（包括引导扇区、分区表）。
- **典型用途**：
    - 磁盘对拷：`dd if=/dev/sda of=/dev/sdb`
    - 制作 ISO 镜像：`dd if=/dev/cdrom of=/path/to/image.iso`
    - 将 ISO 写入 USB 启动盘：`dd if=image.iso of=/dev/sdX`
- **注意事项**：
    - 备份文件大小等于源设备容量（无论实际数据多少）。
    - 克隆后需处理 UUID 冲突（XFS 需用 `xfs_admin -U` 重新生成 UUID）。
### **2. `cpio`：归档工具**
- **特点**：不主动查找文件，需配合 `find` 等命令通过管道传入文件名列表。可备份任意文件（包括设备文件）。
- **典型用法**：
    - 备份：`find /path | cpio -ocvB > archive.cpio`
    - 还原：`cpio -idvc < archive.cpio`
    - 查看内容：`cpio -ivct < archive.cpio`
- **重要应用**：系统初始化内存盘（initramfs）即 cpio 格式，可用 `cpio` 解压查看其内容。
## 重点总结
- 压缩工具 `gzip`、`bzip2`、`xz` 各具特点，xz 压缩率最高但最慢，gzip 速度最快。
- `tar` 是打包与压缩的瑞士军刀，掌握 `-z`/`-j`/`-J` 与 `-c`/`-t`/`-x` 的组合是核心。
- 备份系统关键目录时务必使用 `-p` 保留权限，并注意默认移除绝对路径的安全机制。
- XFS 专用工具 `xfsdump`/`xfsrestore` 支持等级增量备份，但只能用于已挂载的 XFS 文件系统。
- `dd` 提供扇区级复制，适合完整克隆磁盘或制作启动盘，但可能产生 UUID 冲突。
- `cpio` 配合 `find` 可灵活归档任何文件，是 initramfs 等特殊归档的格式基础。
- 光盘工具 `mkisofs` 与 `wodim` 仍可用于制作和烧录可启动介质。
