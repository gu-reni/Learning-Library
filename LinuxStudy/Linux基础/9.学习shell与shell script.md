# 一.vim程序编辑器
## 为什么学习 vim

在 Linux 系统中，绝大部分配置文件都是以 ASCII 纯文本形式存在，因此掌握一种命令行下的文本编辑器至关重要。vim 是 vi 的进阶版本，之所以必须学习，主要基于以下原因：

- **普遍存在**：所有 Unix Like 系统都会内置 vi，其他编辑器则不一定会存在。
- **软件调用**：许多 Linux 指令（如 `crontab`、`visudo`、`edquota`）默认使用 vi 作为编辑界面。
- **程序编辑能力**：vim 支持语法高亮，能根据文件扩展名或内容自动判断语法，以不同颜色显示，便于程序开发和排错。
- **编辑效率高**：功能强大且操作简洁，熟练后可大幅提升编辑速度。

## vi/vim 核心概念

### 三种模式

vi/vim 的操作围绕三种模式进行，彼此间的切换关系如下图所示：

- **一般指令模式**（command mode）  
    打开文件后默认进入的模式。在此模式下，可以使用移动光标、删除字符、复制粘贴等指令，**但不能直接编辑文件内容**。
- **编辑模式**（insert mode）  
    在一般指令模式下按下 `i`、`o`、`a` 等键进入。左下角会显示 `-- INSERT --` 或 `-- REPLACE --`，此时可对文件内容进行编辑。按下 `Esc` 键返回一般指令模式。
- **命令行模式**（command-line mode）  
    在一般指令模式下输入 `:`、`/` 或 `?` 进入。用于执行保存、退出、查找、替换等操作。

> **模式切换规则**：一般指令模式可与编辑模式及命令行模式互相切换，但**编辑模式与命令行模式之间不能直接切换**。

### 基本操作流程

1. **打开文件**：`vi 文件名`（若文件不存在则创建新文件）。
2. **进入编辑模式**：按 `i`（在当前光标前插入）或 `o`（新增下一行）等键。
3. **编辑内容**：输入文字，完成后按 `Esc` 返回一般指令模式。
4. **保存并退出**：在一般指令模式下输入 `:wq`（保存并退出），或 `ZZ`（保存并退出，仅适用于文件未修改时快速离开）。
5. **强制退出不保存**：若修改后不想保存，输入 `:q!`。

### 常用按键功能分类
[[附件：vim按键说明]]
以下分类列出最常用的操作，无需记忆全部键位，掌握常用功能即可高效编辑。

#### 移动光标

- **方向键**或 `h`（左）、`j`（下）、`k`（上）、`l`（右）。
- **行内跳转**：`0` 或`Home`到行首，`$` 或`End`到行尾。
- **按页移动**：`Ctrl+f` 或`PgUp`向下翻页，`Ctrl+b`或`PgDn`向上翻页。
- **文件头尾**：`gg` 到第一行，`G` 到最后一行。
- **跳转到指定行**：`nG`（n 为行号），配合 `:set nu` 显示行号更便捷。

#### 搜寻与取代

- **向下搜寻**：`/word`，按 `n` 继续向下找，按 `N` 反向找。
- **向上搜寻**：`?word`，`n` 和 `N` 方向相反。
- **行内取代**（常用）：
    - `:n1,n2s/old/new/g`：将第 n1 到 n2 行间的所有 old 替换为 new。
    - `:1,$s/old/new/g`：全文替换。
    - 加上 `c` 参数（如 `:1,$s/old/new/gc`）会在每次替换前询问确认。

#### 删除、复制与粘贴

- **删除**：
    - `x` 删除光标后一个字符，`X` 删除前一个字符。
    - `dd` 删除光标所在行，`ndd` 删除向下 n 行。
    - `dG` 删除光标到文件尾，`d1G` 删除光标到文件头。
- **复制**：
    - `yy` 复制光标所在行，`nyy` 复制向下 n 行。
    - `yG` 复制光标到文件尾，`y1G` 复制光标到文件头。
- **粘贴**：
    - `p` 在光标下一行粘贴，`P` 在光标上一行粘贴。

#### 进入编辑模式的常用键

- `i`：在当前光标前插入。
- `a`：在当前光标后插入。
- `o`：在下一行新增一行并插入。
- `O`：在上一行新增一行并插入。
- `R`：进入取代模式，连续覆盖后续字符。

#### 命令行模式常用指令

- `:w` 保存，`:w!` 强制保存。
- `:q` 退出，`:q!` 强制退出不保存。
- `:wq` 保存并退出。
- `:set nu` 显示行号，`:set nonu` 取消行号。
- `:! command` 临时执行 shell 命令（如 `:! ls`）。

### 暂存盘与异常恢复

vim 在编辑文件时会在同一目录下创建一个隐藏的暂存文件 `.filename.swp`，用于记录编辑过程中的变更。当 vim 正常退出时，该暂存盘会被自动删除。

若因系统崩溃、网络中断等异常导致编辑会话被强制终止，暂存盘会保留。下次打开同一文件时，vim 会检测到暂存盘存在并给出警告，提供以下选项：

- **[O]pen Read-Only**：以只读方式打开，不载入暂存盘内容。
- **(E)dit anyway**：忽略暂存盘，直接编辑原文件（可能造成数据混乱）。
- **(R)ecover**：载入暂存盘内容，恢复上次未保存的数据。
- **(D)elete it**：删除暂存盘（确认其无用后选择）。
- **(Q)uit** 或 (A)bort：离开 vim，不进行任何操作。

> **最佳实践**：若确定暂存盘已无用，通常选择 **D** 直接删除；若想恢复数据则选 **R**，恢复后务必手动删除暂存盘。

### vim 的进阶功能

#### 区块选择（Visual Block）

当需要对列对齐的文本进行矩形区域操作时，可使用区块选择：

- `v`：字符选择（逐字）。
- `V`：行选择。
- `Ctrl+v`：**区块选择**（矩形区域）。

选定区域后，可按 `y` 复制、`d` 删除，然后移动光标到目标位置按 `p` 粘贴。此功能特别适合处理表格化数据或批量添加内容。

#### 多文件编辑

同时打开多个文件，便于文件间内容复制：

- 启动：`vim file1 file2`
- 切换：`:n` 到下一个文件，`:N` 到上一个文件。
- 查看列表：`:files` 列出所有打开的文件。

#### 多窗口操作

在一个 vim 界面中分割窗口，同时查看或编辑多个文件（或同一文件的不同部分）：

- **水平分割**：`:sp [filename]`（不指定文件名则复制当前窗口）。
- **窗口切换**：`Ctrl+w` 后按方向键（或 `j`/`k`）移动光标到其他窗口。
- **关闭窗口**：`:q` 或 `Ctrl+w q`。

#### 关键字补全

vim 支持根据上下文自动补全，对程序编写尤为有用：

- `Ctrl+n` 或 `Ctrl+p`：根据当前文件内容补全。
- `Ctrl+x Ctrl+f`：以文件名作为补全。
- `Ctrl+x Ctrl+o`：**根据文件扩展名调用语法补全**（如编辑 `.html` 文件时补全 CSS 属性）。

### 环境设置与个性化

#### .vimrc 配置文件

用户个人的 vim 环境设置可写入主目录下的 `.vimrc` 文件（默认不存在，需手动创建）。每次启动 vim 时会自动读取该文件，实现个性化配置。

常用设置示例（`~/.vimrc`）：
```
" 双引号为注解
set hlsearch        " 高亮显示搜索结果
set backspace=2     " 允许用退格键删除任意字符
set autoindent      " 自动缩排
set ruler           " 显示右下角状态栏
set showmode        " 显示当前模式（如 --INSERT--）
set nu              " 显示行号
set bg=dark         " 深色背景配色
syntax on           " 开启语法高亮
```

#### .viminfo 记录文件

vim 会自动在用户主目录下生成 `.viminfo` 文件，记录操作历史（如搜索过的字符串、光标位置等），以便下次编辑同一文件时光标定位到上次退出位置，并记住之前的高亮关键词。

### 总结

- Linux 配置文件多为文本文件，vim 是必学的编辑器。
- vi 有三种模式：一般指令模式、编辑模式、命令行模式，务必掌握切换方法。
- 常用操作：移动光标（`h j k l`, `0 $`, `gg G`）、删除复制（`dd`, `yy`, `p`）、搜寻取代（`/`, `:s`）。
- 暂存盘机制（`.swp` 文件）用于异常恢复，遇到警告时根据情况选择恢复或删除。
- 进阶功能：区块选择（`Ctrl+v`）、多文件编辑（`:n`）、多窗口（`:sp`）、关键字补全（`Ctrl+x Ctrl+o`）可大幅提升效率。
- 通过 `~/.vimrc` 自定义环境，通过 `~/.viminfo` 记录历史操作。
- 重点记忆几个常用指令，其余可通过 `man vim` 或网络查询。
# 二.认识 BASH 这个 Shell

## 硬件、核心与 Shell 的关系

操作系统（Kernel）负责管理整个计算机硬件，由于核心需要被保护，一般使用者无法直接操作核心，而是通过 **Shell**（壳程序）与核心沟通，让核心完成所需的工作。

- **核心**：直接控制硬件，管理系统资源。
- **Shell**：提供用户操作接口，接收用户指令并调用相应应用程序，应用程序再通过核心驱动硬件工作。
- **广义与狭义**：狭义的 Shell 指命令行界面（如 bash），广义的 Shell 也包括图形界面——只要能操作应用程序的接口都可称为壳程序。

## 为何要学习命令行 Shell

- **跨平台一致性**：各 Linux 发行版使用的 bash 基本相同，学会后能轻松切换不同 distribution。
- **远端管理效率高**：命令行传输速度快，不易断线或泄露信息，适合远程维护。
- **深入理解系统**：命令行操作能更深入了解 Linux 运行机制，而不只是点击鼠标。
- **自动化管理**：通过 Shell Script 可批量处理任务（如日志分析），大幅提升效率。

## 系统的合法 Shell

### 常见 Shell 类型

- **sh**（Bourne Shell）：最早的流行 Shell。
- **bash**（Bourne Again Shell）：Linux 默认 Shell，GNU 项目开发，增强版 sh。
- **csh**（C Shell）：语法类似 C 语言，BSD 系统常用。
- **tcsh**：csh 的增强版。

### /etc/shells 文件

记录系统中所有合法的 Shell。系统服务（如 FTP）会通过此文件检查用户可用的 Shell。
```
cat /etc/shells
/bin/sh
/bin/bash
/bin/tcsh
/bin/csh
/sbin/nologin  # 特殊 Shell，禁止用户登录
```

### 用户默认 Shell

记录在 `/etc/passwd` 文件中，每行最后一个字段即为该用户的登录 Shell。
```
root:x:0:0:root:/root:/bin/bash
bin:x:1:1:bin:/bin:/sbin/nologin
```

- 系统帐号通常使用 `/sbin/nologin`，禁止直接登录系统。

## Bash Shell 的主要功能

### 1. 命令编修能力（history）

- 记录曾经执行过的指令，可通过上下键快速调用。
- 历史记录位置：
    - **内存**：当前登录会话中执行的指令。
    - `~/.bash_history`：**前一次登录**所执行的指令（注销时从内存写入）。
- 默认可记忆多达 1000 个指令，便于追踪操作步骤或排错。

### 2. 命令与文件补全（[Tab] 键）

- **命令补全**：`[Tab]` 接在指令第一个字后，列出所有匹配的命令。
- **文件补全**：`[Tab]` 接在指令第二个字后，自动补全文件名或路径。
- **参数/选项补全**：安装 `bash-completion` 后，某些指令可按 `[Tab]` 补全选项参数。

### 3. 命令别名设置（alias）

- 为长指令串设置简短别名，提高输入效率。
- 查看当前别名：直接输入 `alias`
- 设置别名：`alias lm='ls -al'`

### 4. 工作控制（job control）

- 支持将任务放到前台（foreground）或后台（background）执行。
- 可避免误按 `Ctrl+C` 中断程序，实现单登录环境下的多任务。

### 5. 程序化脚本（Shell Scripts）

- 将连续指令写入文件，通过交互式方式执行。
- 可借助环境变量和指令进行复杂设计，相当于小型程序语言。
- 用于自动化系统管理任务。

### 6. 通配符（Wildcard）

- 支持特殊字符帮助查询文件，如 `*`、`?`、`[]`。
- 示例：`ls -l /usr/bin/X*` 列出所有以 X 开头的文件。

### 查询指令类型：`type`

用于判断一个指令是 bash 内置命令、外部命令还是别名。
```
type [-tpa] name
```

- **不加选项**：显示指令类型（别名、内置或外部）。
- **-t**：仅输出类型关键词：
    - `alias`：命令别名
    - `builtin`：bash 内置指令
    - `file`：外部指令
- **-p**：若为外部指令，显示完整路径。
- **-a**：在 PATH 路径中找出所有包含 name 的指令（包括别名）。
**示例**：
```
type ls          # ls is aliased to `ls --color=auto`
type -t ls       # alias
type -a ls       # 列出别名和 /usr/bin/ls
type cd          # cd is a shell builtin
```

### 指令下达与快速编辑

#### 长指令换行
使用反斜线 `\` 加 `[Enter]` 将指令换到下一行继续输入，注意 `\` 后不能有空格。
```
cp /var/spool/mail/root /etc/crontab \
> /etc/fstab /root
```

系统自动在下一行显示 `>` 提示符。

#### 常用编辑快捷键

|组合键|功能|
|---|---|
|`Ctrl+u`|从光标处向前删除指令串|
|`Ctrl+k`|从光标处向后删除指令串|
|`Ctrl+a`|光标移动到指令串最前面|
|`Ctrl+e`|光标移动到指令串最后面|

### 总结
- **Shell 是用户与核心的桥梁**，bash 是 Linux 默认的 Shell。
- **学习命令行的价值**：跨发行版通用、远程管理高效、便于自动化、深入理解系统。
- **合法 Shell 列表**：记录在 `/etc/shells`；用户默认 Shell 在 `/etc/passwd`。
- **bash 六大功能**：命令历史、补全、别名、工作控制、脚本、通配符。
- **`type` 指令**：快速判断指令来源（内置/外部/别名）
- **指令编辑技巧**：`\` 换行，`Ctrl+u/k` 快速删除，`Ctrl+a/e` 快速移动光标。

# 三 .Shell的变量功能
## 什么是变量

- **变量**：用一个特定的字符串代表不固定的内容，方便程序或脚本引用。
- **作用**：
    - 使程序具有通用性。例如 `MAIL` 变量指向不同用户的邮箱，同一程序可服务所有用户。
    - 影响 Bash 环境操作。如 `PATH` 变量决定可执行文件的搜索路径。
    - 简化脚本维护。在 Shell Script 中，将常用路径定义为变量，修改一处即可全局生效。
## 变量的取用与设置规则
### 取用变量
- 在变量名前加 `$`，如 `echo $PATH`。
- 推荐使用 `${变量名}` 形式，如 `echo ${PATH}`，避免歧义。
### 设置变量
- **基本语法**：`变量名=值`，等号两边**不能有空格**。
- **命名规则**：只能由英文字母和数字组成，但**开头不能是数字**。
### 内容含特殊字符的处理

|符号|作用|示例|
|---|---|---|
|双引号 `"`|保留特殊字符（如 `$`）的功能|`var="lang is $LANG"` → `lang is zh_TW.UTF-8`|
|单引号 `'`|所有字符视为纯文本|`var='lang is $LANG'` → `lang is $LANG`|
|反斜线 `\`|转义特殊字符（空格、`$`、`\`、`'` 等）|`myname=VBird\ Tsai`|
|反引号 `` `command` `` 或 `$(command)`|将命令执行结果作为变量内容|`version=$(uname -r)`|

### 变量操作
- **累加内容**：`PATH="$PATH":/home/bin` 或 `PATH=${PATH}:/home/bin`
- **导出为环境变量**：`export 变量名`，使变量可在子程序中使用。
- **取消变量**：`unset 变量名`

## 环境变量与自订变量
- **环境变量**：可被子程序继承，通常用大写字母表示（如 `PATH`、`HOME`）。
- **自订变量**：仅在当前 Shell 有效，子程序无法继承。
- **export**：将自订变量转换为环境变量。

### 查看变量

|命令|作用|
|---|---|
|`env`|列出所有环境变量|
|`set`|列出所有变量（环境变量 + 自订变量 + 函数）|
|`export`|单独使用列出所有环境变量|

## 常见环境变量

|变量|含义|
|---|---|
|`PATH`|可执行文件搜索路径，目录以冒号分隔|
|`HOME`|当前用户的主文件夹|
|`SHELL`|当前使用的 Shell 程序路径|
|`HISTSIZE`|历史命令可记录的最大笔数（内存中）|
|`MAIL`|当前用户的邮件信箱文件路径|
|`LANG` / `LC_ALL`|语系设置，影响显示语言、时间格式等|
|`RANDOM`|随机数，范围 0~32767|
|`PS1`|命令提示字符格式|
|`$`|当前 Shell 的 PID|
|`?`|上一个执行命令的回传值（0 表示成功，非0 表示错误）|
|`OSTYPE`、`HOSTTYPE`、`MACHTYPE`|操作系统类型、硬件架构等|

## 特殊变量详解

### PS1（提示字符设置）

常用符号含义：

|符号|含义|
|---|---|
|`\u`|当前用户名|
|`\h`|主机名（仅第一个小数点前部分）|
|`\w`|完整工作目录（主文件夹以 `~` 表示）|
|`\W`|仅最后一个目录名|
|`\A`|24小时制时间（HH:MM）|
|`\#`|当前第几个指令|
|`\$`|提示符（root 为 `#`，普通用户为 `$`）|

示例：`PS1='[\u@\h \w \A #\#]\$ '` → `[dmtsai@study /home 17:02 #85]$`

### `$`（当前 Shell PID）

- `echo $$` 显示当前 Shell 的进程 ID。


### `?`（上条命令回传值）

- 命令执行成功返回 `0`，失败返回非 `0` 错误码。
- 可用于脚本中判断命令执行结果。


## 语系变量 locale

### 查看与设置

- `locale -a`：列出系统支持的所有语系。
- `locale`：查看当前语系设置。
- 主要语系变量：`LANG`、`LC_ALL` 等。通常只需设置 `LANG` 或 `LC_ALL`，其他相关变量会自动继承。
- 系统默认语系配置文件：`/etc/locale.conf`

### 临时修改语系
```
LANG=en_US.utf8           # 临时生效
export LC_ALL=en_US.utf8  # 设为环境变量
```

## 变量的有效范围
- **父程序与子程序**：在 Shell 中执行另一个 Shell（如 `bash`）即进入子程序。
- **继承规则**：子程序**仅继承父程序的环境变量**，不继承自订变量。
- **export 的作用**：将自订变量写入环境变量区块，使其被子程序继承。
## 变量键盘读取：`read`
```
read [-pt] variable
```
- `-p`：指定提示字符。
- `-t`：指定等待秒数。
示例：
```
read -p "Please enter your name: " -t 30 name
```
## 变量宣告：`declare` / `typeset`
```
declare [-aixr] variable
```

|选项|作用|
|---|---|
|`-a`|定义为阵列（array）|
|`-i`|定义为整数，可进行算术运算|
|`-x`|相当于 `export`，设为环境变量|
|`-r`|设为只读，不可修改或 unset|
|`+x`|取消 `-x` 属性（将 `-` 改为 `+`）|

示例：
```
declare -i sum=100+300+50   # sum=450
declare -r sum              # 设为只读
declare -p sum              # 显示变量类型
```

## 阵列变量
- **定义**：`var[index]=value`
- **读取**：`${var[index]}`
示例：
```
var[1]="small min"
var[2]="big min"
echo "${var[1]}, ${var[2]}"  # small min, big min
```
## 资源限制：`ulimit`

- **作用**：限制用户可使用的系统资源，防止单个用户耗尽资源。
```
ulimit [-SHacdfltu] [配额]
```

|选项|作用|
|---|---|
|`-a`|显示所有限制|
|`-f`|限制可创建的最大文件大小（KB）|
|`-n`|限制可同时打开的文件数量|
|`-u`|限制可运行的最大程序数|
|`-H`|硬限制（不可超过）|
|`-S`|软限制（可超限但报警）|

示例：`ulimit -f 10240` 限制文件最大 10MB。

**恢复**：登出再登录可恢复默认值。

## 变量内容的删除、取代与替换（高级用法）

### 删除匹配内容

|语法|作用|
|---|---|
|`${变量#关键字}`|从开头删除最短匹配|
|`${变量##关键字}`|从开头删除最长匹配|
|`${变量%关键字}`|从结尾删除最短匹配|
|`${变量%%关键字}`|从结尾删除最长匹配|

示例：
```
path=${PATH}
echo ${path#/*local/bin:}   # 删除第一个 /...local/bin:
echo ${path##/*:}           # 删除到最后一个冒号
echo ${path%:*bin}          # 从结尾删除到最后一个 :...bin
echo ${path%%:*bin}         # 从结尾删除到第一个 :...bin
```

### 取代匹配内容

|语法|作用|
|---|---|
|`${变量/旧/新}`|替换第一个匹配|
|`${变量//旧/新}`|替换所有匹配|

示例：
```
echo ${path/sbin/SBIN}      # 替换第一个 sbin
echo ${path//sbin/SBIN}     # 替换所有 sbin
```

## 变量的测试与默认值

|语法|作用|
|---|---|
|`${var:-默认值}`|若 var 未设置或为空，则使用默认值|
|`${var:=默认值}`|同上，并将默认值赋给 var|
|`${var:+新值}`|若 var 已设置且非空，则使用新值；否则为空|
|`${var:?错误信息}`|若 var 未设置或为空，则输出错误信息并终止|

示例：
```
unset str
echo ${str:-newvalue}       # newvalue（str 仍为空）
echo ${str:=newvalue}       # newvalue（str 被赋值为 newvalue）
str="old"
echo ${str:+new}            # new
echo ${str:?error}          # old（无错误）
```

- 变量是 Bash 环境中存储数据的核心机制，分为环境变量（可继承）和自订变量（仅当前 Shell）。
- 设置变量时需注意等号两侧无空格，特殊字符需用引号或转义处理。
- 常用环境变量包括 `PATH`、`HOME`、`SHELL`、`LANG`、`PS1`、`$`、`?` 等。
- `export` 将自订变量转为环境变量，使其被子程序继承。
- `read` 实现交互式输入，`declare` 声明变量类型（整数、只读、阵列）。
- `ulimit` 控制系统资源使用，防止资源耗尽。
- 变量内容可通过模式匹配进行删除、取代和测试默认值，是 Shell 脚本中处理字符串的利器。

# 四.命令别名与历史命令
## 命令别名（alias）

### 什么是命令别名

- **定义**：为长命令或常用命令串创建简短的替代名称，提高输入效率。
- **与变量的区别**：命令别名是**创建一个新命令**，可直接执行；变量存储数据，需用 `echo` 等方式调用。
- **典型用途**：
    - 简化长命令：`alias lm='ls -al | more'`
    - 增强安全：`alias rm='rm -i'`（删除前询问确认）
    - 模拟其他系统习惯：`alias cls='clear'`、`alias dir='ls -l'`
### 别名管理

|操作|命令|示例|
|---|---|---|
|**设置别名**|`alias 别名='命令串'`|`alias lm='ls -al \| more'`|
|**查看所有别名**|`alias`|直接输入显示当前所有别名|
|**取消别名**|`unalias 别名`|`unalias lm`|

**注意事项**：

- 等号两边不能有空格，命令串建议用单引号包围。
- 别名可覆盖原有命令（如 `alias rm='rm -i'`），但需谨慎。
- 当前 Shell 设置的别名仅临时有效，登出后消失。若要永久生效，需写入配置文件（如 `~/.bashrc`）。

## 历史命令（history）
### 历史命令的存储机制
- **内存**：当前 Shell 会话中执行的命令暂存在内存中，数量由 `HISTSIZE` 变量控制。
- **文件**：用户主目录下的 `~/.bash_history` 文件存储历史命令，数量由 `HISTFILESIZE` 变量控制。
- **写入时机**：
    - 正常登出时，内存中的历史命令会**更新**到 `~/.bash_history`（仅保留最近的 `HISTFILESIZE` 笔）。
    - 可手动强制写入：`history -w`

### 常用操作

|操作|命令|说明|
|---|---|---|
|**查看历史**|`history [n]`|列出所有历史命令，或最近 n 笔|
|**清除历史**|`history -c`|清除当前 Shell 内存中的所有历史|
|**写入文件**|`history -w`|将内存历史写入 `~/.bash_history`|
|**读取文件**|`history -r`|将文件历史读入内存|
|**执行历史命令**|`!number`|执行第 number 笔命令|
|**执行上一个命令**|`!!`|相当于按上键后回车|
|**按开头执行**|`!command`|执行最近一次以 command 开头的命令|

示例：
```
history 3          # 显示最近3笔命令
!1020              # 执行第1020笔命令
!!                 # 执行上一个命令
!vi                # 执行最近一次以 vi 开头的命令
```

### 重要变量

|变量|含义|默认值（CentOS）|
|---|---|---|
|`HISTSIZE`|内存中可记录的历史命令笔数|1000|
|`HISTFILESIZE`|`~/.bash_history` 文件中可记录的最大笔数|1000|

### 注意事项

1. **多重登录的写入问题**  
    同一帐号同时开启多个 bash 时，最后登出的 bash 会覆盖历史文件，导致其他 bash 的历史丢失。建议单一 bash 配合工作控制使用。
2. **无法记录时间**  
    历史命令默认不记录执行时间。可通过自定义 `~/.bash_logout` 等方式附加时间信息。
3. **安全风险**  
    root 的历史文件可能包含敏感操作（如直接输入密码），是攻击者的目标。必要时可清除历史（`history -c; history -w`）。
4. **命令补全与历史结合**  
    使用 `Ctrl+r` 可反向搜索历史命令（输入关键字，实时匹配）。


---

- 命令别名通过 `alias` 设置，可简化操作、增强安全，但仅当前 Shell 有效。
- 历史命令通过 `history` 管理，支持查看、清除、写入文件及快速执行。
- 理解 `HISTSIZE` 与 `HISTFILESIZE` 的差异，掌握内存与文件的同步机制。
- 注意多重登录的写入覆盖问题，以及历史文件可能带来的安全隐患。

# 五.Bash shell的操作环境
## 路径与指令搜寻顺序

当在 bash 中执行一个命令时，系统按照以下顺序查找并执行该命令：

1. **以相对/绝对路径执行指令**（例如 `/bin/ls` 或 `./ls`）。
2. **通过命令别名（alias）找到的指令**（如 `alias ls='ls --color=auto'`）。
3. **bash 内置命令（builtin）**（如 `cd`, `echo` 等）。
4. **通过 `$PATH` 环境变量顺序找到的第一个指令**。

可通过 `type -a 指令名` 查看该指令的完整查找顺序。

## bash 的进站与欢迎讯息

### 登陆前欢迎信息：`/etc/issue`

- 文件 `/etc/issue` 的内容会在本地终端（tty1~tty6）登陆前显示。
- 支持反斜线转义变量，常用符号如下：

|代码|含义|
|---|---|
|`\d`|本地日期|
|`\l`|显示第几个终端机接口|
|`\m`|硬件等级（如 i686, x86_64）|
|`\n`|主机网络名称|
|`\O`|域名|
|`\r`|操作系统版本（`uname -r`）|
|`\t`|本地时间|
|`\S`|操作系统名称|
|`\v`|操作系统版本|

- 远程登录（如 telnet）显示 `/etc/issue.net`。
### 登陆后欢迎信息：`/etc/motd`

- 文件 `/etc/motd` 的内容会在用户成功登录后显示，通常用于通知所有用户（如维护公告）。

## bash 的环境配置文件

bash 启动时会读取一系列配置文件，以初始化环境。根据登录方式不同，读取的配置文件也有区别。

### login shell 与 non-login shell

- **login shell**：需要完整登录流程（输入用户名密码）获取的 shell，如 tty1~tty6 登录。
- **non-login shell**：不需要重新登录即可取得的 shell，如在 X Window 中开启终端，或在原 shell 中执行 `bash` 命令。

### login shell 读取的配置文件

login shell 会按顺序读取以下配置文件：

1. **系统全局配置文件**：`/etc/profile`
2. **用户个人配置文件**（按优先级只读第一个）：
    - `~/.bash_profile`
    - `~/.bash_login`
    - `~/.profile`

#### `/etc/profile`（系统全局）

- 每个用户登录时都会读取，用于设置全局环境变量和启动程序。
- 它会调用以下子配置文件：
    - `/etc/profile.d/*.sh`：目录下所有可读的 `.sh` 文件，用于设置别名、语系、颜色等。
    - `/etc/locale.conf`：由 `/etc/profile.d/lang.sh` 调用，设置语系变量（`LANG`/`LC_ALL`）。
    - `/usr/share/bash-completion/completions/*`：由 `/etc/profile.d/bash_completion.sh` 调用，提供命令选项补全功能。

#### 用户个人配置文件

以 `~/.bash_profile` 为例，它通常包含以下内容：

- 判断并调用 `~/.bashrc`（如果存在）。
- 设置用户个人的 `PATH`（累加 `$HOME/bin` 等）。
- 使用 `export` 导出变量。

若 `~/.bash_profile` 不存在，则依次尝试 `~/.bash_login` 和 `~/.profile`。

### non-login shell 读取的配置文件

non-login shell 只读取 **`~/.bashrc`**。

`~/.bashrc` 通常包含：

- 用户自定义的命令别名（如 `rm -i`、`cp -i`）。
- 调用系统全局配置文件 `/etc/bashrc`（Red Hat 系特有），后者会根据 UID 设置 `umask`、`PS1` 提示符等。

### source 命令：立即生效配置文件

- `source 配置文件` 或 `. 配置文件` 可将配置文件的内容读入当前 shell 环境，无需登出再登录。
- 常用于使修改后的配置文件立即生效（如 `source ~/.bashrc`）。

### 其他相关配置文件

|文件|作用|
|---|---|
|`/etc/man_db.conf`|定义 man page 的搜索路径，安装第三方软件后需手动添加路径。|
|`~/.bash_history`|存储历史命令，记录数量由 `HISTFILESIZE` 控制。|
|`~/.bash_logout`|用户登出时执行的命令，默认为清屏，可添加自定义清理任务。|

## 终端机的环境设置：stty, set

### stty（setting tty）

- 用于查看和设置终端输入按键的功能。
- `stty -a`：列出所有当前终端设置。
- 常见按键含义：

|按键|对应设置|说明|
|---|---|---|
|`Ctrl+C`|`intr`|中断当前程序|
|`Ctrl+D`|`eof`|输入结束（End Of File）|
|`Ctrl+?`（Backspace）|`erase`|向后删除字符|
|`Ctrl+U`|`kill`|删除整行命令|
|`Ctrl+S`|`stop`|暂停屏幕输出|
|`Ctrl+Q`|`start`|恢复屏幕输出|
|`Ctrl+Z`|`susp`|暂停当前程序（放入后台）|

- 可通过 `stty 设置 按键` 修改按键功能（如 `stty erase ^h` 将删除键改为 `Ctrl+H`）。

#### set（bash 内置设置）

- 用于设置 bash 本身的执行环境参数。
- `set -u`：若使用未定义的变量，则显示错误信息（默认不启用）。
- `set -x`：在执行指令前显示指令内容（调试用）。
- `set -C`：防止重定向时覆盖已存在的文件。
- 查看当前设置：`echo $-` 或 `set -o`。

## 万用字符与特殊符号

### 万用字符（通配符）

|符号|含义|

|`\|`|管道，连接两个命令|
|`;`|连续命令分隔符|
|`~`|用户主文件夹|
|`$`|变量取值前缀|
|`&`|将命令放入后台执行|
|`!`|逻辑非，或在历史命令中执行指定命令（如 `!!`）|

- 命令执行顺序：绝对/相对路径 → alias → builtin → `$PATH`。
- 登录欢迎信息通过 `/etc/issue`（本地）和 `/etc/motd`（登录后）设置。
- bash 配置文件分为系统全局（`/etc/profile`）和用户个人（`~/.bash_profile`、`~/.bashrc`），login shell 与 non-login shell 读取不同的配置文件。
- `source` 命令使配置文件立即生效。
- `stty` 控制终端按键行为，`set` 控制 bash 内部选项。
- 万用字符和特殊符号是 bash 操作中强大的匹配和扩展工具，需理解其含义并谨慎使用。

# 六.数据流重导向

## 什么是数据流重导向

数据流重导向（redirect）是将指令执行后本应输出到屏幕的数据，转存到文件或其他设备（如打印机）的机制。它在命令行环境下非常实用，尤其适用于需要保存执行结果、忽略错误信息或背景执行程序等场景。

### 标准输出与标准错误输出

每个指令执行时，都会产生两种输出：

- **标准输出（stdout）**：指令正确执行后回传的讯息，代码为 `1`。
- **标准错误输出（stderr）**：指令执行失败后回传的错误讯息，代码为 `2`。

默认情况下，两者都会显示在屏幕上。通过重导向，可以将它们分别或合并输出到指定位置。

### 重导向符号

| 符号 | 作用 | 说明 |
|------|------|------|
| `>` 或 `1>` | 将标准输出**覆盖**到文件 | 文件不存在则创建，存在则清空后写入 |
| `>>` 或 `1>>` | 将标准输出**追加**到文件 | 文件不存在则创建，存在则在末尾追加 |
| `2>` | 将标准错误输出**覆盖**到文件 | 同上 |
| `2>>` | 将标准错误输出**追加**到文件 | 同上 |
| `<` | 将文件内容作为标准输入 | 取代键盘输入 |
| `<<` | 指定一个结束符，输入遇到该符即结束 | 常用于脚本中定义输入终止 |

**示例**：

```bash
# 将正确输出覆盖到 list_right，错误输出覆盖到 list_error
find /home -name .bashrc > list_right 2> list_error

# 将正确输出追加到 list_all，错误输出也追加到同一文件（错误方式）
find /home -name .bashrc >> list_all 2>> list_all   # 可能造成数据交错

# 正确方式：合并输出到同一文件
find /home -name .bashrc > list_all 2>&1
find /home -name .bashrc &> list_all               # 更简洁的写法
```

### 特殊设备：/dev/null

`/dev/null` 是一个“黑洞”设备，任何导向它的数据都会被丢弃。常用于忽略不需要的输出。

```bash
# 忽略错误信息，只显示正确输出
find /home -name .bashrc 2> /dev/null
```

### 标准输入重定向

- **`<`**：将文件内容作为指令的输入，相当于用文件内容替代键盘输入。
  ```bash
  cat > catfile < ~/.bashrc   # 将 .bashrc 的内容写入 catfile
  ```

- **`<<`**：指定一个结束符，当键盘输入该结束符时自动终止输入（无需 `Ctrl+D`）。
  ```bash
  cat > catfile << "eof"
  > This is a test.
  > eof
  ```

### 应用场景

- 保存屏幕输出的重要信息。
- 将后台执行程序的输出重定向，避免干扰当前终端。
- 将系统例行任务（如 `cron`）的执行结果保存到文件。
- 丢弃已知的错误信息。
- 分别保存正确和错误输出以便排查问题。

## 命令执行的判断依据

有时需要一次执行多个指令，且指令间可能存在依赖关系。bash 提供了几种方式来实现连续或条件执行。

### 不考虑相关性的连续执行：分号 `;`

无论前一个指令执行成功与否，分号后的指令都会继续执行。

```bash
sync; sync; shutdown -h now   # 先执行两次 sync，再关机
```

### 基于回传值的逻辑执行：`&&` 和 `||`

每个指令执行后都会返回一个值（`$?`），0 表示成功，非 0 表示失败。利用这个回传值可以实现条件执行。

| 符号               | 作用    | 说明                                             |
| ---------------- | ----- | ---------------------------------------------- |
| `cmd1 && cmd2`   | **与** | 若 `cmd1` 执行成功（`$?=0`），则执行 `cmd2`；否则 `cmd2` 不执行 |
| `cmd1 \|\| cmd2` | **或** | 若 `cmd1` 执行失败（`$?≠0`），则执行 `cmd2`；否则 `cmd2` 不执行 |

**示例**：

```bash
# 判断目录是否存在，存在则创建文件
ls /tmp/abc && touch /tmp/abc/hehe

# 判断目录是否存在，不存在则创建目录
ls /tmp/abc || mkdir /tmp/abc
```

#### 组合使用：`cmd1 && cmd2 || cmd3`

这种模式常用于实现简单的 if-then-else 逻辑：若 `cmd1` 成功则执行 `cmd2`，否则执行 `cmd3`。注意顺序固定，且 `cmd2` 和 `cmd3` 应选用肯定能成功执行的指令（如 `echo`），否则可能产生预期外的连锁反应。

**示例**：

```bash
# 若 /tmp/abc 存在则显示 "exist"，否则显示 "not exist"
ls /tmp/abc && echo "exist" || echo "not exist"
```

**执行流程**：
- 若 `/tmp/abc` 存在 → `ls` 成功（`$?=0`）→ 执行 `echo "exist"` → 结束。
- 若 `/tmp/abc` 不存在 → `ls` 失败（`$?≠0`）→ 跳过 `&&` 部分 → 执行 `||` 后的 `echo "not exist"`。

**注意**：若将顺序颠倒为 `cmd1 || cmd2 && cmd3`，逻辑会变得复杂，容易产生歧义。通常建议使用固定模式 `cmd1 && cmd2 || cmd3` 来实现条件分支。
**重点**
- 数据流重导向通过 `>`、`>>`、`2>`、`2>>`、`<`、`<<` 将标准输出/错误输出重定向到文件或设备。
- `/dev/null` 是丢弃数据的“黑洞”，常用于忽略不需要的输出。
- 合并标准输出和错误输出可使用 `2>&1` 或 `&>`。
- 命令间用 `;` 分隔可实现连续执行，无论前一个命令成败。
- `&&` 和 `||` 基于命令回传值实现条件执行，组合使用可模拟简单的 if-then-else 逻辑。

# 七.管道命令（pipe）

## 管道命令的基本概念

管道命令（pipe）使用符号 `|` 连接多个命令，将前一个命令的**标准输出（stdout）** 作为后一个命令的**标准输入（stdin）** 进行处理。这种机制允许我们将复杂的数据处理分解为多个简单的步骤，依次递进。

**核心特点：**
- 管道命令**仅处理标准输出**，对标准错误输出（stderr）直接忽略。
- 后一个命令必须能够接受来自前一个命令的 stdin 数据（即该命令需具备从标准输入读取的能力）。
- 若需将 stderr 也纳入管道处理，可先用数据流重导向将 stderr 合并到 stdout（如 `2>&1`）。

**示意图：**  
`命令1 | 命令2 | 命令3` → 数据流从左向右传递，每个阶段只处理前一个阶段输出的正确信息。

## 数据撷取命令

### cut
- **作用**：将一行信息按指定分隔符切割成段，或按字符位置取出部分内容。
- **典型应用**：处理有固定分隔符（如冒号、空格）的文本文件（如 `/etc/passwd`），或输出格式规整的信息（如 `export`）。

### grep
- **作用**：从输入中**筛选**包含（或不包含）指定模式的行，并将匹配的行输出。
- **典型应用**：过滤日志、查找配置文件中的关键字、结合 `-v` 反向选择排除干扰行。
- **扩展**：支持正则表达式，可进行复杂模式匹配。

## 排序与统计命令

### sort
- **作用**：对输入的行进行排序，支持按数字、月份、字段等不同方式排序。
- **典型应用**：对用户列表排序、按 UID 排序 `/etc/passwd`、去重前的预处理。

### uniq
- **作用**：**去除重复行**（通常需配合 `sort` 使用），并可统计重复次数。
- **典型应用**：统计登录用户次数、找出文件中唯一出现的条目。

### wc
- **作用**：计算输入的行数、单词数、字符数。
- **典型应用**：统计文件行数（如 `/etc/passwd` 中的用户数）、查看文本文件大小。

## 双向重导向：tee

- **作用**：同时将数据**输出到屏幕**和**文件**，实现“一边查看一边保存”。
- **典型应用**：在管道处理过程中将中间结果存盘，供后续检查或备份。

## 字符转换命令
### tr
- **作用**：**删除**或**替换**输入中的特定字符。
- **典型应用**：大小写转换、删除 DOS 文件的 `\r` 字符、去除文本中的特殊符号。

### col
- **作用**：将输入中的 `[Tab]` 字符转换为空格，或处理反向换行等。
- **典型应用**：格式化 man page 输出，使 `[Tab]` 显示为统一数量的空格。

### join
- **作用**：将两个文件中**具有相同字段**的行合并为一行（类似数据库的 join 操作）。
- **典型应用**：合并 `/etc/passwd` 与 `/etc/shadow`（以用户名为关联字段），或合并 `/etc/passwd` 与 `/etc/group`（以 GID 为关联字段）。

### paste
- **作用**：直接将两个文件的对应行**粘贴在一起**，中间以 `[Tab]` 分隔（无需比对相同字段）。
- **典型应用**：并排显示两个相关文件的内容，如用户信息与组信息。

### expand
- **作用**：将输入中的 `[Tab]` 字符转换为指定数量的空格。
- **典型应用**：处理包含制表符的文本，使其在不同环境下显示一致。

## 分区命令：split

- **作用**：将大文件按**大小**或**行数**分割成多个小文件。
- **典型应用**：分割超大日志文件以便传输或编辑，将文件拆分后存入多个存储介质。

## 参数代换：xargs

- **作用**：从标准输入读取数据，将其作为**参数**传递给后续命令执行。
- **典型应用**：解决某些命令（如 `rm`、`id`）无法直接从管道接收参数的问题，批量处理文件名列表（如 `find ... | xargs rm`）。
- **特性**：可控制每次传递的参数个数（`-n`）、交互确认（`-p`）、指定结束标记（`-e`）。

## 减号 `-` 的特殊用途

- **作用**：在管道命令中，`-` 代表**标准输入**或**标准输出**，用于替代文件名参数。
- **典型应用**：`tar -cvf - /home | tar -xvf - -C /backup`——前一个 `tar` 将打包数据输出到 stdout，后一个 `tar` 从 stdin 读取并解压到指定目录，全程无需中间文件。

##
- 管道命令 `|` 连接多个命令，数据从左向右流动，仅处理 stdout。
- 常用管道命令按功能分类：
  - **撷取**：`cut`（按字段/字符切分）、`grep`（按模式筛选）
  - **排序与统计**：`sort`（排序）、`uniq`（去重/计数）、`wc`（计数）
  - **双向重导向**：`tee`（同时输出到文件与屏幕）
  - **字符转换**：`tr`（替换/删除字符）、`col`（Tab 转空格）、`join`（合并关联字段）、`paste`（并排粘贴）、`expand`（Tab 转指定空格）
  - **分区**：`split`（按大小/行数分割文件）
  - **参数代换**：`xargs`（将 stdin 转为命令行参数）
  - **特殊符号**：`-` 表示 stdin/stdout，用于替代文件名
- 掌握这些命令可高效处理文本数据，是 shell 脚本和日常管理的核心技能。
