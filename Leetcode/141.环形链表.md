# 题目

给你一个链表的头节点 `head` ，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：`pos` 不作为参数进行传递，仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 `true`。否则，返回 `false`。

**示例 1：**

**输入：** `head = [3,2,0,-4], pos = 1`
**输出：** `true`
**解释：** 链表中有一个环，其尾部连接到第二个节点。

**示例 2：**

**输入：** `head = [1,2], pos = 0`
**输出：** `true`
**解释：** 链表中有一个环，其尾部连接到第一个节点。

**示例 3：**

**输入：** `head = [1], pos = -1`
**输出：** `false`
**解释：** 链表中没有环。

**提示：**

- 链表中节点的数目范围是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 为 `-1` 或者链表中的一个有效索引

**进阶：** 你能用 `O(1)`（即，常量）内存解决此问题吗？

# 解题思路与代码实现

## 方法一：哈希表法
使用哈希集合记录已经访问过的节点，若遍历过程中遇到重复节点，则说明有环。

*   **思路**：
    1.  创建一个 `unordered_set<ListNode*>` 存储节点指针。
    2.  遍历链表，对于每个节点：
        *   如果节点已在集合中，返回 `true`。
        *   否则将节点加入集合，并移动到下一个节点。
    3.  遍历结束未发现重复，返回 `false`。
*   **复杂度**：时间复杂度 O(n)，每个节点最多访问一次；空间复杂度 O(n)，最坏情况下需要存储所有节点。
*   **缺点**：需要额外 O(n) 空间，不满足进阶要求的 O(1) 内存。

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode(int x) : val(x), next(NULL) {}
 * };
 */
class Solution {
public:
    bool hasCycle(ListNode *head) {
        unordered_set<ListNode*> visited;
        ListNode* cur = head;
        while (cur) {
            if (visited.count(cur)) return true;
            visited.insert(cur);
            cur = cur->next;
        }
        return false;
    }
};
```

## 方法二：快慢指针（Floyd 判圈算法，最优解）
使用两个速度不同的指针（慢指针一次走一步，快指针一次走两步），若链表有环，两指针最终会相遇；若无环，快指针会先到达末尾。

*   **思路**：
    1.  初始化慢指针 `slow = head`，快指针 `fast = head`。
    2.  当 `fast` 和 `fast->next` 均不为空时循环：
        *   `slow` 移动一步：`slow = slow->next`。
        *   `fast` 移动两步：`fast = fast->next->next`。
        *   若 `slow == fast`，说明相遇，返回 `true`。
    3.  循环结束，返回 `false`。
*   **正确性证明**：若链表有环，当慢指针进入环后，快指针相对于慢指针的速度为 1 步/轮，因此必定在有限步内追上慢指针。
*   **复杂度**：时间复杂度 O(n)，空间复杂度 O(1)。
*   **优点**：满足进阶要求，是最优解法。

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        if (head == nullptr || head->next == nullptr) return false;
        ListNode* slow = head;
        ListNode* fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) return true;
        }
        return false;
    }
};
```

## 方法三：标记法（破坏链表结构，不推荐）
遍历链表，将每个节点的 `next` 指针指向一个特殊标记（如指向自身），若遇到标记则说明有环。此方法会修改原链表。

*   **思路**：
    1.  遍历链表，对于每个节点：
        *   若 `node->next == node`（标记），返回 `true`。
        *   否则，暂存 `node->next`，然后将 `node->next` 指向 `node`（自身），继续遍历。
    2.  遍历结束返回 `false`。
*   **复杂度**：时间复杂度 O(n)，空间复杂度 O(1)。
*   **缺点**：破坏了链表结构，且多线程环境下不安全，不推荐在实际中使用。

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        ListNode* cur = head;
        while (cur) {
            if (cur->next == cur) return true;
            ListNode* next = cur->next;
            cur->next = cur;
            cur = next;
        }
        return false;
    }
};
```

## 方法四：长度限制法（不严谨）
根据题目提示节点数目上限为 `10^4`，遍历超过此数量则判定有环。

*   **思路**：遍历链表，计数超过 `10000` 则返回 `true`，否则返回 `false`。
*   **复杂度**：时间复杂度 O(10000) = O(1)，空间复杂度 O(1)。
*   **缺点**：依赖题目给出的上限，不具有通用性，且若环很长（超过上限）可能误判，不推荐。

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        int count = 0;
        const int MAX_NODES = 10000;
        ListNode* cur = head;
        while (cur) {
            ++count;
            if (count > MAX_NODES) return true;
            cur = cur->next;
        }
        return false;
    }
};
```

## 方法总结
| 方法             | 核心思想                         | 时间复杂度 | 空间复杂度 | 适用性                               |
|------------------|----------------------------------|------------|------------|--------------------------------------|
| 哈希表法         | 记录访问过的节点，检测重复       | O(n)       | O(n)       | 简单直观，但需要额外空间             |
| 快慢指针         | 不同速度指针在环内必然相遇       | O(n)       | O(1)       | **最优解，满足进阶 O(1) 空间**       |
| 标记法（破坏链表）| 修改 next 指向自身作为标记       | O(n)       | O(1)       | 会破坏链表，不推荐                   |
| 长度限制法       | 利用节点数上限，超过则判环       | O(1)       | O(1)       | 依赖题目条件，不通用                 |

# 知识点与延伸

## 1. 核心知识点
- **快慢指针（Floyd 判圈算法）**：在链表、数组中判断环的经典算法，两个指针速度比为 2:1。
- **空间复杂度优化**：从 O(n) 哈希表到 O(1) 快慢指针的优化思路。
- **边界条件处理**：空链表、单节点链表、无环链表、头尾相连的环等。
- **相遇点与环入口的关系**：本题仅需判断是否有环，但 Floyd 算法还可进一步找到环的入口（LeetCode 142）。

## 2. 面试考察重点
- **能否给出 O(1) 空间的解法**：快慢指针是标准答案。
- **对指针操作的安全性**：循环条件中必须检查 `fast && fast->next`，避免空指针访问。
- **数学证明能力**：能够解释为什么快慢指针在环中一定会相遇（相对速度 1）。

## 3. 算法证明与细节
- **Floyd 判圈算法正确性证明**：
  - 若无环，快指针先到达 `nullptr`，算法结束。
  - 若有环，设环长为 `r`，慢指针进入环时快指针已进入环（或同时进入），两者距离为 `d`（0 ≤ d < r）。由于快指针每次比慢指针多走一步，相对速度为 1，因此经过 `r - d` 步后必能追上。
- **快慢指针的起始位置**：两者都从头开始，或慢指针从头、快指针从头节点的下一个开始，都可以。通常都从头开始，循环条件需相应调整。

## 4. 代码优化技巧
- **提前判断空链表或单节点**：可节省一次循环，但不是必须。
- **使用 `while (fast && fast->next)` 而非 `while (fast->next && fast->next->next)`**：前者更简洁，且能正确处理偶数长度无环链表。
- **避免使用 `ListNode*` 以外的变量**：保持空间 O(1)。

## 5. 拓展与应用
- **寻找环的入口**（LeetCode 142）：在快慢指针相遇后，将慢指针重置到头节点，两者同速前进，再次相遇点即为环入口。
- **判断链表是否有环的变体**：如判断数组是否有重复元素（可视为隐式链表）。
- **龟兔赛跑算法**：广泛应用于检测循环依赖、重复数字等问题。
