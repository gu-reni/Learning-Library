# 解题思路与代码实现

## 方法一：暴力枚举法（不推荐）
最直接的解法，枚举所有可能的元素对，检查其和是否等于目标值。

*   **思路**：使用两层循环，外层循环遍历每个元素 `i`，内层循环从 `i+1` 开始遍历后续元素，计算 `nums[i] + nums[j]` 是否等于 `target`。若相等则返回 `{i, j}`。
*   **复杂度**：时间复杂度 O(n²)，空间复杂度 O(1)。当数组长度较大时（如 n ≥ 10⁴），此方法会超时，仅适用于理解题目，不推荐实际使用。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        int n = nums.size();
        for (int i = 0; i < n - 1; ++i) {
            for (int j = i + 1; j < n; ++j) {
                if (nums[i] + nums[j] == target) {
                    return {i, j};
                }
            }
        }
        return {}; // 根据题意，这里不会执行到
    }
};
```

## 方法二：哈希表法（最优解）
利用哈希表（unordered_map）存储已遍历元素的值与下标的映射，以空间换时间，将查找时间降至 O(1)。

*   **思路**：
    1.  初始化一个空哈希表 `hash`，键为数组元素值，值为该元素的下标。
    2.  遍历数组，对于当前元素 `nums[i]`，计算 `complement = target - nums[i]`。
    3.  在哈希表中查找 `complement`：
        *   如果找到，则返回 `{hash[complement], i}`。
        *   如果未找到，则将 `(nums[i], i)` 存入哈希表，继续遍历。
    4.  题目保证有解，因此最终必然返回。
*   **复杂度**：时间复杂度 O(n)，每个元素最多访问一次，哈希表操作平均 O(1)；空间复杂度 O(n)，最坏情况下需要存储 n 个元素。
*   **正确性说明**：遍历过程中，若当前元素 `nums[i]` 与之前某个元素 `nums[j]` 之和等于 `target`，则在处理到 `i` 时，`complement = nums[j]` 一定已在哈希表中，因此算法能找到解。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> hash; // 值 -> 下标
        for (int i = 0; i < nums.size(); ++i) {
            int complement = target - nums[i];
            if (hash.find(complement) != hash.end()) {
                return {hash[complement], i};
            }
            hash[nums[i]] = i; // 将当前元素存入哈希表
        }
        return {};
    }
};
```

## 方法三：排序 + 双指针（需记录原下标）
通过排序将数组变为有序，利用双指针查找两数之和，但需要额外记录元素的原下标，因为题目要求返回的是下标而非值。

*   **思路**：
    1.  创建数组 `pairs` 存储 `(值, 原下标)` 的二元组，并按值排序。
    2.  初始化左指针 `left = 0`，右指针 `right = n-1`。
    3.  当 `left < right` 时：
        *   计算 `sum = pairs[left].first + pairs[right].first`。
        *   若 `sum == target`，返回 `{pairs[left].second, pairs[right].second}`。
        *   若 `sum < target`，左指针右移；否则右指针左移。
*   **复杂度**：时间复杂度 O(n log n)，主要为排序开销；空间复杂度 O(n)，需要存储下标信息。
*   **适用场景**：当需要保持元素原始信息且对时间要求较宽松时可用，但哈希表法更优。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        vector<pair<int, int>> pairs;
        for (int i = 0; i < nums.size(); ++i) {
            pairs.emplace_back(nums[i], i);
        }
        sort(pairs.begin(), pairs.end()); // 按值排序
        
        int left = 0, right = pairs.size() - 1;
        while (left < right) {
            int sum = pairs[left].first + pairs[right].first;
            if (sum == target) {
                return {pairs[left].second, pairs[right].second};
            } else if (sum < target) {
                ++left;
            } else {
                --right;
            }
        }
        return {};
    }
};
```

## 方法总结
| 方法         | 核心思想                         | 时间复杂度 | 空间复杂度 | 适用性                               |
|--------------|----------------------------------|------------|------------|--------------------------------------|
| 暴力枚举法   | 双重循环枚举所有元素对           | O(n²)      | O(1)       | 仅用于理解，实际超时                 |
| 哈希表法     | 用哈希表记录已遍历元素，快速查找补数 | O(n)       | O(n)       | **最优解，最常用，适用于绝大多数情况** |
| 排序+双指针  | 排序后双指针逼近，需保留原下标   | O(n log n) | O(n)       | 提供另一种思路，但不如哈希表简洁高效 |

# 知识点与延伸

## 1. 核心知识点
- **哈希表（散列表）**：掌握 `unordered_map` 的基本操作（插入、查找），理解其平均 O(1) 的时间复杂度。
- **空间换时间**：通过引入额外存储结构（哈希表）将查找时间从 O(n) 降至 O(1)，是优化算法的常用手段。
- **双指针技巧**：在有序数组上通过双指针相向移动，高效解决“两数之和”类问题。
- **边界条件**：确保返回的是下标，且不能使用同一个元素两次（哈希表法在遍历时先查后存，避免自身匹配）。

## 2. 算法证明与细节
- **哈希表法的正确性**：假设解为 `(i, j)` 且 `i < j`。当遍历到 `j` 时，`nums[i]` 已经存入哈希表，因此 `complement = nums[i]` 能被找到，从而返回正确结果。
- **避免使用自身元素**：哈希表法在查找前未将当前元素存入，因此不会出现 `complement = nums[i]` 且 `hash` 中存储了当前元素的情况（自身匹配），从而保证下标不同。

## 3. 代码优化技巧
- **使用 `unordered_map` 而非 `map`**：`unordered_map` 基于哈希表，查找平均 O(1)；`map` 基于红黑树，查找 O(log n)。本题应优先使用 `unordered_map`。
- **提前返回**：找到解后立即返回，减少不必要的遍历。
- **处理空输入**：题目假设有解，但鲁棒代码应能处理无解情况（返回空数组）。

## 4. 拓展与变体
- **三数之和**、**四数之和** 等问题可借鉴排序+双指针思想。
- **两数之和 II（输入有序数组）** 可直接使用双指针，无需哈希表。
- **两数之和（返回元素值而非下标）** 可排序后双指针，无需额外记录下标。
